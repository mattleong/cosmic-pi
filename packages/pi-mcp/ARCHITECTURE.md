# pi-mcp architecture

`pi-mcp` owns one Pi `mcp` gateway, the `/mcp` command (through core's `registerExtensionCommand`, with server actions and `settings` as subcommands), and the producer side of `tools.mcp.request`. All execution goes through `McpExecution`; Code Mode never owns a second connection manager. The [README](./README.md) defines configuration, public actions, limits, and supported modes, and [CAPABILITIES.md](./CAPABILITIES.md) separates supported behavior from restrictions. Historical acceptance evidence lives in the [original plan](../../docs/plans/pi-mcp.md), [UI record](../../docs/plans/pi-mcp-ui.md), [modernization record](../../docs/plans/pi-mcp-modernization.md), and [feature record](../../docs/plans/pi-mcp-features.md).

## Application and lifecycle

`extension.ts` and `application/register.ts` register inert callbacks. `application/lifecycle.ts` is the only Effect-to-Promise submission boundary and uses core's session-runtime slot for startup, replacement, tree changes, and shutdown. All services compose in `layer.ts` under that runtime. Preview settings load before `tools/controller.ts` wraps the owned gateway with `withCodePreviewShell`; the session runtime also owns the preview animation scheduler, and replacement or shutdown revokes its ticks. A foreign `mcp` registration prevents installation without touching that extension's tools.

An activation owns its tool-error receipts and a stable-session Code Mode provider, and revokes both before runtime disposal. Late cancellation withholds payloads, images, and retained IDs without changing known execution certainty. Because pinned Pi treats a resolved tool as successful, the owned `tool_result` hook restores the gateway's explicit error flag; it never modifies foreign results.

## Authority

Trusted sessions, enabled servers, and exact-name tool allow/deny rules are the authorization model. Pi has no approval middleware, and nested Code Mode calls bypass `tool_call` hooks, so policy lives in the shared services rather than a hook. `code-mode/protocol.ts` exports producer-owned v1 codecs and a narrow Promise capability through `pi-mcp/code-mode`; `boundary/host-code-mode.ts` rechecks session identity, activation, trust, and top-level tool activation on every query and call. The consumer must find exactly one provider and cannot reach management, auth, configuration writes, or arbitrary wire methods. Authentication never enters the model's request union; commands use current-generation session capabilities.

Execution certainty (`not-sent`, `completed`, `unknown`) is independent of `isError`, and no automatic replay recovers uncertain or completed work. The one retried tool call is a correlated `-32020` header mismatch, which the protocol requires before the tool runs (see Invocation). Cancellation and cleanup never roll back remote side effects.

## Configuration

`config/store.ts` is the only persistence API. It reads global `extensions/pi-mcp.json`, project-root `.mcp.json`, and project `.pi/extensions/pi-mcp.json` in increasing precedence, with no ancestor search. Project sources require trust, and untrusted sessions perform no project I/O. Documents need an `mcpServers` root, are read through core's bounded JSON-document API, and are published frozen inside the atomic write commit; unrelated fields are preserved and invalid documents are never repaired. Settings commands write only the global or Pi-specific project file, never `.mcp.json`. Settings merge per field; server definitions replace as a whole, and an invalid project override disables execution rather than inheriting another target's credentials. Diagnostics reuse the transport's field codecs and emit fixed field-level guidance, never raw values or arbitrary keys.

Each server has two identities. `identity` hashes the owning source and complete effective definition; connections, discovery snapshots, and results bind to it, so any definition edit replaces them. `credentialIdentity` hashes only the source, id, and HTTP credential audience (URL and `auth` block); the auth service, Keychain records, grants, and registrations key on it, so tool rules, `protocol`, headers, and enablement edits keep a sign-in.

`boundary/sdk-connection.ts` resolves `${NAME}` placeholders in stdio `env` and HTTP `headers` only at connection time through its captured `ConfigProvider` (single pass, `$$` escapes); command, args, URL, and cwd stay literal. Stdio children get `PATH` plus explicit entries, with no shell or ambient credentials. A server executable is trusted local code with user privileges, not a sandbox. Configured headers cannot set MCP protocol headers (`MCP-Protocol-Version`, `Mcp-Session-Id`, `Last-Event-ID`, `Mcp-Param-*`).

## Connections

`connection/service.ts`, `registry.ts`, and `admission.ts` own child scopes, deduplicated acquisition, bounded session and per-server admission, queue deadlines, idle cleanup, and revocation. Requests recheck trust, configuration, and tool policy (`discovery/policy.ts`) after queued waits. Revocation happens before interruption and cleanup, and no registry lock spans remote work or a user dialog. Login and logout take the owner's auth fence so they cannot race a new dispatch.

Cleanup evidence is sticky and exact-owner: unconfirmed local cleanup blocks replacement admission, even across session replacement, and timeout or interruption cannot produce a false confirmation. A remote answer is not local evidence in either direction: any HTTP answer to DELETE settles it (a leftover remote session is the server's to expire), while a DELETE with no answer stays unconfirmed. `operation.ts` separates publication checks from continuation checks, which also require an accepting owner and fresh credential evidence. Changed credentials increment the authorization revision, revoke metadata and results, and retire the owner; only a later fresh request acquires its replacement.

## Protocol eras and transports

The official client/core SDK 2.0.0 owns negotiation, framing, correlation, cancellation, and wire schemas for MCP `2026-07-28` and its legacy revisions. `boundary/mcp-protocol/contract.ts` holds only what differs by era: list-change observation and resource subscription. `select.ts` alone imports `modern/` and `legacy/`, choosing from `client.getProtocolEra()`; `shared/` holds era-neutral helpers. Oxlint `no-restricted-imports` enforces these boundaries, and boundary code uses the SDK's era and metadata-key constants instead of version strings. Session handling needs no era: modern HTTP never carries a session id, and legacy connections never open listen streams. Removing legacy support changes its directory, selection, tests, and docs, not the services.

Both transports accept `protocol: "auto" | "legacy"`, defaulting to modern-first negotiation. The SDK classifies probe replies with no stricter application policy: authorization failures, server errors, network failures, and HTTP timeouts stay errors, while other evidence, including a stateful 2025 server's uncorrelated 400, falls back to legacy. Historical HTTP+SSE is unsupported; SSE inside Streamable HTTP is supported.

`boundary/sdk-lifecycle.ts` is the one connection driver for both transports: the admission deadline, owner scope, revocation, interruption-safe cached close, cleanup evidence, observation budget, and assembly. Each transport supplies native acquisition, its exchange, and a close policy. `boundary/sdk-transport.ts` is the one SDK Transport wrapper shape; HTTP operation ownership and event ingress supply only `send` and inbound hooks. `sdk-client.ts` captures a bounded prefix of server instructions after the handshake for `server.instructions`; instructions never enter the system prompt.

**Stdio.** `sdk-stdio-transport.ts` runs SDK framing over core's macOS duplex process, whose close confirms the process group and pipes. Automatic negotiation probes on a disposable child and launches the application child only after the probe's cleanup is confirmed. The probe waits up to half the remaining budget so cold starts are not read as silence; a silent probe, or one that exits before replying, selects legacy. The connector remembers only the negotiated era per definition identity for the session: a remembered legacy era skips the probe, a remembered modern era pins its revision for in-place negotiation on the application child, and any failed acquisition forgets it. Per-message and queued write limits are separate (a full queue is `busy`), and admission stops after unconfirmed cleanup, as on HTTP.

**HTTP.** `sdk-http.ts` supplies Streamable HTTP acquisition and teardown; `sdk-http-request.ts` runs requests; `sdk-http-transport.ts` owns operation admission, dispatch and completion evidence, and native resource leases. A finished operation cannot own later traffic, so long-lived continuations such as the standalone GET stream fall back to control ownership. `sdk-http-control.ts` gives uncorrelated control traffic its own admission and deadlines. `sdk-fetch.ts` adapts the injected fetch, strips internal headers, rejects redirects, bounds bodies and SSE events, and releases body leases only on actual source settlement. Only the standalone GET stream is connection-wide observation there; a listen stream's owner decides whether its loss matters. A session-bearing legacy 404 retires the connection without replaying the call. Transport auth is token-only: SDK reconnection and step-up are disabled, and it never starts login UI.

`sdk-protocol-error.ts` maps SDK errors into fixed categories without copying remote messages, data, or custom codes. Subscription failures without transport evidence use `shared/subscription-failure.ts`; only a correlated rejection or proven non-dispatch clears establishment uncertainty.

## Discovery

`discovery/` owns complete, frozen metadata revisions, bounded pagination, list-change coalescing, exact lookup, and revision-bound gateway cursors; it is the only metadata store. `collect.ts` settles each listing independently; a first-page method-not-found marks only that catalog unsupported, and any other failure is fatal. A revision never mixes partial pages or revisions.

`freshness.ts` derives expiry from `ttlMs` and `cacheScope`: missing or nonpositive TTL is immediately stale, and anything over a day clamps to a day. TTL governs listing only. Targeted listing reacquires expired revisions, while invocation reuses the current revision until a notification, failed refresh, owner retirement, or authority change removes it, as the SDK's call-time tool index does; otherwise servers without TTL hints would be relisted before every call. Cursor continuations read the cached revision locally, and passive views disclose staleness. Authorization revisions keep even public metadata from crossing auth contexts. Unscoped discovery never connects every server. Returned links are never followed, and prompt roles and descriptions stay untrusted data.

## Invocation and results

`invocation/validation.ts` prepares each call from one immutable metadata entry: lookup, a refusal for tools that require 2025-11-25 task execution, input validation, and parameter headers. An input schema the local validator cannot use (such as OpenAPI `nullable`) is the server's to enforce, so the call is sent without local input validation and carries an informational notice. `invocation/parameter-headers.ts` mirrors `x-mcp-header` arguments into bounded `Mcp-Param-*` headers for modern HTTP following the SDK's rules; invalid annotations exclude the tool in discovery. On a correlated `-32020` header mismatch, invocation refreshes metadata, prepares the call again from the refreshed entry, and dispatches once more; any other failure or a second mismatch is returned unchanged.

Structured output is validated against the captured schema after settlement, except for tool-error replies. `outputValidation` is `passed`, `failed`, or `unavailable`; both failure states keep completed certainty, report `isError: true`, and preserve accepted output. `validation/schema-rules.mjs` is the single JSON Schema policy (plain ESM because the helper runs it under Node); `validation/schema-policy.ts` bounds and pre-checks documents, and the fixed `schema-validator-helper.mjs` compiles and validates in core's bounded process service with no external loader. This isolates validator CPU, not memory or server privileges.

`results/` separates normalization, authority-checked retention, and bounded projection. It owns session quotas, oldest-settled eviction, result IDs, attachments, and authorized reads. Disconnect preserves completed results; configuration or credential changes, trust loss, logout, eviction, and replacement revoke them, and `tools/projection.ts` binds retention to both configuration revision and revocation generation. Native image checks bound size, MIME, container structure, and dimensions without full decoding. Returned content never gains authority by being an MCP result.

## Optional operations

`observations/` holds a session-local ring of progress and log events read through `events.read` without connecting. Request logging (`logLevel`) needs modern HTTP with advertised logging; elsewhere the request runs without it and carries a notice. `completion/operations.ts` validates advertised references before dispatch.

`resources/subscriptions.ts` owns explicit subscribe/unsubscribe with 16 leases per owner and 32 per session; leases prevent idle retirement and end with their owner or stream. A server may honor a subset of list-change families (the rest stay unobserved), but resource subscriptions must be honored exactly. `sdk-events.ts` validates modern updates against their acknowledged subscription at raw ingress and stages at most 32 acknowledgement-adjacent updates. Both eras share one close pipeline in `shared/subscription-close.ts`; an error reply to a legacy unsubscribe settles it, while a failed stdio cancellation write keeps the lease until child cleanup.

`interaction/conversation.ts` owns modern `input_required` rounds for tool calls, resource reads, and prompts under the originating deadline, with fixed round, request, and byte limits. Only current same-session TUI/RPC providers authorize elicitation; legacy and headless sessions never advertise it. `host-ask-user.ts` resolves providers and owns cancellation; `host-elicitation-browser.ts` opens macOS's browser only after inert URL consent and fresh authority checks.

## Authentication

`auth/service.ts` owns grant access, publication authority, login, and logout; `auth/authority.ts` owns process-local permits and blocks keyed by credential identity. Headerless URL servers start anonymous until rejection, login, or an explicit check. When a server rejects an unexpired token whose grant can refresh, the next access refreshes once; a second rejection within a minute of that recovery requires sign-in, and the rejected request is never replayed. Rejection evidence is process-local.

`boundary/sdk-auth.ts` adapts SDK discovery, registration, PKCE S256, exchange, and refresh one step at a time behind owned policy:

- `sdk-auth-discovery.ts` prefers a retained POST challenge, then an unauthenticated probe. A challenge the strict parser rejects is treated as absent, so well-known discovery on the resource origin continues; a parsed hint naming an unsafe destination fails. Only exclusively 404/410 protected-resource responses permit the configured-issuer or origin fallback; authorization-server metadata candidates move on after a client error or 502.
- Protected-resource metadata may publish a same-origin path prefix of the endpoint, and the grant binds to that identifier; a configured `resource` must match exactly. Configured issuers are exact; inferred bare-host issuers accept a trailing-slash difference.
- `auth/scopes.ts` proposes scopes from challenge or resource evidence, never the server's catalog. Step-up requests the rejected grant's scopes plus the challenged ones, and added scopes need private user approval. Granted scopes may differ from the request; only their syntax is checked.
- `sdk-auth-registration.ts` uses a pre-registered client, a Client ID Metadata Document, or dynamic registration. A metadata client inferred from `clientMetadataUrl` alone falls back to dynamic registration when the authorization server lacks CIMD support. Compatible dynamic registrations are reused; a reused client that meets `invalid_client`, a timeout, or cancellation is forgotten, so the next sign-in registers fresh. `sdk-auth-client.ts` enforces public clients only.
- `auth-fetch.ts` bounds OAuth HTTP, pins DNS to policy-approved addresses, and rechecks every redirect. `auth-callback.ts` owns the loopback listener, which ignores requests until the attempt's state exists and treats `access_denied` as cancellation.

`boundary/credential-store.ts` is the only credential persistence door. Records hold an optional grant and a registration checkpoint in one Keychain account, under core's cross-process lock for the whole transaction. `auth/refresh.ts` saves a quarantine marker before spending a refresh token and clears it only after the new grant is saved; a failed marker save or a failure before the request leaves the process keeps the token usable. `keychain.ts` loads `@napi-rs/keyring` lazily, with no plaintext fallback. Its native fence lifts once a write settles, because the Keychain again holds the truth; a refused removal and a synchronous native throw stay blocked. The cross-process lock journals pending native mutations, and a dead owner with pending native work needs the [README recovery procedure](./README.md#credential-coordination-recovery). Logout revokes connection and result authority before deleting the grant and checkpoint. Managed bearer credentials never reach remote plaintext HTTP.

## Presentation

`auth/flow.ts` owns the explicit sign-in presentation around `McpExecution.login`; `auth/progress.ts` holds secret-free phases, and completion hooks bind to the exact login receipt. `host-auth.ts` keeps browser URLs and callback values in private user capabilities; `host-auth-panel.ts` docks the sign-in panel above the editor on Cosmic UI's `dock` surface.

`manager/service.ts` owns view admission, action tickets, and invalidation from connection status and cached discovery, never credential access. Every mutating action rechecks the displayed configuration, identity, and revision; risky actions confirm on the manager's own screen. `boundary/host-ui.ts` opens managers on Cosmic UI's `screen` surface. `activity/service.ts` is an observational journal; `host-mcp-status.ts` publishes Activity and the status contribution. Top-level `ui/` is pure rendering.

Tool cards keep the execution envelope, native images, retained IDs, and error receipts beneath the shared shell. `code-mode/presentation.ts` and `presentation-evidence.ts` interpret replies and typed failures by operation identity; remote tool output stays data. `code-mode/issues.ts` turns that evidence into bounded `CompactIssue`s with short human messages from `ui/compact-descriptions.ts`, keeping agent recovery in details. Owned notices (retained output, unchecked input, unavailable logging, discovery information) are informational; unknown notices, failed validation, cleanup, and credential blockers stay visible. `pi-mcp/code-mode` exports the same projections for nested calls; they grant no execution authority.

## Packaging and checks

The private package ships TypeScript source plus the plain-ESM validator helper and policy, with no generated `dist/`. The client reports the manifest version. SDK-internal Zod is transitive; authored schemas use Effect Schema. Core owns generic process, DNS-pinning, listener, and document boundaries, never MCP or OAuth policy. Service tests share override-first fakes from `tests/fixtures/services.ts`. The opt-in `mcp:conformance` runner covers the upstream `initialize` and `tools_call` scenarios only and is not part of `validate`.
