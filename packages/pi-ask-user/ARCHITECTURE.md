# Architecture

`pi-ask-user` is an Effect-managed Pi extension for structured user decisions.

## Source ownership

- `src/extension.ts` is the thin Pi registration entrypoint.
- `src/application.ts` owns the core session-runtime slot, trusted preview bootstrap, current-generation admission, deferred tool registration, `/ask-user`, and lifecycle/context handlers.
- `src/layer.ts` composes the current host callbacks into `AskUserService`. No host service or package-local runtime is added.
- `src/questionnaire/service.ts` validates blocking and authenticated owned calls. One private queued runner admits each, publishes its Activity row, races user cancellation, and settles it. `queue.ts` owns one bounded FIFO shared with `async-service.ts`, which owns async request state, opening/completion/cancellation Deferreds, waiter ownership, retention, and presenter/delivery fibers. `async-model.ts` holds the public snapshots; `format.ts` formats answer and control text.
- `src/questionnaire/schema.ts` owns Pi TypeBox schemas and request types. Semantic validation and the pure reducer retain their existing roles. The request union accepts single/multiple questions with choices or text questions without choices. Drafts contain selected values, custom text, or first-class text plus an optional note, not copied keys or labels. One finalizer combines the question and draft into a public answer. Cancellation never returns drafts. Shared pure input validation trims and checks nonblank answers against the fixed 4,000-code-unit limit, with 2,000 for optional notes. RPC and TUI reject invalid input without truncation. Text questions enter the existing Editor on first visit; Escape retains the uncommitted buffer and returns to navigable Edit answer, notes, tabs, and review.
- `src/boundary/host-dialogs.ts` adapts abort-aware RPC answer, note, and final review calls. `host-tui.ts` owns the prompt admission, mount acknowledgement, synchronous callback revocation, hide/resume, and joins for admitted external-editor cleanup. Cosmic UI's shared `dock` surface draws questionnaires in uniquely keyed above-editor widgets. An empty custom overlay retains keyboard focus and prompt lifecycle without painting over the editor or footer. The surface removes the widget on settlement, interruption, and mount failure. `host-ui.ts` retains only token-checked resume capabilities, mounted visibility, and fallback status, with no raw terminal listener. `host-activity.ts` publishes bounded question summaries from service and mounted-dialog transitions. Cosmic UI availability suppresses the fallback status; answering never depends on opening the activity manager.
- `src/boundary/host-delivery.ts` appends versioned branch receipts before calling the public custom-message sender, creates runtime generation IDs, reads active-branch receipt evidence, and checks bounded message metadata for context filtering.
- `src/boundary/host-prompt.ts` tracks Pi's coalesced public prompt lifecycle and this package's custom-call ownership. The application checks admission; the TUI boundary checks again immediately before mounting.
- `src/boundary/host-external-editor.ts` owns Pi settings, temporary files, and the inherited-terminal child process. Its named Promise boundary provides scoped file/process resources, requests termination on cancellation, removes owned files, and restarts the TUI. Trusted editor configuration and generated filenames are passed separately.
- `src/questionnaire/protocol.ts`, re-exported by `pi-ask-user/protocol`, defines plain root/child capabilities and bounded decoders. Descriptor capture permits absent choices for text but rejects text with any choices property; detached request normalization and outcome decoding preserve the text discriminator alongside the historical choices/custom tags. `host-owned-calls.ts` owns the exact-owner call registry that publishes the current root capability; `host-relay.ts` resolves the child relay at blocking-tool execution. Both sides of discovery use pi-cosmic-core's session-capability query: the relay and root capability take the last valid response. The authenticated coordinator alone supplies run, assignment, and request ownership. Owned answers return only to the proxy caller, never through automatic root steering. A fixed Pi child marker requires the relay and forbids fallback RPC dialogs and child async registration, but does not authenticate ownership. The root capability retains at most 16 live owner tuples, rejects duplicate active identities, and refuses a pre-aborted signal or a stale session before admission; a throwing session check counts as stale. `cancel(owner)` aborts the exact captured root call synchronously and acknowledges only after its actual runtime Promise, including overlay/editor finalizers, settles. It does not wait on a foreign answer Promise. Revocation aborts owned calls before disposal; captured old cancellation handles can join only their own generation.
- `src/tools/` owns blocking and async definitions and Promise-shaped domain callbacks. `contract-schema.ts` owns version-1 `pi-ask-user/questionnaire` output contracts, reusing `QuestionnaireOutcomeSchema`; `contract.ts` explicitly projects service facts without interpreting text or mutating decisions. All questionnaire tools, including async control, use the cooperative `pi-code-previews` shell.
- `src/ui/` owns synchronous presentation, input routing, previews, and pure layout. Questionnaires use the full widget width and cap their height at 60% of terminal rows, leaving room for the input dock. Pi owns final allocation, so unusually crowded or tiny terminals can still clip widgets. Short dialogs keep natural height; `ui/viewport.ts` bounds long content, follows selection and editor cursor, and pages complete prompts, previews, and review text. Page, half-page, and first/last navigation stay outside Editor input. Resizing and hide/resume retain drafts and focus. `q` never cancels the questionnaire.
- `tests/` protects questionnaire semantics, serialization, lifecycle, ownership races, host boundaries, defensive replay rendering, and public dialog behavior.

## Native structured results

Each owned tool declares its Effect-schema-derived output through core `toPiToolOutputSchema`. The strict JSON codec rejects excess properties and out-of-bounds producer facts; `freezeSnapshot` detaches and deeply freezes encoded structured content without freezing service snapshots or display details. Blocking results carry outcome/answers; async admission carries one public snapshot; control echoes action and optional request ID with at most 16 public snapshots. Projection excludes prompts, drafts, owner/generation tokens, waiter state and host capabilities. ID-free status omits outcomes even if a callback supplies one. Decision keys, values, labels, text and notes pass verbatim, never through display sanitizers or diagnostic redaction.

Normal text, details, renderers, modes, exposure and cancellation remain unchanged. Service rejection stays rejection. Encoding failure after an action returns an error without structured content, preserving the entire original receipt and details after one neutral failure line, never exposing codec diagnostics or replaying the action. Native scripts must check the envelope and actual outcome: admission is not an answer, cancel can lose to submission, and sent is not acknowledgement. Registered contract tests and faux-provider SDK sessions exercise the real definitions through native QuickJS with owned service/host fixtures, not real user prompts.

## Async ownership and delivery

`AskUserService` constructs the async controller under its Layer scope. The controller forks a child scope for presenters and delivery work; a later parent finalizer revokes delivery before child shutdown. One immutable `Ref` array owns at most 16 request entries. New admission evicts only the oldest terminal entry without a waiter whose delivery is `sent` or `waiter`. Unacknowledged failures and undelivered answers are not evicted. Explicit await or unopposed cancel acknowledges a terminal opening failure with `delivery: waiter`, making it evictable after the waiter releases its claim. A full registry without an eligible entry rejects admission rather than growing. Entries retain bounded work descriptions and final outcomes, not completed question drafts or host callbacks.

All blocking, owned-child, and async requests share 16 pending FIFO slots, separate from the 16 retained async results. Queue admission is an atomic `Ref` transition linking each ticket to its predecessor. A cancelled waiting caller settles promptly, but its queue slot remains occupied until the predecessor finishes. Its interruptible session-owned drain prevents successors from skipping ahead and bounds cancellation churn. Session closure revokes admission and interrupts drains. Active overlay and editor cleanup complete before the ticket advances. Automatic result delivery runs outside the ticket.

Async ticket acquisition, registry insertion, and session-scope fork form a short uninterruptible commit. No admission lock is held while the user answers. An immediate opener waits only for the separate mount Deferred. A queued opener returns its pending ID with `presentation: queued` immediately; admission is not mount acknowledgement or an answer. Queued questionnaires open automatically in FIFO order. Its caller signal never owns the presenter. If the opening call is interrupted after admission, `status` can recover the request ID. Opening failure settles a failed request, releases the permit, and fails the mount Deferred. Presenter cancellation races the host through an Effect-owned Deferred; tool await interruption does not cancel it.

Waiter claims are atomic `Ref.modify` transitions. A live await or unopposed cancel caller owns result delivery for that request. Cancel still signals the presenter when another caller owns delivery, then waits non-consumingly for cancellation to settle. Completion records the answer before waking the waiter or attempting automatic delivery. The waiter prepares its result without publishing a tentative acknowledgement. Its finalizer uses one interruptible, owner-checked `Ref.update` to publish `waiter` and release the claim atomically. That transition is final completion: pending interruption prevents it, but cancellation after publication cannot revoke it or a successor's acknowledgement. If interruption wins, masked cleanup releases only the caller's still-owned claim and leaves the previous delivery state intact, then offers automatic delivery in the session scope. Failed openings remain `none` until acknowledged, never a synthetic pending answer. Status is non-consuming; list status returns metadata only so it cannot multiply full answer output by the retention limit.

Without a waiter, the service claims automatic delivery. The host emits a custom `pi-ask-user-async-answer` message with `deliverAs: "steer"` and `triggerTurn: true`. This can continue an idle agent but cannot interrupt Pi's current tool batch. Request and delivery IDs remain stable across messages and control results. Results are retained after every delivery attempt. A synchronous host failure records `failed` and schedules at most two retries, one second apart, in the session scope. These sleeps do not hold the dialog permit. Recovery through await suppresses retries; scope closure cancels them. Exhausted failures remain retained for status/await recovery.

Pi's public sender returns `void`. `sent` therefore means only that the call returned. Later host errors and model consumption are not acknowledged, so this package promises neither exactly-once delivery nor reliable acceptance. Repeated delivery IDs must be treated as the same result. A status read can overlap an already claimed automatic message.

## TUI lifecycle and pinned host workaround

The TUI boundary lazily imports the dialog, then checks Effect interruption before reading settings or calling Pi. Async admission rejects unrelated public UI prompts but accepts queue entries behind an owned questionnaire. Blocking and queued async presenters wait for the public gate after lazy loading. The questionnaire host opens on Cosmic UI's shared `dock` surface (`pi-cosmic-ui/boundary/host-surface`). Its admission hook runs that second synchronous check in the same frame as `ui.custom`; a queued presenter retries a blocked admission after the gate reopens without losing its request. Pi coalesces nested prompts, so the boundary does not treat events as per-dialog counters or clear public prompt activity when only its own dialog closes. Each custom call owns one callback AbortController and bridge token; the surface owns the factory and finish latches and the overlay handle. Pinned Pi calls the component factory synchronously but mounts in a Promise continuation. The surface's mount callback, not factory execution, completes the opening Deferred. A finish requested before mounting is held; a late mount immediately removes the revoked questionnaire without activating its bridge. The external-editor command is read inside the factory, after the gate wait, so a retry reads it again.

Pinned Pi's custom `done` pops the global overlay stack rather than removing its own overlay, so the shared surface closes by removing the owned handle, showing an inert noncapturing guard, calling `done`, and removing the guard. An unrelated overlay above a hidden questionnaire is left intact. Host tests exercise submission, interruption, another stacked overlay, abort before mount, and each close fault. Cleanup detaches from a nonsettling `ui.custom` Promise. Closing revokes callback and editor admission authority before `done`; after `done` it disposes the dock, releases the prompt gate, and clears the bridge token, then joins nonrejecting settlement handles for every admitted editor before releasing the presenter's dialog permit or completing session disposal. The standalone editor runner retains process and temporary-file ownership through TUI restoration; process cancellation escalates after one second. Late editor successes and rejections cannot update a revoked dialog. The join intentionally waits for owned cleanup, not the arbitrary custom Promise, so a replacement cannot stop its TUI before the old editor restarts it.

The surface's Effect door owns completion independently of Pi's custom Promise. Synchronous finish failures reject with a redacted `AskUserHostError`, including guard cleanup failure after `done` resolves. The finish latch prevents reentrant or stale retries. Failed handle removal or guard acquisition never falls back to unguarded `done`. A throwing handle may leave its overlay behind. The FIFO ticket still releases after editor cleanup, but a nonsettling Pi Promise also retains its public prompt span. Subsequent presentation waits for a real host prompt-end event or session replacement, never a synthetic reset that could steal a foreign prompt's input.

Pressing `b` asks the host to collapse: the host owns hide/resume, calls the dock-wrapped handle's `setHidden(true)`, which suppresses the widget and drops input, and preserves the mounted dialog's drafts. `/ask-user` or the activity manager's token-checked Resume action restores it with `setHidden(false)`. The dialogs keep their TUI, editor, and drafts but no overlay handle. An async presenter also receives mount, hide, and resume signals through an Effect queue, so a pending request's status reports `open` or `hidden` and tells the agent the user can resume it. Activity rows publish queued, opening, mounted, hidden, and settled transitions; cancellation requires confirmation. Needs-input rows explicitly target the user, including authenticated child questionnaires. Settlement clears attention metadata. Standalone questions are roots. Only authenticated owned requests attach beneath `pi-subagents` run IDs. Settled summaries retain no drafts or cancellation callbacks; at most 16 settled rows remain. The main editor is never replaced or rewritten. Pi's UI-prompt notifications still include hidden custom dialogs; they do not pause agent execution.

## Session lifecycle and history

The factory registers callbacks, `/ask-user`, and the async answer custom-message renderer without acquiring resources. The message renderer is available before `session_start` and in every mode, reading compact/preview policy per invocation; it neither restores questionnaires nor registers tools. `session_start` captures the host, skips modes without UI except explicitly marked Pi children requiring root relay, starts one core managed runtime, loads trusted preview settings, and only then registers tools from the current activation hook. TUI receives all three tools; RPC receives only the blocking tool, routed to the root for marked local Pi children. Pi's `ctx.signal` is turn-dynamic and is not attached to the session slot, including tree restarts. Per-tool calls receive their own signals; explicit slot disposal still interrupts preview bootstrap and session work.

The factory also registers `registerCodePreviewReplay`, anchored to `/ask-user`, for the three questionnaire tools. History Pi rebuilds before `session_start` stays raw until that start's activation wraps tools through the replay shell and publishes; only tools the mode registered can adopt, so RPC async rows stay raw. That start's settlement closes no-UI, failed, or replaced startup; tree activations never publish, and shutdown retires replay. Replay never executes tools or changes registration or exposure.

Shutdown, reload, session replacement, and successful tree navigation revoke admission and delivery before disposal. Tree navigation replaces the runtime because Pi otherwise keeps it alive. Old registered tool callbacks reject during replacement. The slot's synchronous deactivation clears the bridge and current generation; no questionnaire is durably restored.

Immediately before each send, the host synchronously appends a version-1 `pi-ask-user-async-delivery` custom entry containing only generation and delivery ID to the originating branch. At session start and tree navigation, the application snapshots generation/delivery pairs from these receipts on the active branch before yielding into replacement. Answer messages never establish their own provenance. Context filtering admits this package's messages only if they belong to the current generation or have active-branch receipt evidence. Valid historical answers survive resume/navigation. A stale queued message persisted on a different branch stays rejected across repeated navigation and reload. Receipts do not restore pending work or confirm model consumption. Other messages and other extensions' queues are untouched. If the branch read is unavailable, old-generation messages fail closed. Filtering affects model context, not the visible transcript.

## Modes, security, and rendering

`ui/compact-summary.ts` classifies each settled questionnaire tool for the shared shell, which draws the same outcome and issue lines in both collapsed styles. It reads no service state and shares `ui/tool-render-projection.ts`, including one classifier of snapshot state (waiting, queued, answered, cancelled, failed) that preview bodies also use. Subjects are question titles, or `Questionnaire`/`all` beside the control action; request IDs never appear. A submission's counter holds verified choice labels for one choice question (each short, single-line, and matching a supplied choice), the kind of one custom or text answer, or else a count. Answer text and notes never enter compact rows. Pending requests are routine: the call succeeds, the counter says waiting or queued, and one informational issue carries the await guidance as its detail. Failed questionnaires are errors, failed automatic delivery is one grouped warning, and status lists count each state with shorter alternatives for narrow rows. Pi's error flag yields an error outcome that the shell explains from the error's first line; decoded cancellation wins over it. Inconsistent snapshots decline to the generic row.

`ui/tool-body.ts` holds the bodies all three tools and the answer message share. Preview headings come from `renderToolHeader`: "Ask user" with question titles, or "Questionnaire" with the action. Collapsed bodies preview each answer on one line with its note beneath it, a pending request's state, or a list's counts. The shell states failures and cancellations Pi reports as errors; the body states a cancellation the questionnaire returned. Expanded bodies in both styles list the exact arguments, with the shell's issue lines under the heading, then the agent-facing result under "Raw result" (or "Error"), where request and delivery IDs and agent guidance stay. A replay without text shows its answers whole. Compact answer messages use the shared planner, row, and issue renderer; no message shows its generation. Output padding, preview mode, and delivery lifecycle are unchanged.

RPC retains native `select`/`input` answer, optional-note, and review/edit/submit/cancel behavior. Its calls receive Effect-owned abort signals. Multi-select input accepts only valid choice numbers rather than reinterpreting malformed syntax as custom text. Ordinary JSON and print modes receive no questionnaire tools. Marked local Pi children may register the blocking relay tool without a local UI. Native Claude/Codex interactions and `contact_parent` are not forwarded by this package.

Prompts, previews, answers, notes, and work descriptions are ordinary session content. They never enter errors, logs, or telemetry attributes. Validation errors identify only question/choice positions. Guidance forbids collecting credentials. Display text boundaries strip terminal controls, including automatic messages and status output; native structured decision strings remain lossless.

Blocking and async renderers share private service-free Effect Schema projections and answer/fallback formatting in `src/ui/tool-render-projection.ts`. Both validate and display notes, and a malformed note declines to the raw text. Blocking replay accepts only content arrays; async replay also accepts string content. They cap array cardinalities, return neutral content for malformed input, and sanitize fallback text parts independently. `src/ui/async-tool-render.ts` projects async tool cards and automatic answer messages into readable states, answers, and notes. Expanded views show the agent-facing text, which carries request/delivery metadata, without implying model acknowledgement. The factory installs the existing async custom-message type's renderer independently of TUI-only, non-relay async tool registration. Details and safety guidance are unchanged; agent-facing text says whether a pending questionnaire is open, hidden, or still queued. Synchronous renderers never read the service or run Effects.

The application Layer owns `CodePreviewSchedulerService` in the same session runtime as its tools. Startup returns that scheduler to activation, which passes a token-checked scheduling capability to each cooperative wrapper. Replacement and shutdown close animation fibers; retained wrappers cannot schedule against a stale session. No animation depends on another extension's Jiti module instance.
