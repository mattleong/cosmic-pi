# Pi and platform boundaries

Effect application code is separated from APIs that Pi or third-party libraries require in another shape.

## Approved boundaries

### Pi registration

Extension factories only register callbacks; they do not acquire background resources. `session_start` creates one managed runtime for the started session, and callbacks delegate to it. A callback may pass Pi's `AbortSignal` to the runtime. The runtime is never recreated per event or command. Runtime creation cannot be owned by the runtime being created, so `pi-cosmic-core` provides one small host-boundary session slot for generation checks, replacement, abort-listener removal, and idempotent disposal; it owns no application polling or state.

### Shutdown

The Pi lifecycle boundary disposes the runtime and interrupts session fibers. Finalizers own timers, subscriptions, streams, file handles, HTTP agents, child sessions, and cached resources. Cosmic UI materializes the session CWD and AbortSignal capability through its bounded host-callback boundary before mutating or replacing the prior session. Capture first installs an owned native `AbortController` forwarder and only then reads the source's initial aborted state, so an abort cannot be lost before runtime registration. Advisor likewise materializes guarded CWD, model-registry, trust, and any session-start signal before replacement; it registers against that captured signal, rechecks `aborted` after listener installation to close the capture race, and releases the listener from the same application scope. Pi's agent-run signal is turn-dynamic and commonly absent at `session_start`, so every checkpoint separately captures the current run signal at synchronous admission and retains that exact capability for cancellation listening and post-provider delivery checks. Capture failure shuts down the prior slot instead of leaving stale work alive. Deactivation, failed or superseded startup, and short-lived event work release source listeners exactly once. Cosmic UI generation-checks delayed shutdown and failed-start resets, so old cleanup cannot clear replacement context, totals, ingress, or projections.

### User dialogs

`pi-ask-user` adapts Promise-shaped RPC dialogs in `host-dialogs.ts` and TUI overlays in `host-tui.ts`. RPC calls receive Effect-owned abort signals. TUI async tools wait for the `onHandle` mount acknowledgement, never the answer; a session-scope presenter owns the answer Promise and overlay cleanup independently of tool interruption. Pi 0.85 mounts after factory return and its custom `done` pops the global overlay stack. The boundary latches pre-mount finishes, removes only its owned handle, synchronously adds an inert noncapturing guard, calls `done`, and removes the guard in `finally`. This public-API workaround protects unrelated stacked overlays and can be removed once pinned Pi closes by identity. The synchronous dialog bridge retains only a token-checked resume capability and status, with no hidden raw input listener. `host-delivery.ts` adapts void-returning custom-message steering; successful return is not delivery acknowledgement. Retained results and stable delivery IDs support recovery. Session/tree replacement revokes send authority. Before sending, the boundary synchronously appends a versioned custom-entry receipt to the originating branch. Context filtering admits current-generation messages or generation/delivery pairs backed by receipts on the active branch, never by answer messages alone. Repeated navigation cannot promote a stale queued message. Other extensions' queues remain untouched. Coalesced public UI-prompt events gate async admission, with a second guard after the lazy import immediately before `ui.custom`; closing the owned dialog does not clear an unrelated nested prompt's activity.

Advisor onboarding uses the same `onHandle` identity guard and inert-overlay cleanup. An independent `Effect.callback` settles a redacted typed finish failure even if Pi's custom Promise cannot settle; guard creation failure never calls unguarded `done`.

Ask User revokes callbacks and editor admission synchronously at finalization, then joins every admitted editor's process, temporary-file, and TUI-restoration cleanup before releasing the dialog permit or transferring the session. It does not await an arbitrary `ui.custom` Promise. Late editor settlement cannot update the revoked dialog.

### Code Mode settings surface

`pi-code-mode` adapts `ctx.ui.select`, `input`, and `custom` as no-requirement session Effects in `boundary/host-ui.ts`. Select/input receive Effect-owned signals. Custom has no signal option, so it returns tagged `Closed`, `PromptInteger`, or `Failed` outcomes and owns a callback `AbortController` plus closing, factory, and done latches. The `ui.custom` Promise runs under `Effect.tryPromise`; an `Effect.ensuring` finalizer aborts callback authority and invokes an available `done(Closed)` once. A normal `PromptInteger` call is authoritative, and a factory arriving after finalization stores `done`, closes, and returns an inert component. Pi 0.84 has one editor slot, so the settings controller closes the list with `PromptInteger` before opening input. Scope selection, list settlement, pending preset-write joins, custom input, application, and fresh-snapshot reopening run as one outer session Effect submitted once to the slot. Each list iteration joins its nonrejecting preset and `inherit` Promises before handling the close or prompt outcome; the join remains interruptible. All command, list, active-write, and reopen signal checks use one guarded getter that falls back to aborted when the host getter throws. Custom input and application use the command Effect, not the aborted list signal. Cancelled, unavailable, and rejected custom input reopen unless the session was interrupted, state disappeared, or the custom component failed. Preset writes keep the list signal, which suppresses stale mutation and retains active optimistic-row rollback. The `code_mode` boundary is package-local: `boundary/codemode-runtime.ts` loads the shipped private `runtime/src/` TypeScript through one relative-path door, `host-builtin-tools.ts` dispatches seven core fresh definitions plus Windows-only PowerShell with
the `Effect.tryPromise` signal, `host-background-task.ts` queries only the versioned
`pi-background-task` stable-session capability, `host-mcp.ts` queries only the versioned `pi-mcp`
stable-session capability, and `host-tool-update.ts` contains undefined,
synchronous-throwing, and rejecting-thenable progress callbacks. Every private slot input owns a publication flag; deactivation revokes it before clearing state and disposal, so a late old-session commit cannot publish. Slot startup uses core `bestEffortHostBootstrap` for preview settings and returns `void`. Current-owner, current-token `onActivated` rereads the guarded live state before building, wrapping, registering, and activating the tool. The hostile renderer-ticker adapter (`boundary/host-render-ticker.ts`) owns weak ticker cleanup; the tools controller captures sanitized bounded expand keys once when it builds the definition. Pure rendering stays in `ui/tool-renderer.ts`; pure defensive details normalization lives in `ui/tool-render-details.ts`. Direct nested built-in dispatch still bypasses Pi middleware and registered overrides. The Background Tasks adapter does not invoke a registered definition; its provider
rechecks stable session identity, current slot token, and top-level activation on every query.

### Synchronous TUI rendering

Pi render methods remain synchronous. Better OpenAI, Better xAI, Cosmic UI, and code-preview services own state transitions and publish deeply frozen plain snapshots; their renderers read synchronous projections. Cosmic UI has one narrow live-data exception for Pi's synchronous footer, session, model, thinking-level, and context-usage getters. Each value is materialized through the bounded `HostCallbackBoundary` `host-query` operation with a neutral fallback before layout code uses it. Code previews expose one narrowly documented exception: the current Shiki highlighter is a third-party synchronous render capability paired with immutable generation/theme/language metadata. Initialization, language loading, callbacks, replacement, and disposal remain Effect-owned. The render cache belongs to one highlighter object and theme pair. Releasing a stale highlighter cannot discard a newer owner's cache. Advisor has no synchronous controller projection. Each `/advisor` command captures one readonly snapshot at Effect start from one application-state read plus queue activity, checkpoint orchestrator active count, and the last-candidate ref, and settings retain it across modal yields. The orchestrator contributes only its synchronous count callback, so a yielding cursor restart appears as reviewing and `/advisor cancel` can settle it while no queue is installed. Checkpoint and status handles never enter that snapshot. Synchronous renderer entrypoints should not import Effect runtimes, full services, or session capabilities. A renderer must not build a Layer, read an effectful Ref, or run an Effect.

### Tool renderer installation

`pi-code-previews` installs renderer-bearing replacements without reading or writing Pi's active tool selection. Settings choose which replacements to install, not which tool names the agent may call. Startup calls Pi 0.84's mandatory `getAllTools` directly, plans conflicts, resolves options, and constructs every planned definition before the first registry mutation. A failure in that pre-mutation phase reaches the lifecycle failure path with no partial install.

Once mutation begins, each `registerTool` failure becomes a bounded status with no raw error. Later replacements are still attempted and no rollback occurs. The lifecycle records every attempted name as owned immediately before registration, then records an install only after `registerTool` returns. This matches Pi 0.84, where registry mutation precedes refresh and refresh may throw. Discovery treats a visible nonbuiltin name in the owned set as retryable. Startup succeeds after partial registration so installed renderers retain the session runtime and failed replacements can retry on a later session start.

The lower `renderer-adapter.ts` factory is shared by the public cooperative wrapper and all built-in replacement factories. It captures one shell, copies the source definition once, preserves execution and result options, and calls supplied renderers as unbound functions. This matches Pi 0.84's `ToolExecutionComponent` renderer calls. Pi's mandatory `ToolRenderContext` shape is derived from `ToolDefinition` because the 0.84 package root does not re-export that named type.

### Tool schemas

Pi tool parameter declarations may use TypeBox or literal JSON Schema. Tool execution delegates to Effect immediately. This exception applies to schema representation, not implementation logic.

### Third-party libraries

Promise/callback libraries such as Pi APIs and Shiki are wrapped once with the appropriate Effect constructor in a named adapter. Their native errors are translated into typed domain failures.

Sharp runs only in Better OpenAI's fixed packaged `src/boundary/sharp-decoder.mjs` helper through core's opt-in bounded process adapter. No build, shell, caller argv, or caller environment is required. Parent and child cap input at 60 MiB. The child decodes all pages under a 40-million-pixel limit into uchar sRGB raw data with at most four channels; cache is disabled and concurrency is one inside the child. Only bounded, schema-decoded format JSON returns, never pixels, stderr, or native errors. One module-private immediate semaphore rejects busy calls across runtimes rather than queuing image buffers.

The permit covers process scope closure. A 30-second execution deadline requests process termination, with a two-second cleanup-confirmation budget and forced SIGKILL fallback. Sharp's cooperative raw timeout is secondary; stream destruction is not native cancellation. Core explicitly reports exit confirmation through a cleanup callback on success, interruption, and failure, including uncertainty during incomplete acquisition. This is necessary because the pinned spawner can swallow kill failure. Unconfirmed cleanup disables decoding until process restart. OS exit failure can prolong scope closure beyond these budgets while ownership and admission remain held. These work limits are not an OS memory sandbox.

### MCP gateway, SDK, and authentication

`pi-mcp` registers one `mcp` gateway, user-only `/mcp` and `/mcp-settings` commands, and a versioned Code Mode capability. `application/lifecycle.ts` is its Effect-to-Promise boundary, with one core-managed session runtime. Registration acquires no server resources and refuses a foreign `mcp` tool without modifying it. Session replacement revokes capabilities and result-publication authority before cleanup. The owned `tool_result` receipt hook restores actual Pi error status while preserving bounded completed output.

The gateway and fixed `tools.mcp.request` capability call the same execution service. Nested calls bypass Pi middleware, approvals from unrelated extensions, registered overrides, and previews. MCP trust, server policy, validation, and admission therefore live in shared services, not a Pi hook. The capability excludes explicit management, auth, config changes, and arbitrary protocol methods; each call rechecks one current provider for the same stable session.

`sdk-client.ts` uses public SDK requests and wire schemas without running remote JSON Schema compilation on Pi's thread. The fixed packaged validator helper runs through core's bounded process adapter before dispatch and after completed structured output. One immediate process-wide permit covers work and cleanup, and a private runner-keyed disabled record survives service replacement after uncertain cleanup. Accepted results remain completed when output validation, retention, or projection fails. Neither cancellation nor cleanup rolls back remote side effects, and uncertain or completed operations are never automatically replayed.

`boundary/sdk-stdio-transport.ts` uses public SDK framing over core's macOS duplex process owner. The SDK's stdio close does not supply the required process-group and pipe-close confirmation. Core therefore owns native spawn, one scoped writer, EOF-aware readers, byte accounting, and bounded confirmed cleanup. The MCP boundary owns protocol cancellation and reader/writer scope closure. It does not parse a separate wire protocol.

`boundary/sdk-fetch.ts` adapts the Effect `FetchHttpClient.Fetch` capability to the SDK's Promise/ReadableStream contract. Synchronous native callbacks transfer continuous fetch/body/discard leases and latch redacted failures. `sdk-http-transport.ts` owns per-operation and session-traffic cleanup; `sdk-http.ts` installs interruption-safe request and cached connection finalization. Consumer cancellation does not imply source cleanup, and uncertain cleanup revokes reuse. `sdk-http-control.ts` adds 16-slot admission and scoped admission-time deadlines for uncorrelated non-GET traffic, independently of long-lived GET streams and application calls. Control permits cover native cleanup; uncertainty permanently closes admission. The SDK receives token-only authentication with automatic auth recovery and reconnection disabled. These adapters own no detached Effect runtime.

`auth/service.ts` owns credential identity, serialized refresh, and revocation. A connection-owned auth fence prevents dispatch racing login/logout. `boundary/sdk-auth.ts` adapts SDK public-client OAuth registration, PKCE, exchange, and refresh under application issuer/resource/redirect policy. Browser opening and callback dialogs are explicit-user capabilities in `host-auth.ts`, never gateway or Code Mode parameters. `credential-store.ts` and `keychain.ts` use macOS Keychain without plaintext or session-only fallback. Native mutation fences distinguish an interrupted waiter from confirmed write/delete completion. Logout removes local grants only and reports failed deletion.

`auth/flow.ts` owns one explicit-user attempt around the complete execution login, with safe progress separate from private browser/callback capabilities. Ready evidence requires the exact inner login receipt and successful outer fence settlement. `host-auth.ts` uses fixed-title stock RPC confirmation/input/select dialogs; authorization URLs appear only in private message bodies. The TUI auth adapter uses an independent cancellation Deferred so browser work cannot delay or drop cancellation. Reopen ingress does not queue duplicates, and a host-local latch covers the native browser Promise after an interrupted waiter. The callback page acknowledges receipt without claiming authentication succeeded.

`manager/service.ts` aggregates passive connection/discovery observations and owns view/action admission. It never polls retained gateway status or resolves credentials. Cached browsing uses the discovery service's policy-filtered local API, not targeted gateway discovery. Results expose scoped change notifications for eviction and revocation without notifying on reads. Components withdraw cached text synchronously and reauthorize reads before restoring it. `host-ui.ts` and `host-auth-panel.ts` use `onHandle`, owned handle removal, and an inert completion guard to protect newer overlays, including pre-mount cancellation.

`activity/service.ts` records actual shared auth, connection, and metadata owners without duplicating tool calls. `host-mcp-status.ts` publishes bounded Activity v1 rows and keyed Cosmic UI status; its only action opens MCP details after activation/revision checks. It retains fallback status until acknowledgment and removes only its own contribution on disposal. Pure `ui/` renderers preserve machine envelopes, native images, receipts, and execution certainty. All Effects still enter through `application/lifecycle.ts`; these adapters create no runtime.

`boundary/auth-fetch.ts` resolves through core's `NetworkAddresses`, validates the candidate set, then passes `pinnedNetworkLookup` to a scoped HTTP agent. Connections cannot substitute a later DNS answer; approved redirects repeat the policy check. Core owns native lookup, while MCP owns destination policy. `boundary/auth-callback.ts` uses core's `nodeHttpServerLayer` for an auth-attempt-owned IPv4 loopback listener. Core owns listener/connection closure; MCP owns bind policy, routes, Host/origin checks, single-use state, and issuer validation. Manual login uses a user-only callback dialog with no local listener.

The result service retains bounded accepted output before projection and rechecks authority on reads. Top-level native images undergo MIME, header/container, base64, and dimension checks, not full decompression validation. Code Mode receives attachment descriptors rather than image bytes. Resource URLs are sent only to the selected MCP server; neither returned links nor prompt instructions are followed automatically. Server content remains untrusted data. A configured executable is trusted local code with user privileges, not a process confined by an OS sandbox.

### Cross-extension events

Cosmic UI events carry plain data and explicitly checked function capabilities. Providers import the narrow `pi-cosmic-ui/protocol` and `pi-cosmic-ui/client` subpaths, never the extension root. Events never carry Effect services, Layers, refs, scopes, fibers, or runtimes. The host answers discovery synchronously and retains a bounded, ordered pre-session event buffer; once a session starts, `FooterProtocolHost` drains it into a scoped ingress worker. `FooterRegistryService` serializes contribution state, owns surface child scopes and exact-once detach/dispose finalizers, and publishes only a frozen contribution snapshot plus checked render capabilities. Hostile callbacks are isolated by operation name, and bounded diagnostics never retain callback errors or payloads.

The activity protocol uses a host-activation nonce and producer registration identity in addition to the stable session ID. Widget availability is acknowledged only after successful installation and revoked on disposal. Producers retain their fallback UI until acknowledgement. Action and lazy-detail capabilities recheck generation and revision, receive an abort signal, and return bounded redacted content. Cosmic UI owns the manager overlay by handle; closing it cannot pop a newer questionnaire.

Ask User owns a bounded FIFO shared by blocking, async, and explicitly routed Pi-child questionnaires. Child relays carry structured requests through the authenticated subagent coordinator, which supplies assignment ownership. Parent-agent coordination questions remain separate. The root capability exposes exact-owner cancellation acknowledgement, so subagent cleanup joins questionnaire/editor finalizers without making the answer wait uninterruptible. Native supervisor and async child questionnaires are not routed by this protocol.

### Code-preview settings, syntax, write, and deferred-render boundaries

The settings service contract is `load`, `save`, and `flush`. Each service keeps one complete save context in a private `Ref`; building its Layer does not publish settings. A process-local coordinator uses one module-level semaphore and monotonic admissions to serialize work across live and one-shot runtimes. Publication currency advances only after a successful publication. A failed or interrupted newer operation therefore cannot suppress an older success. Loads update private state and publish conditionally while returning defensive clones. A one-shot save rehydrates and saves under one permit without publishing the intermediate load. A stale save exits before `modifyObject`, and global `flush` waits behind work from every Layer. Atomic replacement keeps lock order coordinator, document lock, then the lock-free `afterCommit` Ref update and conditional publication. Interruption cannot leave the renamed document ahead of the renderer projection. The syntax service contract is only `initialize`; status comes from the synchronous projection, while replacement and finalization stay private to the scoped service.

The write service contract is `rememberBeforeWrite` and `withPathLock`. Before-write correlation is owned by a serialized Effect projection. Tool result rendering performs a non-destructive lookup in a bounded, deeply frozen snapshot, so duplicate renders and call-ID reuse remain deterministic until eviction or scope cleanup. Write admission captures the originating token-bound session capability before entering Pi's cross-tool `withFileMutationQueue`. That runtime owns the interruptible outer queue wait. Cancellation, replacement, or shutdown revokes the delayed callback, which may use only the captured capability. Pi cannot physically remove a pending queue entry until its predecessor settles; the revoked callback is inert, and cancellation does not wait for the predecessor. The outer lock is acquired before the package-local Effect path lock. The former coordinates ordinary top-level and nested Code Mode edit/write definitions in the same process; the latter protects the read-before-write/write/correlation transaction inside the preview extension. Nested Code Mode mutations deliberately bypass that preview extension and therefore share only the outer mutation queue, not before-write correlation or a nested diff preview. Removing either lock from the flows that use it requires integration evidence that their ordering remains atomic.

Pi's write operation intentionally preserves direct filesystem mutation semantics for symlinks, hard links, inode identity, and open descriptors. Because that API has no separate atomic commit primitive, its bounded mkdir/write/correlation sequence is the commit region and remains uninterruptible under the path lock: an applied write must always publish the matching before-write projection before interruption becomes observable.

`DeferredPreview` uses accurately named deferred same-thread publication. No worker was added: the checked baseline used five `bench:render-boundaries` runs whose representative 250-line diff CPU medians were 6.109–6.346 ms (committed median 6.329 ms) and cancellation publication medians were 2.653–3.033 ms. The harness now performs three warmups plus nine raw timed samples, reports both sample lists and medians, and fails when the diff median exceeds the committed baseline by more than 10%; absolute 50 ms CPU and 100 ms cancellation budgets remain secondary responsiveness guards. The work is pure but a live Theme/TUI result and Shiki capability are not serializable; worker transfer would add complexity without an observed responsiveness problem. Reconsider only if profiling exceeds the blocking budget and a serializable preparation phase improves it without more than a 10% median render regression.

### Advisor synchronous admission and resource ownership

Advisor preserves synchronous Pi admission for observation ordering, cancellation latching, `AgentSession.followUp`, and status ownership. Pure application reducers coalesce session initialization, genuine-user-request admission, request cancellation, and committed configuration publication. Session initialization advances epoch and cancellation before its first yield, then applies loaded config against the latest state without rewinding those generations. Request-domain reset changes policy only; request and cancellation counters advance only in their owning reducers. `application/register.ts` submits each event or command to the session slot once. The internal dispatcher returns Effect directly, runs observation-only mutations before its first asynchronous yield, and returns the correlated final catch-up Effect without an Effect-to-Promise-to-Effect bounce. These callbacks only capture bounded/redacted plain data or flip a synchronous generation latch; dynamic session branch, context, activity, abort, and tool-metadata calls pass through typed or conservative no-throw adapters. Review context snapshots every input message record before inspection. It redacts the candidate before correlation and composition, and it redacts serialized roles so dynamic tool and extension headings cannot carry credentials into the model prompt. Checkpoint sequencing and cancellation finalization are owned by `CheckpointOrchestrator`; its synchronous active count also drives command activity and cancellation admission during queue-less cursor restarts. Its scope finalizer can run cancellation inline after the outer slot deactivates, contains defective cancellation callbacks, interrupts owned checkpoint fibers, and finalizes bookkeeping exactly once. Each checkpoint retains its admission request generation across any yielding restart, captures one provider owner generation only after that admission is revalidated, and applies one full currentness predicate after provider and verification yields and on rejection. Its idempotent review settler records one settled review and duration across completion, discard, failure, cancellation, and interruption. Stale success and rejection settle discarded without delivery or failure side effects. `AdvisorStatusService` and the clock boundary recover from hostile render/timer callbacks while retaining delayed/animated fiber ownership. Child replacement, reprime, cancellation, and disposal serialize lifecycle detachment. Usage and diagnostic callbacks carry the child start epoch. Dynamic application work and queues live under a child resource scope whose parent finalizer is registered before the application finalizer; Layer shutdown therefore advances epoch before that scope or refs close, so replaced-runtime and replaced-Layer callbacks and checkpoint failures cannot publish. The configured Advisor operation timeout is also the upper bound for awaiting the third-party `AgentSession.abort()` Promise, and that Promise always runs in an explicitly interruptible region. A successful abort preserves the reusable child at the successor epoch. Rejection, timeout, or interruption atomically detaches the installed child, marks the runtime reset-required, and invokes the session's synchronous forced-disposal boundary before lifecycle admission continues; no checkpoint can reuse it until a clean re-prime succeeds. Child acquisition forks its scope and registers the session finalizer in a bounded uninterruptible commit before restoring interruption for fallible ingress and subscription setup.

Persistent recovery settlement is a pure identity-checked application-state transition. Guidance retains semantic dedupe, emission history, and intervention budget while acknowledging findings, recording a receipt, and arming routing. Card-only delivery retains the same state but leaves findings open and adds no receipt. Total non-delivery rolls dedupe and emission state back and restores the previous budget with `correctionUsed` forced true. The handler persists each accepted settlement and emits an intervention observation only for guidance. Immediate abort-boundary failure remains a separate fallback because the parent abort never acquired recovery ownership.

The review queue is constructed directly under the captured application scope. It has no Context service Layer and no physical work `Queue`. One immutable `SynchronizedRef` state owns disposal, `processedThrough`, the running or cancelling entry, 16 FIFO queued entries, and wake rearming. Internal symbols own entries; external checkpoint IDs remain provider correlation fields. Every transition is pure. Barrier commit or release follows the ref commit, then isolated lifecycle callbacks, then worker wake or restart, with request `Deferred` completion last. Public ID cancellation chooses the active entry first and otherwise the oldest queued match. Caller interruption cancels its captured token. Active cancellation joins `FiberHandle.clear` and runtime abort cleanup before it settles; disposal commits disposed first, joins checkpoint and steering fibers, disposes the runtime, then releases barriers, settles callbacks exactly once, and fails pending requests.

Steering claims a running token and observation range atomically before `runtime.steer`. Acceptance checks the same token and running phase, so a late steer for a repeated checkpoint ID cannot advance its replacement. Newer unclaimed evidence is reoffered, and steering never commits evidence. Recovery, provider results, exact ID plus `processedThrough` correlation, poison-drop commits, and reprime calls use the same running-token gate. The second reset reprimes before it commits and drops the poison batch. Cancellation or disposal cannot reprime.

The queue's synchronous `processedThrough`, pending, and active properties call the documented rc.112 `SynchronizedRef.getUnsafe` over immutable states; backlog reads the separate observation buffer authority. These reads support synchronous command admission without a duplicate mutable copy. `AdvisorObservationBuffer` remains the separate evidence owner, and the capacity-one coalesced steering ingress remains the only queue-adjacent bounded ingress resource. Its observation records are package-private; production consumers receive bounded rendered strings rather than shared record references, so this boundary does not add defensive record copies or freezes.

A timed-out `createSession` Promise is detached from Effect ownership after a no-throw late-resolution callback is registered. Replacement and shutdown may then proceed; if the never-installed session eventually resolves, the callback synchronously force-disposes it exactly once, while late rejection is ignored without retaining its error. No arbitrary host Promise can hold scope closure indefinitely, and a replacement never overlaps an installed child still owned by the runtime. Semantically asynchronous continuations run in the scoped session runtime. No host callback launches a detached publication fork.

Advisor configuration persistence uses the shared atomic JSON-document modification capability. Commands and automatic onboarding use the same persistence function and no-fail `afterCommit` publication. The normalized configuration becomes authoritative application state in the rename commit region, advances `cancellationEpoch` once, and forks owned runtime convergence into the application scope before interruption becomes observable. Onboarding captures its config path before the modal yields and reports a fixed redacted warning on save failure; it never performs a partial publication or a second runtime start. Authentication-triggered shutdown uses the same application scope and remains non-blocking. Standalone compatibility writes retain their explicit sequential update because they do not own live session state.

### Advisor queue benchmark gate

The Advisor queue benchmark uses three reduced warmups followed by seven full samples (100,000 synchronous ingestions and 500 correlated checkpoints per sample), reports every raw per-operation sample, and compares medians with committed pre-cutover reference-machine baselines of 8.65 µs/ingestion and 0.0475 ms/checkpoint. It fails above 110% of either baseline. The JSON report is always printed first and includes every violation plus pass status for each metric; only then does the process set a nonzero exit code. Removing redundant dynamic Schema decoding from the descriptor snapshot hot path recovered the regression without changing the 9.515 µs ingestion or 0.05225 ms checkpoint limits. Two full same-machine runs measured ingestion medians of 8.933 and 8.921 µs, with checkpoint medians of 0.031 ms in both runs. These figures are a same-machine regression ratchet rather than portable hardware targets; a failure on materially different hardware must be reproduced against a fresh pre/post baseline on that machine, never waived from one noisy cold sample.

The remaining unsafe Effect calls are localized and documented. Process-global `Semaphore.makeUnsafe` values appear only where independently built runtimes must share admission. The core keyed process coordinator serializes access to the same resolved file, and removes idle key entries after their final user exits. The code-preview settings coordinator uses one private permit across live and short-lived Layers; queued callers remain interruptible, and the permit is never reacquired from `afterCommit`. Better OpenAI's Sharp boundary adds one module-private immediate semaphore across runtimes; its permit covers the decoder process and cleanup, and busy admission fails without queuing. None of these semaphores leaves its package or owns a process-wide Effect runtime. The shared core synchronous-ingress adapter owns exactly one `Queue.offerUnsafe` call; it exposes only bounded plain-data offer results (`accepted`, `dropped`, `coalesced`, or `closed`) while a scoped Effect fiber drains work. Advisor uses that adapter for its capacity-one, coalesced child-runtime control mailbox and has no package-local unsafe Queue offer. `CheckpointOrchestrator` uses one `Deferred.makeUnsafe` per synchronously admitted checkpoint because Pi cancellation admission cannot allocate effectfully; the Deferred never leaves the scoped orchestrator, has one claimed cancellation producer, and only joins duplicate cancellation/finalizer consumers. Parent host admission and checkpoint cancellation no longer use closure-owned callback sets. Ask User's `host-tui.ts` uses one `Deferred.doneUnsafe` call at Pi's synchronous `onHandle` callback to acknowledge a mounted overlay; the Deferred is allocated and awaited by the session service. Validated `DateTime.makeUnsafe` conversions and the advisor clock boundary's `Fiber.interruptUnsafe` calls are likewise intentional integration points that should remain narrow.

## Forbidden internal boundaries

Application services must not:

- call `Effect.run*` or a managed runtime,
- construct unmanaged Promises or timers,
- use global fetch or direct filesystem I/O,
- expose native `Error` or `unknown` in an Effect error channel,
- leak implementation service requirements through public methods.

## Advisor security

Advisor's read-only filesystem capability receives only the narrow filesystem and path Layers it needs. It must not receive an aggregate Node services Layer because that Layer also exposes process-spawning capabilities. Its exact no-process and no-mutation guarantee remains independently tested.
