# Settings workspace

Part of the [pi-subagents](../README.md) architecture documentation. See [ARCHITECTURE.md](../ARCHITECTURE.md) for the package overview, complete source map, and cross-cutting invariants.

## Settings safety

`/subagents profiles` is a full-screen responsive Profiles → Route → Candidate workspace that presents every profile's active resolved route and source while editing Session, Global, or trusted-Project declarations. A single `s Scope` control cycles `Session → Global → Project` when trusted and `Session ↔ Global` otherwise, while the workspace explains `Session > Project > Global > Built-in` precedence. Session routes are complete copy-on-write overlays of the activation-time effective route, apply immediately to new launches, and visibly shadow persistent edits; global editing still warns when a project declaration wins. Profile search, visible currently-applicable route actions, breadcrumbs, configured-keybinding labels, decoded Kitty printable shortcuts, and consistent Enter-forward/Escape-back navigation avoid hidden nested menus. Existing ordered candidates remain individually editable; candidate actions add (to 32), clone, move, and remove without implicit collapse or reorder. Destructive confirmation explains last-candidate disablement and scope shadowing. Disabled routes, missing global declarations (built-in), missing project declarations (inherit), and invalid fail-closed declarations remain distinct states. Invalid routes can be replaced, disabled, reset, or inherited without treating malformed data as current.

The candidate page exposes only the v4 product fields, including a per-candidate OpenAI fast-mode toggle. Pi eligibility follows the shared `pi-better-openai` model policy; Codex eligibility comes from the authenticated native model catalog's advertised `priority` service tier. Entering any editable row navigates within the existing workspace to a dedicated full-page searchable dropdown; Escape returns without changing the candidate. Fixed fields explain their active policy instead. Entering the model row uses the same interaction without opening a nested custom-UI dialog. The settings host awaits one Pi registry refresh before constructing the workspace and falls back to its captured authenticated snapshot with a bounded warning on refresh failure. Authenticated canonical Pi models then come from that registry, with `parent` offered only to local Pi; Herdr Pi omits extension-registered providers and fails closed when provider provenance is unavailable, while a configured unavailable selector remains an explicit current choice so Enter cannot silently replace it. Claude models come from the CLI's no-inference initialize catalog and Codex models from its bounded `model/list` request; both use the same picker page and preserve current/default fallback choices when discovery is unavailable. A native runtime change requires an advertised model selection before persistence. Runtime effort choices intersect the selected model's catalog-advertised values with one shared runtime-native policy, use that static vocabulary as fallback, and use current Pi model capabilities. The same policy is enforced by config decoding, route persistence, local preflight, and Herdr preflight. Host/runtime/write/model changes visibly normalize incompatible model, effort, fork, and retention values; fork and parent remain local-Pi-only, while retained reports remain Herdr-read-only-only. Advertised native models whose selectors cannot pass the shared bounded launch/config grammar are omitted. Short profile, route, candidate, and selector pages window around the selected row with explicit position/overflow cues. Model-catalog loading is independently cancelable with Escape and releases its native-catalog waiter. Route-level destructive actions remain on the Profiles or Route pages and never appear among candidate fields. Executable, argv, environment, session, and tool-policy controls are not exposed.

Each complete valid field or route action commits immediately; invalid intermediate values are never committed. Session mutations use a `SynchronizedRef` revision check, write no file or Pi session entry, and publish a frozen seed to the generation-checked application handoff. `i` removes the selected session override and `X` clears all temporary overrides after confirmation. The authoritative local handoff survives `/tree`, including a failed internal reconstruction followed by reload. On `/reload`, shutdown publishes only the frozen override seed to a process-global slot keyed by Pi's current session ID; the new extension instance strictly schema-decodes that envelope, loads the newly persistent base, reapplies the seed, and consumes the slot only after successful activation. Invalid envelopes are discarded. New/resume/fork, quit, and process restart clear the handoff. Active runs retain their admitted routes.

Global/project writes preserve unrelated declared profile routes, revalidate project trust/version and the strict root schema, compare the latest inspected document for optimistic concurrency, and re-inspect through the single `config/store.ts` persistence door. Those writes remain reload-required. A successful commit that cannot be re-inspected blocks further edits while retaining the applicable optimistic state; a failed commit likewise blocks stale revision/document reuse until the workspace is reopened. Reload retains the active-run stop warning and closes the stale settings workspace on success.

## Module responsibilities

- `src/settings/controller.ts` owns the `/subagents` command and host orchestration.
- `src/settings/profile-route-editor.ts` owns pure route draft operations and validation.
- `src/settings/ui/profile-workspace.ts`, `profile-workspace-render.ts`, `profile-workspace-model.ts`, `profile-workspace-actions.ts`, and `profile-workspace-selectors.ts` own the page-based profile workspace.
- `src/settings/ui/searchable-select-page.ts`, `candidate-editor.ts`, and `model-picker.ts` own bounded selectors and authenticated model choice.

Routing precedence and candidate validity are documented in [Routing](routing.md).
