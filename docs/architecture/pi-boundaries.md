# Pi and platform boundaries

Effect application code is separated from APIs that Pi or third-party libraries require in another shape.

## Approved boundaries

### Pi registration

Extension factories only register callbacks; they do not acquire background resources. `session_start` creates one managed runtime for the started session, and callbacks delegate to it. A callback may pass Pi's `AbortSignal` to the runtime. The runtime is never recreated per event or command. Runtime creation cannot be owned by the runtime being created, so `pi-cosmic-core` provides one small host-boundary session slot for generation checks, replacement, abort-listener removal, and idempotent disposal; it owns no application polling or state.

### Shutdown

The Pi lifecycle boundary disposes the runtime and interrupts session fibers. Finalizers own timers, subscriptions, streams, file handles, HTTP agents, child sessions, and cached resources. Cosmic UI materializes the session CWD and AbortSignal capability through its bounded host-callback boundary before mutating or replacing the prior session. Capture first installs an owned native `AbortController` forwarder and only then reads the source's initial aborted state, so an abort cannot be lost before runtime registration. Pi's agent-run signal is turn-dynamic and commonly absent at `session_start`, so every checkpoint separately captures the current run signal at synchronous admission and retains that exact capability for cancellation listening and post-provider delivery checks. Capture failure shuts down the prior slot instead of leaving stale work alive. Deactivation, failed or superseded startup, and short-lived event work release source listeners exactly once. Cosmic UI generation-checks delayed shutdown and failed-start resets, so old cleanup cannot clear replacement context, totals, ingress, or projections.

### User dialogs

`pi-ask-user` adapts Promise-shaped RPC dialogs in `host-dialogs.ts` and TUI overlays in `host-tui.ts`. RPC calls receive Effect-owned abort signals. TUI async tools wait for the `onHandle` mount acknowledgement, never the answer; a session-scope presenter owns the answer Promise and overlay cleanup independently of tool interruption. Pi 0.85 mounts after factory return and its custom `done` pops the global overlay stack. The boundary latches pre-mount finishes, removes only its owned handle, synchronously adds an inert noncapturing guard, calls `done`, and removes the guard in `finally`. This public-API workaround protects unrelated stacked overlays and can be removed once pinned Pi closes by identity. The synchronous dialog bridge retains only a token-checked resume capability and status, with no hidden raw input listener. `host-delivery.ts` adapts void-returning custom-message steering; successful return is not delivery acknowledgement. Retained results and stable delivery IDs support recovery. Session/tree replacement revokes send authority. Before sending, the boundary synchronously appends a versioned custom-entry receipt to the originating branch. Context filtering admits current-generation messages or generation/delivery pairs backed by receipts on the active branch, never by answer messages alone. Repeated navigation cannot promote a stale queued message. Other extensions' queues remain untouched. Coalesced public UI-prompt events gate async admission, with a second guard after the lazy import immediately before `ui.custom`; closing the owned dialog does not clear an unrelated nested prompt's activity.

Ask User revokes callbacks and editor admission synchronously at finalization, then joins every admitted editor's process, temporary-file, and TUI-restoration cleanup before releasing the dialog permit or transferring the session. It does not await an arbitrary `ui.custom` Promise. Late editor settlement cannot update the revoked dialog.

Its separate `OwnedFormCapability`, exported through `pi-ask-user/protocol`, serves local extensions with genuine `ExtensionFormOwner` identities. `host-form-proxy.ts` publishes only the current local UI generation and joins exact-owner cancellation. `form-service.ts` shares the existing 16-slot FIFO, prompt gate, and Activity lifecycle; `host-form-dialogs.ts` and `host-form-tui.ts` own bounded RPC/TUI presentation. Answers return only to the calling extension, never through model steering or persistence. URL dialogs show the full inert URL and host and return consent only. Ask User does not fetch or open URLs; MCP owns later navigation and authority rechecks. This is not a subagent relay or permission engine.

### Code Mode settings surface

`pi-code-mode` adapts `ctx.ui.select`, `input`, and `custom` as no-requirement session Effects in `boundary/host-ui.ts`. Select/input receive Effect-owned signals. Custom has no signal option, so it returns tagged `Closed`, `PromptInteger`, or `Failed` outcomes and owns a callback `AbortController` plus closing, factory, and done latches. The `ui.custom` Promise runs under `Effect.tryPromise`; an `Effect.ensuring` finalizer aborts callback authority and invokes an available `done(Closed)` once. A normal `PromptInteger` call is authoritative, and a factory arriving after finalization stores `done`, closes, and returns an inert component. Pi 0.84 has one editor slot, so the settings controller closes the list with `PromptInteger` before opening input. Scope selection, list settlement, pending preset-write joins, custom input, application, and fresh-snapshot reopening run as one outer session Effect submitted once to the slot. Each list iteration joins its nonrejecting preset and `inherit` Promises before handling the close or prompt outcome; the join remains interruptible. All command, list, active-write, and reopen signal checks use one guarded getter that falls back to aborted when the host getter throws. Custom input and application use the command Effect, not the aborted list signal. Cancelled, unavailable, and rejected custom input reopen unless the session was interrupted, state disappeared, or the custom component failed. Preset writes keep the list signal, which suppresses stale mutation and retains active optimistic-row rollback. The `code_mode` boundary is package-local: `boundary/codemode-runtime.ts` loads the shipped private `runtime/src/` TypeScript through one relative-path door, `host-builtin-tools.ts` dispatches seven core fresh definitions plus Windows-only PowerShell with
the `Effect.tryPromise` signal, `host-background-task.ts` queries only the versioned
`pi-background-task` stable-session capability, `host-mcp.ts` queries only the versioned `pi-mcp`
stable-session capability, and `host-tool-update.ts` contains undefined,
synchronous-throwing, and rejecting-thenable progress callbacks. Every private slot input owns a publication flag; deactivation revokes it before clearing state and disposal, so a late old-session commit cannot publish. Slot startup uses core `bestEffortHostBootstrap` for preview settings and returns the session-owned preview scheduler. Current-owner, current-token `onActivated` rereads the guarded live state before building, wrapping, registering, and activating the tool with token-checked animation scheduling. The hostile renderer-ticker adapter (`boundary/host-render-ticker.ts`) owns weak ticker cleanup; the tools controller captures sanitized bounded expand keys once when it builds the definition. Pure rendering stays in `ui/tool-renderer.ts`; pure defensive details normalization lives in `ui/tool-render-details.ts`. Direct nested built-in dispatch still bypasses Pi middleware and registered overrides. The Background Tasks adapter does not invoke a registered definition; its provider
rechecks stable session identity, current slot token, and top-level activation on every query.

Code Mode result capture crosses only the optional synchronous runtime `onResult` hook after
plain-data validation and before output bounding. The extension bounds serialization, retains
text in its scoped results service, and contains capture failure without relabeling execution.
`code_mode` result reads never construct an interpreter or dispatch tools. Their complete paging
envelope fits the current output-byte cap, retains the original outcome and rechecks publication
after waiting. Tree navigation replaces the runtime and revokes IDs; disabling revokes the
activation until reload. Receipts preserve completed and uncertain nested work, with guest
output delivery separate from adapter settlement. No recovery path automatically replays work.

### Synchronous TUI rendering

Cosmic UI's `boundary/host-viewport.ts` reads live terminal dimensions for one custom UI opening. Its retained options getters and component height callback share the pure `manager/viewport.ts` calculation. Pinned Pi 0.86.0 evaluates the options factory once but reads retained properties during rendering, so hosts must pass the options object without copying it. The adapter owns no listeners, runtime, focus, or cleanup. Embedded children consume allocated dimensions; compact dialogs retain natural height within the allocation.

Pi render methods remain synchronous. Better OpenAI, Better xAI, Cosmic UI, and code-preview services own state transitions and publish deeply frozen plain snapshots; their renderers read synchronous projections. Cosmic UI has one narrow live-data exception for Pi's synchronous footer, session, model, thinking-level, and context-usage getters. Each value is materialized through the bounded `HostCallbackBoundary` `host-query` operation with a neutral fallback before layout code uses it. Code previews expose one narrowly documented exception: the current Shiki highlighter is a third-party synchronous render capability paired with immutable generation/theme/language metadata. Initialization, language loading, callbacks, replacement, and disposal remain Effect-owned. The render cache belongs to one highlighter object and theme pair. Releasing a stale highlighter cannot discard a newer owner's cache. Synchronous renderer entrypoints should not import Effect runtimes, full services, or session capabilities. A renderer must not build a Layer, read an effectful Ref, or run an Effect.

### Tool renderer installation

`pi-code-previews` installs renderer-bearing replacements without reading or writing Pi's active tool selection. Settings choose which replacements to install, not which tool names the agent may call. Startup calls Pi 0.84's mandatory `getAllTools` directly, plans conflicts, resolves options, and constructs every planned definition before the first registry mutation. A failure in that pre-mutation phase reaches the lifecycle failure path with no partial install.

Once mutation begins, each `registerTool` failure becomes a bounded status with no raw error. Later replacements are still attempted and no rollback occurs. The lifecycle records every attempted name as owned immediately before registration, then records an install only after `registerTool` returns. This matches Pi 0.84, where registry mutation precedes refresh and refresh may throw. Discovery treats a visible nonbuiltin name in the owned set as retryable. Startup succeeds after partial registration so installed renderers retain the session runtime and failed replacements can retry on a later session start.

The lower `renderer-adapter.ts` factory is shared by the public cooperative wrapper and all built-in replacement factories. It captures one shell, including background mode and the opt-in `toolCallCollapsedStyle`, copies the source definition once, preserves execution and result options, and calls supplied renderers as unbound functions. This matches Pi 0.84's `ToolExecutionComponent` renderer calls. Pi's mandatory `ToolRenderContext` shape is derived from `ToolDefinition` because the 0.84 package root does not re-export that named type.

The [tool presentation standard](tool-presentation.md) governs every workspace-owned visible tool. `toolCallCollapsedStyle` defaults to `preview`; trusted settings load before wrapping, and wrapping captures style until reload. Compact tools use Pi's fixed `self` shell. Pure `planCompactPresentation` owns generic fallback and outcome reconciliation, never domain classification. Ordinary collapsed calls have one semantic heading; all retained children contribute attention before row selection. Unknown outcomes never become success merely because Pi returned without an error flag.

In compact expansion, opted-in content callbacks supply unique arguments, source, diffs, output, or reports beneath one shared heading. Each omitted callback keeps its original slot. Valid semantic summaries can use content callbacks despite unknown issue coverage; malformed or missing summaries retain original rendering. Complete coverage is required for failure-body takeover and legacy whole-call ownership. A failure body cannot hide unique call content or borrow claims from an unrendered result. Preview style retains original callbacks.

Renderer ownership uses explicit `CompactIssueClaim` evidence snapshots with selected fields, not blanket flags or operation/code identities alone. Subtraction validates causes, severity, recovery conflicts, and diagnostic evidence against the entire aggregate before removing anything. Additional merged evidence remains visible. Original-result claims apply only after the current result constructs and draws successfully; failure bodies use only their own claims. Component failures revoke claims and use safe raw output without replaying renderers. Original and content-only slots keep independent `lastComponent` caches; shared state, invalidation, mouse routing, and scoped timing remain intact. Operation identities are not default display labels. Rendering never changes execution, approvals, result bytes, native images, or the host transcript separator.

Built-in compact summaries apply only to installed `read`, `bash`, `write`, `edit`, `grep`, `find`, and `ls` replacements. Cooperative tools may supply a semantic summary provider. Missing or declined providers use generic compact rows with full details on expansion and never imply domain success. Cooperative hosts also compose the public `CodePreviewSchedulerService.layer` into their own session runtime and pass a token-checked `scheduleAnimation` callback. Pi's isolated Jiti loaders do not share the previews extension's module-local capability. The same injected scheduler drives compact icons and ordinary preview duration refresh; replacement/shutdown disposes its fibers, and unavailable scheduling is not cached as an active subscription. `preserveSelfShell` applies only to preview mode; compact mode wraps all cooperating tools. Neither compact mode nor its settings change active tool selection, execution, approvals, result contents, or native images. Pi's host-owned blank separator and separately rendered native images are outside the extension text-row budget.

### Tool schemas

Pi tool parameter declarations may use TypeBox or literal JSON Schema. Tool execution delegates to Effect immediately. This exception applies to schema representation, not implementation logic.

### Third-party libraries

Promise/callback libraries such as Pi APIs and Shiki are wrapped once with the appropriate Effect constructor in a named adapter. Their native errors are translated into typed domain failures.

Sharp runs only in Better OpenAI's fixed packaged `src/boundary/sharp-decoder.mjs` helper through core's opt-in bounded process adapter. No build, shell, caller argv, or caller environment is required. Parent and child cap input at 60 MiB. The child decodes all pages under a 40-million-pixel limit into uchar sRGB raw data with at most four channels; cache is disabled and concurrency is one inside the child. Only bounded, schema-decoded format JSON returns, never pixels, stderr, or native errors. One module-private immediate semaphore rejects busy calls across runtimes rather than queuing image buffers.

The permit covers process scope closure. A 30-second execution deadline requests process termination, with a two-second cleanup-confirmation budget and forced SIGKILL fallback. Sharp's cooperative raw timeout is secondary; stream destruction is not native cancellation. Core explicitly reports exit confirmation through a cleanup callback on success, interruption, and failure, including uncertainty during incomplete acquisition. This is necessary because the pinned spawner can swallow kill failure. Unconfirmed cleanup disables decoding until process restart. OS exit failure can prolong scope closure beyond these budgets while ownership and admission remain held. These work limits are not an OS memory sandbox.

### MCP gateway, SDK, and authentication

`pi-mcp` registers one `mcp` gateway, user-only `/mcp` and `/mcp-settings` commands, and a versioned Code Mode capability. `application/lifecycle.ts` is its Effect-to-Promise boundary, with one core-managed session runtime. Registration acquires no server resources and refuses a foreign `mcp` tool without modifying it. Session replacement revokes capabilities and result-publication authority before cleanup. The owned `tool_result` receipt hook restores actual Pi error status while preserving bounded completed output.

The gateway and fixed `tools.mcp.request` capability call the same execution service. Nested calls bypass Pi middleware, approvals from unrelated extensions, registered overrides, and previews. MCP trust, server policy, validation, and admission therefore live in shared services, not a Pi hook. The capability excludes explicit management, auth, config changes, and arbitrary protocol methods; each call rechecks one current provider for the same stable session.

`boundary/mcp-protocol/contract.ts` and `select.ts` separate MCP `2026-07-28` and pinned SDK legacy support over stdio and Streamable HTTP. `modern/` and `legacy/` cannot import each other. Protocol-neutral services and `shared/` helpers cannot directly import either implementation; only the selector combines them. Narrow Oxlint import restrictions leave tests and the selector unrestricted. Removing legacy support does not require changes to auth, discovery, execution, retention, or UI. Optional `protocol: "auto" | "legacy"` preserves canonical configuration without migrations or aliases. Historical HTTP+SSE remains unsupported; SSE within Streamable HTTP is not deprecated. The [MCP feature record](../plans/pi-mcp-features.md) tracks modern optional interaction and subscription work separately from historical acceptance. Legacy server-driven elicitation is not advertised.

`sdk-client.ts` uses public SDK requests and wire schemas without running remote JSON Schema compilation on Pi's thread. The fixed packaged validator helper runs through core's bounded process adapter before dispatch and after completed structured output. Identifiers and annotations grant no I/O or plugin authority. Synchronous compilation has no external schema loader, and conservative reference guards can reject valid schemas rather than silently weaken validation. One immediate process-wide permit covers work and cleanup, and a private runner-keyed disabled record survives service replacement after uncertain cleanup. Accepted results remain completed when output validation, retention, or projection fails. Neither cancellation nor cleanup rolls back remote side effects, and uncertain or completed operations are never automatically replayed.

`boundary/sdk-stdio-transport.ts` uses public SDK framing over core's macOS duplex process owner. The SDK's stdio close does not supply the required process-group and pipe-close confirmation. Core therefore owns native spawn, one scoped writer, EOF-aware readers, byte accounting, and bounded confirmed cleanup. The MCP boundary owns protocol cancellation and reader/writer scope closure, not a separate wire parser. Auto stdio negotiation scopes a disposable probe child and confirms cleanup before replacement. Only bounded protocol evidence permits HTTP fallback; auth failures, generic errors, malformed replies, and HTTP timeouts do not. A silent stdio probe may select legacy after its bounded deadline and confirmed child cleanup; early-exiting pre-initialize servers need explicit legacy mode.

`boundary/sdk-fetch.ts` adapts the Effect `FetchHttpClient.Fetch` capability to the SDK's Promise/ReadableStream contract. Synchronous native callbacks transfer continuous fetch/body/discard leases and latch redacted failures. `sdk-http-transport.ts` owns per-operation and session-traffic cleanup; `sdk-http.ts` installs interruption-safe request and cached connection finalization. Consumer cancellation does not imply source cleanup, and uncertain cleanup revokes reuse. `sdk-http-control.ts` adds 16-slot admission and scoped admission-time deadlines for uncorrelated non-GET traffic, independently of long-lived GET streams and application calls. Control permits cover native cleanup; uncertainty permanently closes admission. SSE budgets bound individual events and incomplete input, not lifetime stream bytes. Modern metadata subscriptions have an acknowledgement deadline and connection-owned lifetime; observation loss withdraws stale metadata. Legacy session-bearing POST 404 invalidates reuse without replay. DELETE 404 proves remote absence only, so local cleanup must still settle before replacement. The SDK receives token-only authentication with automatic auth recovery and reconnection disabled. These adapters own no detached Effect runtime.

`discovery/freshness.ts` bounds metadata `ttlMs`/`cacheScope` hints using monotonic time. Complete revisions use the earliest page/family expiry and retain authorization-revision identity. Absent, nonpositive, invalid, or greater-than-one-day TTL gives zero freshness. Initial active lookups reacquire expired metadata; passive browsing and cursor continuations stay local even when expired. Refresh, notification evidence, and auth/configuration changes invalidate cursors without relaxing invocation freshness. Public cache scope grants no cross-auth reuse. Changed credentials retire the old connection owner before schema reuse, requiring a later fresh request after confirmed cleanup rather than retrying the operation. Local result owners include revocation generation as well as configuration revision. `invocation/parameter-headers.ts` enforces modern-HTTP `x-mcp-header` annotations without schema compilation. Discovery excludes invalid tools; invocation rechecks declared string/safe-integer/boolean types, rejects invalid UTF-16, and mirrors standard `Mcp-Param-*` headers under 64-header/16 KiB encoded bounds before HTTP send. Legacy and stdio paths do not apply this requirement.

Completion, observations, and resource subscriptions use the existing MCP execution service. `completion/operations.ts` validates advertised references and arguments. `observations/` retains current-authority events for local string-cursor `events.read`; progress on both transports also reaches bounded top-level `onUpdate` callbacks. Explicit `logLevel` requires modern HTTP with advertised logging; legacy and modern stdio reject it before dispatch. Structured Logging is deprecated compatibility, not global logging or an OTel exporter. Progress is not deprecated.

`resources/subscriptions.ts` owns 16 leases per connection owner and 32 per session, explicit subscribe/unsubscribe, and local active-status inspection. Raw modern ingress requires the exact SDK-generated subscription ID and acknowledged URI filter. Both eras allocate a private identity before acquisition, carry it through the queue, and recheck it before publication, then strip it before retention. Modern raw ACK evidence allows bounded staging until SDK/filter acceptance. Matching readiness waits occur outside the registry lock; stale identities never wait on a replacement. One owner finalizer visits only current entries, so normal subscription churn does not retain historical cleanup closures. Legacy wire notifications cannot distinguish old server work first received after replacement. HTTP source cancellation must settle independently of SDK close. Stdio send reservations track actual native write settlement; SDK-swallowed write errors retain ownership until child cleanup. Successful pipe writes are not remote acknowledgements. Unknown legacy pre-acknowledgement outcomes retire the owner; failed cleanup never becomes unsubscribe success. No automatic reads, reconnect, or re-listening occur.

Private modern continuation applies only to tool calls, resource reads, and prompt retrieval. SDK constructor capabilities stay empty; only a current same-session TUI/RPC form provider enables per-request elicitation advertisement. No headless/legacy advertisement or public answer/state API exists. MCP bounds the conversation and maps strict flat forms; its sensitive-text heuristic is not a complete secret detector. Ask User shows full inert URLs and hosts for consent, while MCP owns system-browser navigation, manual resume, and fresh continuation authority checks. After auth rejection those checks prohibit more UI/browser work without erasing a separately completed reply's current-authority publication.

MCP's `host-ask-user.ts` waits one second for exact-owner cancellation. An opaque token per unresolved cancellation remains in a module-wide process-local set across runtime/session replacement. Only the exact Promise's successful settlement removes it; timeout/rejection blocks later provider resolution rather than claiming cleanup. The [feature record](../plans/pi-mcp-features.md) owns final acceptance.

Core's scoped `makeNativeContext` supplies `run`/`current` over native AsyncLocalStorage. It carries callback provenance around SDK HTTP send/onmessage and observation correlation, never authorization or an Effect execution context. Closing its scope withdraws reads/new runs before best-effort native disable. It adds neither a foreign parser nor an Effect runner; application owners still check authority.

`auth/service.ts` owns credential identity, serialized refresh, and revocation. A connection-owned auth fence prevents dispatch racing login/logout. `boundary/sdk-auth.ts` adapts SDK public-client OAuth registration, PKCE, exchange, and refresh under application issuer/resource/redirect policy. Browser opening and callback dialogs are explicit-user capabilities in `host-auth.ts`, never gateway or Code Mode parameters. `credential-store.ts` and `keychain.ts` use macOS Keychain without plaintext or session-only fallback. Core's cross-process lock serializes same-Keychain-account transactions beneath the actual OS account home's `.cosmic-pi-locks-v1`, independent of `HOME` and agent directories. Its default 15-second `acquireTimeoutMs` is separate from native Keychain `timeoutMs`. Auth-authority/local-store permits and filesystem acquisition inherit one monotonic admission budget. Timeout never expires admitted/native-pending work; local wake notifications promise neither FIFO nor a waiter cap, and synchronous filesystem stalls are not preemptible. The transaction covers reread, refresh quarantine and exchange, registration/grant persistence, and logout. A durable pending-native journal distinguishes waiter cancellation from mutation settlement. Dead quiescent owners can be reclaimed; native-pending owner death fails closed. Normal exact-owned `.released-<token>` deletion is best-effort; recovery barriers and crash/malformed artifacts remain without online GC or a global storage bound. Offline maintenance must stop all participating processes and reclaimers, inspect reviewed terminal artifacts only, and preserve pending evidence until independent native-settlement proof exists. PID death, age, and a fresh login are not proof. There is no reset CLI or bulk-root-deletion recovery; durable refresh quarantine must remain. Live trust/configuration checks run after waits and before refresh or publication, including headless checks. Managed bearer tokens cannot reach remote plaintext HTTP. Logout removes local grant and registration records only and reports failed deletion.

`auth/flow.ts` owns one explicit-user attempt around the complete execution login, with safe progress separate from private browser/callback capabilities. Ready evidence requires the exact inner login receipt and successful outer fence settlement. `host-auth.ts` uses fixed-title stock RPC confirmation/input/select dialogs; authorization URLs appear only in private message bodies. The TUI auth adapter uses an independent cancellation Deferred so browser work cannot delay or drop cancellation. Reopen ingress does not queue duplicates, and a host-local latch covers the native browser Promise after an interrupted waiter. The callback page acknowledges receipt without claiming authentication succeeded.

`manager/service.ts` aggregates passive connection/discovery observations and owns view/action admission. It never polls retained gateway status or resolves credentials. Cached browsing uses the discovery service's policy-filtered local API, not targeted gateway discovery. Results expose scoped change notifications for eviction and revocation without notifying on reads. Components withdraw cached text synchronously and reauthorize reads before restoring it. `host-ui.ts` and `host-auth-panel.ts` use `onHandle`, owned handle removal, and an inert completion guard to protect newer overlays, including pre-mount cancellation.

`activity/service.ts` records actual shared auth, connection, and metadata owners without duplicating tool calls. `host-mcp-status.ts` publishes bounded Activity v1 rows and keyed Cosmic UI status; its only action opens MCP details after activation/revision checks. It retains fallback status until acknowledgment and removes only its own contribution on disposal. Pure `ui/` renderers preserve machine envelopes, native images, receipts, and execution certainty. Display copies disclose cuts and expose recognized MCP text beside sanitized raw output. Retained readable mode requires a complete authorized JSON page; partial pages stay raw and original offsets remain authoritative. Switching views performs no I/O, and invalidation withdraws both variants. Discovery summaries are default data projections, separate from display copies: full immutable definitions still govern exact describe and invocation validation. All Effects still enter through `application/lifecycle.ts`; these adapters create no runtime.

`boundary/auth-fetch.ts` resolves through core's `NetworkAddresses`, validates the candidate set, then passes `pinnedNetworkLookup` to a scoped HTTP agent. Connections cannot substitute a later DNS answer; approved redirects repeat the policy check. Core owns native lookup, while MCP owns destination policy. `boundary/auth-callback.ts` uses core's `nodeHttpServerLayer` for an auth-attempt-owned IPv4 loopback listener. Core owns listener/connection closure; MCP owns bind policy, routes, Host/origin checks, single-use state, and issuer validation. Manual login uses a user-only callback dialog with no local listener.

The result service retains bounded accepted output before projection and rechecks authority on reads. Top-level native images undergo MIME, header/container, base64, and dimension checks, not full decompression validation. Code Mode receives attachment descriptors rather than image bytes. Resource URLs are sent only to the selected MCP server; neither returned links nor prompt instructions are followed automatically. Server content remains untrusted data. A configured executable is trusted local code with user privileges, not a process confined by an OS sandbox.

### Cross-extension events

Cosmic UI events carry plain data and explicitly checked function capabilities. Providers import the narrow `pi-cosmic-ui/protocol` and `pi-cosmic-ui/client` subpaths, never the extension root. Events never carry Effect services, Layers, refs, scopes, fibers, or runtimes. The host answers discovery synchronously and retains a bounded, ordered pre-session event buffer; once a session starts, `FooterProtocolHost` drains it into a scoped ingress worker. `FooterRegistryService` serializes contribution state, owns surface child scopes and exact-once detach/dispose finalizers, and publishes only a frozen contribution snapshot plus checked render capabilities. Hostile callbacks are isolated by operation name, and bounded diagnostics never retain callback errors or payloads.

The activity protocol uses a host-activation nonce and producer registration identity in addition to the stable session ID. Widget availability is acknowledged only after successful installation and revoked on disposal. Producers retain their fallback UI until acknowledgement. Action and lazy-detail capabilities recheck generation and revision, receive an abort signal, and return bounded redacted content. Cosmic UI owns the manager overlay by handle; closing it cannot pop a newer questionnaire.

Ask User owns a bounded FIFO shared by blocking, async, local-extension forms, and explicitly routed Pi-child questionnaires. Child relays carry structured requests through the authenticated subagent coordinator, which supplies assignment ownership. Parent-agent coordination questions remain separate. The root capability exposes exact-owner cancellation acknowledgement, so subagent cleanup joins questionnaire/editor finalizers without making the answer wait uninterruptible. Native supervisor and async child questionnaires are not routed by this protocol.

## Imperative boundaries

Effect runners are intentionally localized to these call owners:

- `pi-cosmic-core/src/runtime/runtime.ts`: the raw managed runtime is narrowed to `run`, `fork`, `runSync`, and idempotent `dispose`;
- `pi-code-previews/src/boundary/settings-one-shot.ts`: the named pre-session public settings compatibility runner; cross-runtime ordering belongs to the shared settings coordinator;
- `pi-ask-user/src/boundary/host-dialogs.ts`, `host-tui.ts`, `host-delivery.ts`, and `host-external-editor.ts`: abort-aware Pi RPC/custom dialog adaptation, the pinned public-API owned-overlay guard, mount-Deferred callback ingress, guarded custom-message steering and historical branch metadata, plus the inherited-terminal external-editor process and temporary-file lifecycle. The configured editor command is trusted host configuration; the generated filename is passed separately, the tool signal requests process termination, and cleanup restarts the TUI.
- `pi-cosmic-ui/src/boundary/host-ui-ticker-pool.ts` and `host-status.ts`: the process-lifetime, ref-counted, closeable-scope owner for synchronous Pi repaint tickers; Background Tasks, Code Mode, and Subagents consume only its plain start/stop callback door.
- `pi-mcp/src/application/lifecycle.ts`: the session-runtime submission boundary for gateway execution, user commands, and the stable-session Code Mode provider. SDK, auth, callback, credential, and validation adapters remain scoped services and create no independent runtime.
- `pi-code-mode/src/boundary/host-tool-update.ts`: one synchronous `Effect.runCallback` interruptor per pending frame flush; status-only updates coalesce to the latest snapshot, while semantic updates and settlement interrupt the pending flush before publishing synchronously.
- `pi-subagents/src/application/register.ts`: settings model refresh captures its originating activation and runs through that session boundary with editor cancellation. Current-activation checks reject stale submission and delayed inspection; the registry receives the Effect-owned signal, so a noncooperative Promise cannot retain the fiber or publish after interruption.
- `pi-background-task/src/boundary/local-process.ts`: cwd inspection is interruptible before masked spawn and release handoff. One process-scoped fiber owns bounded graceful Windows `taskkill`; force escalation interrupts and joins it before serialized bounded force attempts. Helper interruption kills and detaches the helper without waiting indefinitely for its exit. Task process settlement remains separately confirmed.
- `pi-subagents/src/boundary/process-tree.ts`: the Effect-native POSIX/Windows process-tree terminator plus its Promise compatibility door for synchronous Node callbacks; the Windows taskkill helper uses an interruptible Clock-owned deadline.
- `pi-subagents/src/boundary/writer-lease.ts`: bounded private agent-directory writer phase evidence, stable device/inode directory identity, durable pre-spawn marking, token-derived ABA tombstones, and atomic Node filesystem/PID-liveness primitives for same-host cross-process ownership. Spawn-started crash evidence is deliberately manual-recovery-only, and Windows writers are denied before this boundary until Job Object ownership exists.
- `pi-subagents/src/boundary/git-worktree*.ts`: fixed Git process calls, eligible filesystem snapshots, private standalone bare stores and detached worktrees, and durable artifact records. Stores contain snapshot objects, not the source repository's object database or history. Revisions and fresh successors use the original baseline, not a new snapshot of a changed parent checkout. `WorkspaceService` serializes these operations; the run coordinator checks direct-parent authority, confirmed process cleanup, complete exact-revision review, and the selected combined test preparation. Integration leases every existing ancestor of touched files and rechecks worker, preparation, source tree, HEAD, and index before journaled file publication. Ordinary new nested directories are supported. ### Code-preview settings, syntax, write, and deferred-render boundaries

The settings service contract is `load`, `save`, and `flush`. Each service keeps one complete save context in a private `Ref`; building its Layer does not publish settings. A process-local coordinator uses one module-level semaphore and monotonic admissions to serialize work across live and one-shot runtimes. Publication currency advances only after a successful publication. A failed or interrupted newer operation therefore cannot suppress an older success. Loads update private state and publish conditionally while returning defensive clones. A one-shot save rehydrates and saves under one permit without publishing the intermediate load. A stale save exits before `modifyObject`, and global `flush` waits behind work from every Layer. Atomic replacement keeps lock order coordinator, document lock, then the lock-free `afterCommit` Ref update and conditional publication. Interruption cannot leave the renamed document ahead of the renderer projection. The syntax service contract is only `initialize`; status comes from the synchronous projection, while replacement and finalization stay private to the scoped service.

The write service contract is `rememberBeforeWrite`. Before-write correlation is owned by a serialized Effect projection. Tool result rendering performs a non-destructive lookup in a bounded, deeply frozen snapshot, so duplicate renders and call-ID reuse remain deterministic until eviction or scope cleanup. Write admission captures the originating token-bound session capability. Native Pi write owns path resolution, the canonical cross-tool mutation queue, and abort checks around its operation callbacks. There is no outer queue wrapper or package-local `withPathLock`. The captured runtime owns the interruptible queue wait; cancellation, replacement, or shutdown aborts the native invocation without waiting for its held predecessor. Pi's delayed queue entry checks that signal before invoking any operation. Nested Code Mode mutations share the native queue but bypass before-write correlation and nested diff previews.

`boundary/host-write.ts` bridges Pi's Promise-only operation callbacks into scoped Effect workers using the invocation's services and scope. Its callback Promises join those workers without an abort signal, keeping Pi's queue held until admitted masked work settles. Directory creation is masked separately. The before-read remains interruptible after native queue admission; the write callback then checks abort before its masked direct write and correlation commit. An applied write publishes matching before-write evidence before interruption becomes observable. Direct mutation preserves Pi's symlink, hard-link, inode, and open-descriptor semantics without introducing an atomic replacement.

`DeferredPreview` uses accurately named deferred same-thread publication. No worker was added: the checked baseline used five `bench:render-boundaries` runs whose representative 250-line diff CPU medians were 6.109–6.346 ms (committed median 6.329 ms) and cancellation publication medians were 2.653–3.033 ms. The harness now performs three warmups plus nine raw timed samples, reports both sample lists and medians, and fails when the diff median exceeds the committed baseline by more than 10%; absolute 50 ms CPU and 100 ms cancellation budgets remain secondary responsiveness guards. The work is pure but a live Theme/TUI result and Shiki capability are not serializable; worker transfer would add complexity without an observed responsiveness problem. Reconsider only if profiling exceeds the blocking budget and a serializable preparation phase improves it without more than a 10% median render regression.

### Remaining unsafe Effect calls

The remaining unsafe Effect calls are localized and documented. Process-global `Semaphore.makeUnsafe` values appear only where independently built runtimes must share admission. The core keyed process coordinator serializes access to the same resolved file and removes idle key entries after their final users exit. The code-preview settings coordinator uses one private permit across live and short-lived Layers. Better OpenAI's Sharp boundary adds one module-private immediate semaphore across runtimes. The shared core synchronous-ingress adapter owns exactly one `Queue.offerUnsafe` call and exposes only bounded plain-data results while a scoped Effect fiber drains work. `CheckpointOrchestrator` uses one `Deferred.makeUnsafe` per synchronously admitted checkpoint because Pi cancellation admission cannot allocate effectfully. Ask User's `host-tui.ts` uses one `Deferred.doneUnsafe` call at Pi's synchronous `onHandle` callback. Validated `DateTime.makeUnsafe` conversions are likewise intentional integration points that should remain narrow.

## Forbidden internal boundaries

Application services must not:

- call `Effect.run*` or a managed runtime,
- construct unmanaged Promises or timers,
- use global fetch or direct filesystem I/O,
- expose native `Error` or `unknown` in an Effect error channel,
- leak implementation service requirements through public methods.
