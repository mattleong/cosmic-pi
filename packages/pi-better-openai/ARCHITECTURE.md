# Better OpenAI architecture

## Purpose

Adds OpenAI subscription usage, fast-mode request injection, provider-native compaction, image generation, settings, and footer output to Pi.

## Host surface

- Flag: `--fast`.
- Command: one `/openai` root from core's `registerExtensionCommand`, created at load in `src/application.ts` with `usage` and `fast`; `src/settings/controller.ts` adds `settings`, and `src/image/register.ts` adds or replaces `image` at each session activation alongside the image tool.
- Events: session lifecycle, agent/turn/model/message changes, `session_before_compact`, `before_provider_headers`, and `before_provider_request`.

## Source map

- `src/extension.ts` is the thin Pi package entrypoint.
- `src/application.ts` coordinates commands, host events, projections, and one session runtime.
- `src/layer.ts` composes usage, fast-mode, image, platform, and file/Sharp Layers.
- `src/auth/codex-auth.ts` reads `openai-codex` credentials only through Pi's model registry `getProviderAuth`, which owns refresh and persistence, and lossily parses the key as a JSON credential payload or an account-bearing JWT. A rejected lookup fails with a fixed `CodexAuthError`, an empty key is missing, and an unparseable non-empty key is `registry-decode`. Tokens remain `Redacted` until usage or image HTTP code constructs an authorization header. The diagnostics `Auth file:` line names Pi's default credential store.
- `src/usage/controller.ts`, `src/fast/service.ts`, `src/compaction/service.ts`, and `src/image/service.ts` are the feature Context service doors.
- `src/usage/projection.ts` owns frozen usage projection policy, and `debug.ts` owns deterministic diagnostics. `format.ts` defines the usage HTTP schema and projects its decoded root and primary bucket directly. It still decodes the unknown additional-limit entries before selecting the Spark bucket.
- `src/image/register.ts` owns image host names, registration, result formatting, and renderer-specific guards (legacy detail-backed images and image content). `service.ts` captures one context/config snapshot, resolves request options once, and orchestrates auth, HTTP, validation, and saving. `protocol.ts` builds requests from those resolved values and schema-decodes provider events into a normalized internal union.
- `src/image/compact-summary.ts` supplies a pure semantic opt-in to the cooperative preview shell, and the one classification both tool results and command messages use. It classifies validated image details, uses a shortened prompt as its subject with the saved file name as metadata, and declines unknown results or attachment-bearing errors. A failed status projects one error issue and typed incomplete states project one warning issue. Text-only failures project an error issue from the first line of their text; the full text stays in the labeled raw result. Expanded content already states the saved path, so no issue repeats it. Pi still owns native result images; execution and session resources are unchanged.
- `src/image/presentation.ts` owns the preview heading and the image body shared by tool results and command messages: format, size, and saved file, then the revised prompt and any raw text once expanded. In preview style the body states a cancellation the call did not report as an error; the shell states the ones it did. `src/image/message.ts` renders `/openai image` messages with the same heading, issue lines, and body the shell draws for the tool, so a message and a tool result for one record read the same. Pi owns native tool images; the message renderer owns its Image component, including legacy detail-backed images. Execution bytes are unchanged. Validated cancellation remains cancellation even when the host reports an error.
- `src/image/input.ts` owns input MIME detection and workspace containment. `stream.ts` owns bounded SSE framing and terminal outcomes. `output.ts` owns strict base64 decoding, output-format metadata, output containment, generated-byte validation, and publication. `types.ts` retains only contracts, constants, and the shared image-details guard used by the renderer and compact summary.
- `src/config/schema.ts` owns config shapes and defaults, `options.ts` owns setting descriptors (update decoding is shared core `decodeSettingUpdate`), and `store.ts` is the persistence door. `src/fast/controller.ts`, `src/fast/routing.ts`, `src/fast/models.ts`, and `src/image/protocol.ts` contain deterministic policy and protocol logic.
- `src/boundary/` isolates Pi UI, provider-header and cached-transport adaptation, schema-encoded and response-bounded OpenAI compaction HTTP, and Sharp. Best-effort UI effects call the total `pi-cosmic-core` host callback adapter and add no ignored error channel. `host-ui.ts` also owns the command-failure containment shared by `/openai fast`, `/openai usage`, and `/openai image`: typed failures and defects warn, and interrupts stay silent. Footer and usage projection code call the shared core OAuth host helper directly.
- `src/ui/primitives.ts` projects frozen provider state into plain footer contributions. Application orchestration queries Cosmic UI's v2 ownership, readiness, and visibility policy. Cosmic UI is the only custom-footer owner; providers use its sanitized keyed-status helper when no custom footer is active. Provider config has no footer mode or usage-display switch. Hidden usage suppresses automatic requests and both output paths, while the explicit usage command remains available. Visibility changes invalidate pending usage results and refresh newly visible usage. Deactivation removes contributions and clears provider status. Image tools retain the cooperative code-preview shell. The application merges its animation scheduler into the image session runtime and returns it with the fast-mode ingress through startup activation. Image registration receives a generation-checked scheduler callback; replacement and shutdown revoke scheduling and dispose ticks without relying on shared extension modules.
- `src/settings/controller.ts` adds `/openai settings` through Cosmic UI's shared settings subcommand (`pi-cosmic-ui/boundary/host-settings-command`), which owns completions, help, guarded diagnostics, validation messages, and the shared apply with its per-change `id = value` notice. `updateContext` runs on every invocation and before each apply. The signal is optional: each apply rereads it, a throwing getter applies without one, and a rejected apply warns unless its signal has aborted. Without a custom-UI TUI, the bare command shows help. The controller supplies the persistence call and keeps its grouped picker, which opens on Cosmic UI's shared inline surface (`pi-cosmic-ui/boundary/host-surface`); a throwing factory or failing `custom` call reports a failed open. The picker owns category-summary reconciliation from the authoritative projection after each write, the redacted-config refresh, and the outer `pi-cosmic-ui/manager/settings-surface` adapter with the package's guarded host rendering. Redacted raw configuration is rendered with standard JSON serialization. Cosmic UI projects config descriptors and owns the shared category submenu and diagnostic text panel; Better OpenAI supplies plain rows, persistence actions, and package-specific summaries. The outer adapter owns search; the small nested category lists do not create a second search input. `status` prints the diagnostics; in the picker, the Diagnostics item's id is `diagnostics`.

## State and resources

Usage, fast mode, compaction, and image work are scoped services. They publish immutable projections for synchronous request injection and rendering. Fast mode serializes transitions with one `SynchronizedRef` before publishing its frozen boundary snapshot. Its snapshots contain only owned boolean and string state, so cloning and freezing are total by contract. In-memory publication and persisted transitions keep publication uninterruptible; persisted transitions run it through config persistence's durable `afterCommit`, so the committed document and authoritative fast state cannot diverge. Fast-mode startup returns its scoped injection ingress through the session slot, so only the current activation can install it and deactivation immediately restores a no-op boundary. Omitted project-trust input is treated as untrusted; project-local configuration is read only after literal-true trust. OpenAI checkpoints live in normal branch-local Pi compaction entries under typed extension details. Pi retains the original branch for tree navigation; only its last entry stays in the new active context. Image streaming, file handles, and background refresh work are owned by the session runtime. Output writing opens, identifies, writes, and syncs the temporary file inside a nested scope, so its handle closes before publication. The outer pathname acquisition retains identity-checked cleanup. Image publication commits at the exclusive hard link. After that link succeeds, verification may report a positive identity mismatch but never removes the destination, which may already be a foreign replacement.

Sharp runs only in the shipped `src/boundary/sharp-decoder.mjs` one-shot process. `boundary/sharp.ts` opts into core `runBoundedProcessNode` with fixed `process.execPath` and helper path, no shell or caller argv/environment. Both sides reject stdin over 60 MiB. The child fully decodes all animation pages with strict error handling, a 40-million-pixel limit, sequential reads, and uchar sRGB raw output of at most four channels. Sharp cache is disabled and concurrency is one, only inside the child. Only bounded, schema-decoded format JSON crosses back; native errors, stderr, and pixels never reach callers.

One module-private immediate semaphore shares admission across session runtimes. Busy calls fail rather than queue image buffers. Its permit covers the runner's entire process scope, including cancellation cleanup. The 30-second execution deadline terminates the process, with a two-second cleanup confirmation budget and forced SIGKILL fallback. Sharp's cooperative 30-second raw timeout is secondary and does not bound metadata. Stream destruction is not native cancellation. Core's finalizer reports explicit child-exit confirmation through `onCleanup`, even on interruption or stream failure. Sharp defaults to unconfirmed and latches disabled before releasing admission unless cleanup confirms exit. A failed or partial spawn without a returned handle also disables decoding until restart, since the platform cannot prove no child survived. Confirmed cancellations remain reusable; a successful scope return or kill call alone is not confirmation. If the OS cannot terminate a child, core's platform finalizer can wait beyond these budgets for actual exit; ownership and the permit remain held, so shutdown has no unconditional wall-clock guarantee. The subprocess and pixel limits constrain work but are not an OS memory sandbox.

## Compaction

Compaction projects Pi's persisted transcript through public `normalizeContext`, `resolveTranscript`, and the Responses converter with the native provider's transcript, tool-addition, tool-search, and grammar options. Effect JSON codecs serialize the converter output before validation, matching the SDK's omission of optional undefined fields. Projection and injection exclude the same leading instruction prefix; mid-conversation system updates remain in the counted input.

Each new checkpoint keeps only the last pre-compaction branch entry, never an older compaction. `compaction/context.ts` reconstructs the plaintext conversation whenever the latest compaction is owned, regardless of configuration or current model. It replaces owned entries with inert cloned parent anchors before public `buildContextEntries` applies the last ordinary Pi compaction boundary. Public `getCurrentSystemMessage` folds the original prompt updates through the checkpoint, avoiding absent or already-obsolete v1 snapshots. Reconstruction emits that canonical system snapshot, the covered conversation with complete tool results and images, and genuine post-checkpoint updates. It never changes persisted entries or resurrects history summarized by ordinary Pi compaction.

The context hook replaces only an identified native session prefix and preserves non-session additions after it. Matching permits Pi's retry omission of persisted assistant `error` or `length` responses, but requires every other native message. A session-scoped Ref tracks observed omissions; actual native reappearance or tree navigation clears transient evidence. `willRetry` preparation accounts for the final response Pi removes before continuing. Optional v1 `omittedEntryIds` preserves covered exclusions across checkpoints and reload, with active-branch and assistant-stop-reason checks preventing metadata from deleting user, system, tool, successful assistant, or future-tail messages. Newly observed covered omissions disable stale encrypted reuse. A failed repair aborts the Pi run with a sanitized warning, because Pi contains extension exceptions. Encryption is optional: eligible matching-model requests replace the reconstructed covered prefix only after JSON-equivalent provider-prefix verification. A mismatch leaves complete plaintext. Subsequent OpenAI compaction uses that same reconstructed coverage to combine encrypted output with new tail input. The v1 stored count still describes native retained entries for read compatibility; it is not restored-context coverage.

`compaction/fallback.ts` prepares public native compaction from reconstructed history when configuration is disabled, the model changes, or the OpenAI endpoint fails. Public `findCutPoint` keeps tool groups intact and limits retention to entries after the owned checkpoint and any omitted response, so native replay cannot reinsert an omitted tail. Public `prepareBranchEntries` supplies file operations, not messages, since it omits tool results. Previous ordinary summaries and file operations survive. `boundary/host-compaction.ts` calls public `compact` through `ModelRegistry.streamSimple`, preserving native authentication and runtime selection with scoped cancellation, instructions, thinking level, and session routing. The ordinary result supersedes repair. Missing safe boundaries or failed fallback cancel compaction rather than passing Pi an incomplete preparation. Unowned sessions keep normal native fallback behavior. Pi persists an ordinary compaction's system snapshot from its unfiltered session, not the repaired request. If legacy native system state differs from reconstructed prompt sections or tool authority, fallback cancels rather than freezing that obsolete state and superseding repair. Full request-time repair still works; no persisted transcript mutation is attempted.

The service returns native `CompactionResult.usage`; Pi stores and totals it on the compaction entry without a second usage entry. Legacy checkpoint token fields remain readable, with optional cached input detail. Uncached input excludes cached tokens. Public `calculateCost` uses the captured request model's custom rates and token tiers. This is a catalog estimate, not an invoice-exact priority price: Pi's public calculator does not apply provider-private priority multipliers.

## Lifecycle

```text
session_start -> application -> layer -> abort-aware preview-settings bootstrap
                              -> usage + fast + image services -> current-session activation
current-session activation -> register image command/tool with captured preview shell settings
command/event -> runtime service -> projection -> footer/UI or request injection
Pi compaction trigger -> OpenAI /responses/compact -> custom checkpoint -> request projection
session_shutdown -> fibers/resources disposed -> projections reset
```
