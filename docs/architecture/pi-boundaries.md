# Pi and platform boundaries

Effect application code is separated from APIs that Pi or third-party libraries require in another shape.

## Approved boundaries

### Pi registration

Extension factories only register callbacks; they do not acquire background resources. `session_start` creates one managed runtime for the started session, and callbacks delegate to it. A callback may pass Pi's `AbortSignal` to the runtime. The runtime is never recreated per event or command. Runtime creation cannot be owned by the runtime being created, so `pi-cosmic-core` provides one small host-boundary session slot for generation checks, replacement, abort-listener removal, and idempotent disposal; it owns no application polling or state.

### Shutdown

The Pi lifecycle boundary disposes the runtime and interrupts session fibers. Finalizers own timers, subscriptions, streams, file handles, HTTP agents, child sessions, and cached resources. Cosmic UI materializes the session CWD and AbortSignal capability through its bounded host-callback boundary before mutating or replacing the prior session. Capture first installs an owned native `AbortController` forwarder and only then reads the source's initial aborted state, so an abort cannot be lost before runtime registration. Advisor likewise materializes guarded CWD, model-registry, trust, and any session-start signal before replacement; it registers against that captured signal, rechecks `aborted` after listener installation to close the capture race, and releases the listener from the same application scope. Pi's agent-run signal is turn-dynamic and commonly absent at `session_start`, so every checkpoint separately captures the current run signal at synchronous admission and retains that exact capability for cancellation listening and post-provider delivery checks. Capture failure shuts down the prior slot instead of leaving stale work alive. Deactivation, failed or superseded startup, and short-lived event work release source listeners exactly once.

### User dialogs

`pi-ask-user` adapts Pi's Promise-shaped TUI and RPC dialog APIs in one named host boundary. RPC `select` and `input` calls receive the Effect-owned abort signal directly. Pi's custom TUI component has no signal option, so the boundary also invokes the captured `done` callback synchronously when the Effect signal aborts; session disposal therefore cannot leave a modal overlay alive. The synchronous active-dialog bridge retains only a checked resume capability and status, uses activation tokens to reject stale cleanup, and never registers a hidden raw terminal-input listener.

### Code Mode settings surface

`pi-code-mode` adapts `ctx.ui.select`, `input`, and `custom` as no-requirement session Effects in `boundary/host-ui.ts`. Select/input receive Effect-owned signals. Custom has no signal option, so it returns tagged `Closed`, `PromptInteger`, or `Failed` outcomes and owns a callback `AbortController` plus closing, factory, and done latches. The `ui.custom` Promise runs under `Effect.tryPromise`; an `Effect.ensuring` finalizer aborts callback authority and invokes an available `done(Closed)` once. A normal `PromptInteger` call is authoritative, and a factory arriving after finalization stores `done`, closes, and returns an inert component. Pi 0.84 has one editor slot, so the settings controller closes the list with `PromptInteger` before opening input. Scope selection, list settlement, pending preset-write joins, custom input, application, and fresh-snapshot reopening run as one outer session Effect submitted once to the slot. Each list iteration joins its nonrejecting preset and `inherit` Promises before handling the close or prompt outcome; the join remains interruptible. All command, list, active-write, and reopen signal checks use one guarded getter that falls back to aborted when the host getter throws. Custom input and application use the command Effect, not the aborted list signal. Cancelled, unavailable, and rejected custom input reopen unless the session was interrupted, state disappeared, or the custom component failed. Preset writes keep the list signal, which suppresses stale mutation and retains active optimistic-row rollback. The `code_mode` boundary is package-local: `boundary/codemode-runtime.ts` loads the shipped private `runtime/src/` TypeScript through one relative-path door, `host-builtin-tools.ts` dispatches all seven fresh definitions with the `Effect.tryPromise` signal, and `host-tool-update.ts` contains undefined, synchronous-throwing, and rejecting-thenable progress callbacks. Every private slot input owns a publication flag; deactivation revokes it before clearing state and disposal, so a late old-session commit cannot publish. Slot startup uses core `bestEffortHostBootstrap` for preview settings and returns `void`. Current-owner, current-token `onActivated` rereads the guarded live state before building, wrapping, registering, and activating the tool. The tools controller owns weak ticker cleanup and captures sanitized bounded expand keys once when it builds the definition. Pure rendering stays in `ui/tool-renderer.ts`; pure defensive details normalization lives in `ui/tool-render-details.ts`. Direct nested dispatch still bypasses Pi middleware and registered overrides as recorded in ADR 0004.

### Synchronous TUI rendering

Pi render methods remain synchronous. Better OpenAI, Better xAI, Cosmic UI, and code-preview services own state transitions and publish deeply frozen plain snapshots; their renderers read synchronous projections. Cosmic UI has one narrow live-data exception for Pi's synchronous footer, session, model, thinking-level, and context-usage getters. Each value is materialized through the bounded `HostCallbackBoundary` `host-query` operation with a neutral fallback before layout code uses it. Code previews expose one narrowly documented exception: the current Shiki highlighter is a third-party synchronous render capability paired with immutable generation/theme/language metadata. Initialization, language loading, callbacks, replacement, and disposal remain Effect-owned. The render cache belongs to one highlighter object and theme pair. Releasing a stale highlighter cannot discard a newer owner's cache. Advisor publishes its controller state through a deeply frozen synchronous projection; checkpoint and status resource handles never enter that snapshot. Synchronous renderer entrypoints should not import Effect runtimes, full services, or session capabilities. A renderer must not build a Layer, read an effectful Ref, or run an Effect.

### Tool renderer installation

`pi-code-previews` installs renderer-bearing replacements without reading or writing Pi's active tool selection. Settings choose which replacements to install, not which tool names the agent may call. Startup calls Pi 0.84's mandatory `getAllTools` directly, plans conflicts, resolves options, and constructs every planned definition before the first registry mutation. A failure in that pre-mutation phase reaches the lifecycle failure path with no partial install.

Once mutation begins, each `registerTool` failure becomes a bounded status with no raw error. Later replacements are still attempted and no rollback occurs. The lifecycle records every attempted name as owned immediately before registration, then records an install only after `registerTool` returns. This matches Pi 0.84, where registry mutation precedes refresh and refresh may throw. Discovery treats a visible nonbuiltin name in the owned set as retryable. Startup succeeds after partial registration so installed renderers retain the session runtime and failed replacements can retry on a later session start.

The lower `renderer-adapter.ts` factory is shared by the public cooperative wrapper and all built-in replacement factories. It captures one shell, copies the source definition once, preserves execution and result options, and calls supplied renderers as unbound functions. This matches Pi 0.84's `ToolExecutionComponent` renderer calls. Pi's mandatory `ToolRenderContext` shape is derived from `ToolDefinition` because the 0.84 package root does not re-export that named type.

### Tool schemas

Pi tool parameter declarations may use TypeBox or literal JSON Schema. Tool execution delegates to Effect immediately. This exception applies to schema representation, not implementation logic.

### Third-party libraries

Promise/callback libraries such as Pi APIs, Sharp, and Shiki are wrapped once with the appropriate Effect constructor in a named adapter. Their native errors are translated into typed domain failures.

### Cross-extension events

Cosmic UI events carry plain data and explicitly checked function capabilities. Providers import the narrow `pi-cosmic-ui/protocol` and `pi-cosmic-ui/client` subpaths, never the extension root. Events never carry Effect services, Layers, refs, scopes, fibers, or runtimes. The host answers discovery synchronously and retains a bounded, ordered pre-session event buffer; once a session starts, `FooterProtocolHost` drains it into a scoped ingress worker. `FooterRegistryService` serializes contribution state, owns surface child scopes and exact-once detach/dispose finalizers, and publishes only a frozen contribution snapshot plus checked render capabilities. Hostile callbacks are isolated by operation name, and bounded diagnostics never retain callback errors or payloads.

## Imperative boundaries

Effect runners are intentionally localized to these call owners:

- `pi-cosmic-core/src/runtime/runtime.ts`: the raw managed runtime is narrowed to `run`, `fork`, `runSync`, and idempotent `dispose`;
- `pi-code-previews/src/boundary/settings-one-shot.ts`: the named pre-session public settings compatibility runner; cross-runtime ordering belongs to the shared settings coordinator;
- `pi-ask-user/src/boundary/host-dialogs.ts` and `host-external-editor.ts`: abort-aware Pi custom/RPC dialog adaptation plus the inherited-terminal external-editor process and temporary-file lifecycle. The configured editor command is trusted host configuration; the generated filename is passed separately, the tool signal requests process termination, and cleanup restarts the TUI.
- `pi-advisor/src/boundary/executor.ts`: the named Pi/compatibility adapter used at host and test boundaries;
- `pi-cosmic-ui/src/boundary/host-ui-ticker-pool.ts` and `host-status.ts`: the process-lifetime, ref-counted, closeable-scope owner for synchronous Pi repaint tickers; Background Terminals, Code Mode, and Subagents consume only its plain start/stop callback door.
- `pi-code-mode/src/boundary/host-tool-update.ts`: one synchronous `Effect.runCallback` interruptor per pending frame flush; status-only updates coalesce to the latest snapshot, while semantic updates and settlement interrupt the pending flush before publishing synchronously.
- `pi-subagents/src/boundary/process-tree.ts`: the Effect-native POSIX/Windows process-tree terminator plus its Promise compatibility door for synchronous Node callbacks; the Windows taskkill helper uses an interruptible Clock-owned deadline.
- `pi-subagents/src/boundary/writer-lease.ts`: bounded private agent-directory writer phase evidence, stable device/inode directory identity, durable pre-spawn marking, token-derived ABA tombstones, and atomic Node filesystem/PID-liveness primitives for same-host cross-process ownership. Spawn-started crash evidence is deliberately manual-recovery-only, and Windows writers are denied before this boundary until Job Object ownership exists.
- `pi-subagents/src/boundary/supervisor-channel.ts`, `supervisor-rpc-protocol.ts`, `supervisor-mcp-helper.mjs`, `supervisor-mcp-helper.ts`, and `src/supervisor/protocol.ts`: staged private-state acquisition plus Effect RPC v2 over scoped IPv4-loopback Effect Socket/NodeSocketServer services. The shared erasable-TypeScript protocol defines schema-bounded authenticated requests, assignment streaming/adoption, interruptible questions with explicit reply confirmation, and idempotent reports. One Deferred-shared close operation owns peer detachment, server-scope closure, and private-state removal; per-connection Effect deadlines own authentication expiry. The typed helper is the remaining foreign MCP JSON-RPC stdio adapter and an Effect RPC client. Because it owns its standalone Node process, one scoped `NodeRuntime.runMain` program owns input, output, sockets, watchers, active calls, and finalizer ordering; a minimal Jiti-backed `.mjs` launcher preserves plain-Node execution from installed packages. The boundary emits only bounded normalized supervisor/report events, retains exact accepted-report evidence for transport-close reconciliation, uses fixed packaged launch metadata, and is not exposed through the public start/profile surface.
- `pi-subagents/src/boundary/local-cli-harness.ts`, `local-cli-transport.ts`, `local-cli-process.ts`, and `claude-writer-cwd.ts`: shared foreign Claude scoped-Edit cwd/rule policy plus fixed local Claude/Codex executable/argv, sanitized environment, bounded readiness probes, isolated private launch/catalog/auth-probe harnesses with bounded Codex auth copy, bounded JSONL transport/backpressure, explicit Codex priority-service-tier requests/confirmation, and fail-closed platform-consistent process-group cleanup. Ownership is split: scoped Effect acquisitions in the harness boundary own private filesystem/auth/config state, the transport boundary owns child spawn and the bounded wire queue/termination, the `LocalCliProcess` service door owns cancelable preflight/probe orchestration without an internal runner plus Layer composition, and the narrow `claude-writer-cwd.ts` path adapter alone decides platform absoluteness before the pure `pi-subagents/src/backend/claude-policy.ts` grammar (no Effect, no Node) builds tool/settings/argv policy from the prevalidated result. They never accept free argv/env, pass a custom source Codex home to the child/probe, or write harness state into the project.
- `pi-subagents/src/boundary/native-model-catalog.ts`: fixed no-inference Claude initialize and Codex `model/list` settings probes with terminal-control-safe schema-bounded effort/service-tier catalogs, distinct request-rejection errors, sanitized environment, Effect-cancelable process IO/deadlines, cwd-scoped session caching and in-flight deduplication, isolated strict Codex configuration even through executable test seams, and confirmed process-tree/private-harness cleanup.
- `pi-subagents/src/boundary/herdr-cli.ts`, `herdr-harness.ts`, and `herdr-host.ts`: fixed inherited-session Herdr CLI protocol boundary, private sterile native harnesses, and parent-session-owned exact subagent panes. Mutation-free readiness requires the parent Pi's inherited calling pane in addition to shared native-selector and Claude writer-cwd checks. Launches split that caller, then the newest live owned pane in the same current workspace/tab; the boundary uses no public session/argv/env selector, transfers only a specifically resolved Herdr-Pi API key through a 0600 private bootstrap, revalidates workspace/tab/pane/terminal/agent/native-session identity before every state change, preserves uncertain private state, and never closes the calling pane, tab, or workspace.
- `pi-subagents/src/boundary/host-pi-supervisor-extension.ts` and `pi-supervisor-bridge-client.ts`: sole Herdr-Pi bridge extension/client, owned by a delegated-session runtime slot whose Layer scopes the packaged concurrent supervisor MCP helper and joins its cleanup on shutdown. It also applies the private per-candidate OpenAI priority-tier request hook for eligible Pi models. Four strictly bounded `pi-code-previews` cooperative tools multiplex through that helper; no custom Pi process RPC or report file is introduced. The complete current boundary and topology map is indexed from [`packages/pi-subagents/ARCHITECTURE.md`](../../packages/pi-subagents/ARCHITECTURE.md).
- `pi-herdr-fork/src/boundary/host-session.ts`, `session-file.ts`, `host-link-store.ts`, and `herdr-client.ts`: guarded parent-session capture, exclusive blank-child creation, bounded no-follow session-header probes, parent-session custom-entry persistence, and the fixed Herdr process/protocol boundary for `/herdr-fork` and `/herdr-fork:new`. The commands target only the inherited calling pane, create or resume one blank child session with fixed argv, revalidate exact live Herdr session identity before focus, and retain outcome-uncertain panes rather than retrying or closing them. A generation-checked host projection gives marked child sessions a reference to the live parent file; it revalidates the parent header before each child run and never imports transcript content.

Direct filesystem imports are limited to core `SafeFile`, advisor's narrow read-only Node filesystem adapter and pure synchronous path adapter, pi-subagents' private cross-process writer-lease, supervisor-channel and helper no-follow configuration boundaries, and local-CLI/Herdr harness boundaries, plus herdr-fork's regular non-symlink parent-session check. Process spawning is localized to Background Terminals' scoped Effect child boundary, pi-subagents' IPC/foreign-protocol adapters and fixed no-inference catalog requests, and herdr-fork's fixed bounded `herdr` CLI boundary. Process, network, worker, VM, and child-process Node modules are rejected outside exact adapters. Reflected environment reads are currently limited to code-preview's environment and serialized one-shot settings boundaries. Raw JSON compatibility boundaries are limited to the named advisor and code-preview protocol adapters. Provider HTTP boundaries cannot expose unknown JSON bodies: provider-local schemas decode accepted JSON responses, rejected responses preserve status and response text without entering errors or telemetry, and streaming JSON requests are schema-encoded before explicitly named raw response bytes reach protocol parsers. Pi's Promise-returning xAI model-registry lookup is isolated by the typed `ModelRegistryAuth` Layer. TypeBox is limited to Pi agent-tool parameter schemas such as advisor and pi-subagents. These locations document the current integration boundaries; changes should be justified in review. All package-local runtime facades were removed.

### Code-preview settings, syntax, write, and deferred-render boundaries

The settings service contract is `load`, `save`, and `flush`. Each service keeps one complete save context in a private `Ref`; building its Layer does not publish settings. A process-local coordinator uses one module-level semaphore and monotonic admissions to serialize work across live and one-shot runtimes. Publication currency advances only after a successful publication. A failed or interrupted newer operation therefore cannot suppress an older success. Loads update private state and publish conditionally while returning defensive clones. A one-shot save rehydrates and saves under one permit without publishing the intermediate load. A stale save exits before `modifyObject`, and global `flush` waits behind work from every Layer. Atomic replacement keeps lock order coordinator, document lock, then the lock-free `afterCommit` Ref update and conditional publication. Interruption cannot leave the renamed document ahead of the renderer projection. The syntax service contract is only `initialize`; status comes from the synchronous projection, while replacement and finalization stay private to the scoped service.

The write service contract is `rememberBeforeWrite` and `withPathLock`. Before-write correlation is owned by a serialized Effect projection. Tool result rendering performs a non-destructive lookup in a bounded, deeply frozen snapshot, so duplicate renders and call-ID reuse remain deterministic until eviction or scope cleanup. Pi's cross-tool `withFileMutationQueue` remains the outer lock and is acquired before the package-local Effect path lock. The former coordinates ordinary top-level and nested Code Mode edit/write definitions in the same process; the latter protects the read-before-write/write/correlation transaction inside the preview extension. Nested Code Mode mutations deliberately bypass that preview extension and therefore share only the outer mutation queue, not before-write correlation or a nested diff preview (ADR 0004). Removing either lock from the flows that use it requires integration evidence that their ordering remains atomic.

Pi's write operation intentionally preserves direct filesystem mutation semantics for symlinks, hard links, inode identity, and open descriptors. Because that API has no separate atomic commit primitive, its bounded mkdir/write/correlation sequence is the commit region and remains uninterruptible under the path lock: an applied write must always publish the matching before-write projection before interruption becomes observable.

`DeferredPreview` uses accurately named deferred same-thread publication. No worker was added: the checked baseline used five `bench:render-boundaries` runs whose representative 250-line diff CPU medians were 6.109–6.346 ms (committed median 6.329 ms) and cancellation publication medians were 2.653–3.033 ms. The harness now performs three warmups plus nine raw timed samples, reports both sample lists and medians, and fails when the diff median exceeds the committed baseline by more than 10%; absolute 50 ms CPU and 100 ms cancellation budgets remain secondary responsiveness guards. The work is pure but a live Theme/TUI result and Shiki capability are not serializable; worker transfer would add complexity without an observed responsiveness problem. Reconsider only if profiling exceeds the blocking budget and a serializable preparation phase improves it without more than a 10% median render regression.

### Advisor synchronous admission and resource ownership

Advisor preserves synchronous Pi admission for observation ordering, cancellation latching, `AgentSession.followUp`, and status ownership. These callbacks only capture bounded/redacted plain data or flip a synchronous generation latch; dynamic session branch, context, activity, abort, and tool-metadata calls pass through typed or conservative no-throw adapters. Checkpoint sequencing and cancellation finalization are owned by `CheckpointOrchestrator`; its scope finalizer can run cancellation inline after the outer slot deactivates, contains defective cancellation callbacks, interrupts owned checkpoint fibers, and finalizes bookkeeping exactly once. `AdvisorStatusService` and the clock boundary recover from hostile render/timer callbacks while retaining delayed/animated fiber ownership. Child replacement, reprime, cancellation, and disposal serialize lifecycle detachment. The configured Advisor operation timeout is also the upper bound for awaiting the third-party `AgentSession.abort()` Promise, and that Promise always runs in an explicitly interruptible region. A successful abort preserves the reusable child at the successor epoch. Rejection, timeout, or interruption atomically detaches the installed child, marks the runtime reset-required, and invokes the session's synchronous forced-disposal boundary before lifecycle admission continues; no checkpoint can reuse it until a clean re-prime succeeds. Child acquisition forks its scope and registers the session finalizer in a bounded uninterruptible commit before restoring interruption for fallible ingress and subscription setup.

A timed-out `createSession` Promise is detached from Effect ownership after a no-throw late-resolution callback is registered. Replacement and shutdown may then proceed; if the never-installed session eventually resolves, the callback synchronously force-disposes it exactly once, while late rejection is ignored without retaining its error. No arbitrary host Promise can hold scope closure indefinitely, and a replacement never overlaps an installed child still owned by the runtime. Semantically asynchronous continuations run in the scoped session runtime. No host callback launches a detached snapshot-publication fork.

Advisor configuration persistence uses the shared atomic JSON-document modification capability. The normalized configuration's authoritative state and frozen projection publish as the rename's no-fail `afterCommit` action in the same uninterruptible commit region; the action also schedules the owned runtime convergence before interruption becomes observable. Standalone compatibility writes retain their explicit sequential update because they do not own a session projection.

### Advisor queue benchmark gate

The Advisor queue benchmark uses three reduced warmups followed by seven full samples (100,000 synchronous ingestions and 500 correlated checkpoints per sample), reports every raw per-operation sample, and compares medians with committed pre-cutover reference-machine baselines of 8.65 µs/ingestion and 0.0475 ms/checkpoint. It fails above 110% of either baseline. These figures are a same-machine regression ratchet rather than portable hardware targets; a failure on materially different hardware must be reproduced against a fresh pre/post baseline on that machine, never waived from one noisy cold sample.

The remaining unsafe Effect calls are localized and documented. Process-global `Semaphore.makeUnsafe` values appear only where independently built runtimes must share admission. The core keyed process coordinator serializes access to the same resolved file, and removes idle key entries after their final user exits. The code-preview settings coordinator uses one private permit across live and short-lived Layers; queued callers remain interruptible, and the permit is never reacquired from `afterCommit`. Neither semaphore leaves its package. The shared core synchronous-ingress adapter owns exactly one `Queue.offerUnsafe` call; it exposes only bounded plain-data offer results (`accepted`, `dropped`, `coalesced`, or `closed`) while a scoped Effect fiber drains work. Advisor uses that adapter for its capacity-one, coalesced child-runtime control mailbox and has no package-local unsafe Queue offer. `CheckpointOrchestrator` uses one `Deferred.makeUnsafe` per synchronously admitted checkpoint because Pi cancellation admission cannot allocate effectfully; the Deferred never leaves the scoped orchestrator, has one claimed cancellation producer, and only joins duplicate cancellation/finalizer consumers. Parent host admission and checkpoint cancellation no longer use closure-owned callback sets. Validated `DateTime.makeUnsafe` conversions and the advisor clock boundary's `Fiber.interruptUnsafe` calls are likewise intentional integration points that should remain narrow.

## Forbidden internal boundaries

Application services must not:

- call `Effect.run*` or a managed runtime,
- construct unmanaged Promises or timers,
- use global fetch or direct filesystem I/O,
- expose native `Error` or `unknown` in an Effect error channel,
- leak implementation service requirements through public methods.

## Advisor security

Advisor's read-only filesystem capability receives only the narrow filesystem and path Layers it needs. It must not receive an aggregate Node services Layer because that Layer also exposes process-spawning capabilities. Its exact no-process and no-mutation guarantee remains independently tested.
