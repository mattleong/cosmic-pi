# Code Previews architecture

## Purpose

Provides syntax-highlighted previews, structured diffs, safer write/edit presentation, settings, and cooperative tool-shell APIs.

## Host surface

- Commands: preview health and settings (`settings/controller.ts`, `commands/health.ts`); both guard non-TUI hosts and fall back to plain notifications instead of opening custom UI. Health opens its component-sized panel on Cosmic UI's shared `overlay` surface, so closing never pops an overlay stacked above it; a failed opening rejects the command.
- Events: `session_start` and `session_shutdown`.
- Tool surface: installed replacements for supported built-in tools and the public cooperative shell wrapper. The extension never changes Pi's active tool names.

## Source map

- `src/extension.ts` is the thin Pi package entrypoint.
- `src/application/lifecycle.ts` coordinates runtime replacement, settings startup, syntax initialization, and renderer installation. It uses the shared host-session capture, fail-closed trust, and best-effort notification boundaries.
- `src/application/capability.ts` is the canonical named bridge used by synchronous callers. Its `activeCapability` is the sole authority for active checks, runtime execution, deferral, and scheduling. Inactive defer calls return a no-op canceller, and animation without a captured capability does not schedule. Each installed run capability checks its captured runtime-slot token before calling the mutable slot. Cleanup is unconditional.
- `src/application/scheduler.ts` owns deferred and fixed-cadence renderer callbacks in a scoped `FiberSet`; synchronous disposers interrupt immediately, while session runtime disposal awaits every remaining scheduler fiber. Startup returns the scheduler through the runtime slot's activation value. The public scheduler Layer lets cooperative extensions own the same scoped service in their own session runtime and inject `scheduleAnimation`; independent Jiti loaders do not share the previews capability. Absent scheduling is not cached as an active animation.
- `src/layer.ts` is the sole application Layer composition root. Agent directory, environment, and Shiki adapters are private dependencies of the settings, syntax, write, and scheduler services. The final Layer retains the Node file-platform services so effects run through the session capability can use them.
- `src/config/store.ts` is the public settings persistence entrypoint for `CodePreviewSettingsService`, the loader, and the panel's Promise helpers. The service exposes `load`, `save`, and `flush`. The service keeps one complete save context in a private `Ref`; Layer construction does not publish settings. Each load or save captures a process-local monotonic admission before asynchronous work. The module-level coordinator serializes settings work across separately built Layers and publishes only admissions newer than the latest successful publication. Failed or interrupted newer work does not suppress an older success. `document-store.ts` always returns a complete save context containing only the baseline and loaded settings. Each atomic `modifyObject` derives known overrides from the locked latest document, applies only caller-edited fields, and preserves unknown root fields. `schema.ts` owns every persisted field decoder, including bundled Shiki themes and the opt-in `toolCallCollapsedStyle`; tolerant field recovery derives from that struct. Collapsed style uses the same defaults, environment mapping, trusted precedence, and persistence path as other fields, with `preview` as its default. `defaults.ts` contains the static settings and performance defaults. `env.ts` owns the single `CODE_PREVIEW_*` environment door: `CodePreviewEnvironmentService` decodes once, exposes only settings defaults, and publishes the synchronous performance/tools projection locally. Settings sources are current-only: nested `codePreview` objects in `$PI_CODING_AGENT_DIR/settings.json` and the trusted project's `.pi/settings.json` form the baseline, and the flat `$PI_CODING_AGENT_DIR/code-previews.json` stores package overrides (unknown root fields preserved). Invalid fields recover independently with bounded path-only diagnostics. Legacy settings formats and locations are ignored.
- `src/settings/` owns host commands (`controller.ts`) and the persistence-aware `/code-preview-settings` controller in `panel.ts`; `config/store.ts` owns abort-aware public loading. Signalled startup loads have independent cancellation ownership and never fall back to a one-shot runtime after abort. No-signal public loads share one admission and in-flight disk operation, then clone the settings object and tools array for each caller. The pre-session compatibility runner only builds and runs a short-lived Layer; the shared settings coordinator provides cross-runtime serialization and permits queued cancellation. A one-shot save rehydrates private state and saves under one coordinator permit without an intermediate publication. After a successful theme save, the panel catches a rejected Shiki initialization Promise locally. That failure cannot enter the persistence rollback or warning path. The host composes its settings tree with `pi-cosmic-ui/manager/settings-surface`; shared category submenus and the Vim adapter provide one search and navigation contract. Pure menus, submenus, and summaries remain under `settings/ui/`. The host threads its callback Theme through nested settings and syntax-theme selectors, using shared manager focus/value callbacks. The health panel uses the same read-only panel chrome; transcript preview styles remain separate.
- `src/syntax/` and `src/write/` are the other primary stateful features. The syntax service exposes only `initialize`; it owns Shiki replacement and finalization while `syntax/ingress.ts` owns the bounded synchronous renderer request bridge and its sole invalidation callback ledger. Duplicate and distinct requests share the same callback retention cap; overflow invalidates immediately without dropping admitted language work. Initialization masks admission through cleanup installation, but restores interruption for creation and duplicate waits. Returning to the installed theme or admitting a different theme settles superseded joiners without restarting the obsolete request. Pure language transitions publish and commit synchronously through `SynchronizedRef.modify`; language loading stays interruptible. Late candidates are disposed without clearing the installed highlighter's caches. The write service exposes only `rememberBeforeWrite`; native write execution owns mutation serialization. Its bounded projection has non-destructive renderer lookup. Shiki render entries belong to one highlighter object and theme pair. Replacement and finalization discard render and ANSI color caches only when releasing their owning highlighter, so stale cleanup cannot clear newer caches. `src/shared/projection-ownership.ts` gives syntax and write projections monotonic session ownership so a newer session wins overlap and stale cleanup cannot clear it.
- `src/diff/`, `src/paths/`, `src/tools/` (including grep/path-list/shell helpers), and `src/warnings/` contain deterministic preview policy and transformation logic. Word-diff matching shares confidence and ambiguity rules through `diff/word/line-pair-scoring.ts`; `sparse-candidates.ts` owns bounded feature evidence, while `sparse-line-matching.ts` selects anchors and positional fallbacks.
- `tools/builtin-issues.ts` projects builtin result limits, secrets, command risks, and write diff guards into `CompactIssue`s, counters, and metadata. Known complete-line read pagination is an `info` issue; unknown truncation, partial lines, and oversized first lines are warnings or decline compaction. Byte-cap hints require an explicit numeric size-limit footer and `lastLinePartial: false`. Reached grep/find/ls caps use the priority counter lane, never inferred totals or continuation promises. Write guards become metadata only from validated owned size evidence or bounded byte/complexity checks with known previous contents. A cooperative consumer may pass the explicit `not-captured` before-write variant; that producer-owned choice yields an `info` issue and does not classify unknown native history. These projections do not change execution results or expanded renderers.
- `src/tools/` owns tool policy, the public cooperative shell API in `cooperative-tools.ts`, `renderer-adapter.ts`, the exported built-in emoji lookup in `presentation.ts`, argument/result helpers, and synchronous renderer factories. It consumes Cosmic UI's semantic status rows but owns preview behavior. The public wrapper and every built-in factory use the same adapter. It creates one shell, copies the source definition once, preserves execution/result options, and calls supplied renderers unbound to match Pi 0.84. A path-list result creates one chunk renderer for the complete output, so collapsed head and tail chunks share the tree-mode decision and directory set across the hidden-lines marker.
- `src/preview/tool-shell.ts` captures background mode and collapsed style at registration. `tools/compact-summary.ts` owns the summary types, `resolveCompactSummary` (Pi error reconciliation; a classified error may be explained by a child row), and `compactStatus`; `tools/compact-presentation.ts` adds the generic fallback for missing summaries. Domain adapters supply semantic summaries and content-only expanded callbacks. Compact expansion composes heading, issues with their details, unique call content, then unique result content; without content hooks the original slots remain with issues between them. Preview style and malformed summaries keep original renderers. `preview/compact-slots.ts` owns separate original and content-only call/result caches and slot-local failure evidence. `preview/compact-details.ts` composes the expanded body. Construction or drawing failures restore safe raw output for that slot only. Drawing failure recomposes from retained bodies without replaying factories. Invalidation and expansion do not retry a failed renderer. Changed host args, content, details, lifecycle flags, or image visibility may; recreated result envelopes and callbacks do not. `compact-shell.ts` retains planning, frame colour by status, timing, and mouse routing. Preview timing wrappers retain producer caches across timing toggles and forward mouse events only to child rows. `tools/data/results.ts` shares attachment-aware raw fallback across both styles; Pi still owns native images. Scoped animation retains its existing owner. `preview/expanded-section.ts` supplies the shared labeled, indented expanded sections.
- `tools/compact-issues.ts` owns the `CompactIssue` shape (`severity`, `code`, `message`, optional `detail`), merging, and severity. `tools/issue-message.ts` owns the shared message helpers for unclassified text: `firstLineMessage`, `failureMessage` (common service and network failures named from the first line), and `isAgentGuidance`. `testing/issue-messages.ts` exports `issueMessageStyleProblems` for producers' style tests, and `testing/gallery.ts` renders registered calls as plain-text frames for `pnpm presentation:gallery`. `preview/compact-issues.ts` renders issue lines (one per issue, own glyph and colour; `info` and `detail` only when expanded) and the primary-issue label used on child rows. `compact-issues-schema.ts` bounds issues that cross package or persistence boundaries.
- The normative [tool presentation standard](../../docs/architecture/tool-presentation.md) records adapter responsibilities and the tool inventory. The source-only `pi-code-previews/testing` export drives real registered render callbacks without a Vitest dependency or tool execution. Its invalidation rebuilds both mounted callbacks with fresh result envelopes, matching Pi. It also owns the consumer-test presentation helpers: pending render contexts, snapshot-and-restore settings overrides, registration capture on core's `extensionApiFixture`, expansion cycles, and the registering-owner animation probe; the harness defaults to core's `plainTheme`.
- `tools/builtin-projection.ts` owns the pure public builtin semantic projector. All settings and before-write evidence are explicit inputs. It never reads the private write registry or executes tools. `builtin-compact-summary.ts` adapts standalone context and published settings; `captureBuiltinCompactPolicy` returns a detached, no-I/O policy snapshot for cooperative consumers. Unknown previous contents remain distinct from a known new file and from a cooperative producer's explicit `not-captured` choice. Compact and detailed write renderers share `isKnownNewWrite`: only an explicit own data property recording an absent file permits a new-file claim. Standalone diff-count caching stays in `builtin-result-detail.ts`, keyed by snapshot identity, contents, and work limits. Transient projection retains no results or raw output. `builtin-failure.ts` composes the pure `builtin-failure-shell.ts` and `builtin-failure-file.ts` classifiers: recognized shell, filesystem, and edit-refusal envelopes get human messages with technical cause and recovery as detail; a shell exit adds the output's first failure line, redacted and bounded, else the meaning of a conventional exit code; anything else uses its first line. `tools/process-failure.ts` owns those two helpers, `outputFailureLine` and `exitStatusMeaning`, which Background Task also uses. `compact-summary-schema.ts` rejects malformed provider evidence before the shell can hide original results. In preview style, `renderers/shared/preview-issues.ts` renders the same issues under each builtin heading: argument-based issues before a result exists, then the cached result projection, with a generic truncation warning when classification declines.
- `src/preview/presentation-policy.ts` exposes a detached, no-I/O snapshot of published timing and collapsed-style settings. Consumers capture style at registration and read live timing when rendering.
- `src/preview/compact-row.ts` exposes shared heading rendering for standalone and nested calls, including sanitization, colours, clipping, counter/metadata priority, timing policy, and an optional issue label that replaces the counter on child rows. Branch indentation reduces the child row's available width; it adds no second heading policy.
- `tools/builtin-subject.ts` owns argument-only builtin targets, shared by standalone summaries and the public `describeBuiltinCompactSubject` helper. It supplies path shortening, read ranges, commands and search targets without inspecting results or write snapshots.
- `src/preview/compact-children.ts` exposes semantic call-tree rendering. Child `status` is the effective display classification; failed delivery must not look successful. The tree selects up to five calls, prioritizing active/problem calls and then recent completions while preserving admission order; each row shows its primary issue inline and the omission row counts hidden failures. Exact provider totals include calls omitted before rendering. The flat layout lists every caller-bounded retained entry with all of its issues and details beneath it; `all` bypasses selection in tree layout. `compact-status.ts` shares header and child status icons; neutral `returned` means delivery without an asserted operation outcome, and `?` marks unconfirmed outcomes. Supplied measured child durations use the shared pure formatter and obey the global `toolCallTiming` gate; the renderer never estimates missing durations.
- `src/preview/compact-header.ts` allocates semantic action and target before one selected counter, metadata, or duration. It preserves whole counter labels and uses grapheme-safe middle elision for long targets. Counter budgets leave a minimum target width, while short or empty targets release unused space. Layout owns no execution state, timers, or argument/result cache.
- `src/commands/health.ts` supplies health projection data to the shared bounded `pi-cosmic-ui/manager/panel`; it retains the plain notification fallback for non-TUI hosts.
- `src/boundary/` wraps Node and Shiki integration plus the one-shot settings runner. Shiki initialization uses `Effect.callback` cleanup for interruption; a highlighter that resolves after cancellation is disposed without resuming the fiber. Synchronous render timing imports `synchronousNow` from `pi-cosmic-core`, while session host capture, trust, and notifications use the shared core boundaries directly.
- `src/preview/` and feature render modules are synchronous UI (no top-level `ui/` folder).
- `src/shared/terminal-text.ts` owns the code-point SGR classifiers (`matchSgrSequence`, `replaceSgrSequences`) used instead of control-character regexes for ANSI parsing.

Issue messages are producer-authored, human-facing, and identical collapsed and expanded; agent procedures, recovery commands, and internal identities live in `detail`, shown only on expansion. `compactSubject` gives compact headings a human-readable alternative to opaque IDs.

## State and resources

Settings, syntax, and before-write correlation are Effect-owned and publish bounded synchronous projections. Deferred and scheduled renderer callbacks are Effect-owned and reached synchronously through the active session capability. Settings state is one save context in a `Ref`; its `loaded` settings publish only after a coordinated load or the atomic rename commit. A stale save exits before `modifyObject`. Global `flush` waits behind settings work from any Layer. Save lock order is coordinator, JSON document lock, then the lock-free `afterCommit` Ref update and conditional publication. Renderer installation status is bounded plain state: pending, installed, disabled, conflict, or registration error. No raw registration error is retained. Write admission captures the originating capability before delegating to Pi 0.86's native write definition. Native execution owns path resolution, the canonical file-mutation queue, parent creation sequencing, abort checks, and success content. `boundary/host-write.ts` adapts its Promise-only `WriteOperations` callbacks to per-invocation scoped Effect workers. The native queue wait stays interruptible; cancellation aborts the native signal so delayed callbacks remain inert, without waiting for the predecessor. Each callback Promise joins its worker without an abort signal, keeping Pi's queue held until admitted filesystem work settles. Parent creation is masked through settlement; cancellation there prevents the subsequent write. Before-state reading runs inside the native queue and remains interruptible. Direct file mutation and correlation commit share one mask, preserving evidence if cancellation arrives after mutation. Invocation scope closure joins admitted workers; session projection ownership rejects retired publications and cleanup clears its own evidence. Both registered and context-free Effect callers enter the native queue, so no outer queue or package-local path lock remains. Correlation entries remain visible for duplicate renders until bounded eviction or scope cleanup. Shiki is the documented synchronous-capability exception. Pure diff and rendering calculations remain synchronous.

## Lifecycle

```text
session_start -> guarded host capture -> application Layer -> settings load -> discover and build replacements
                                                          -> install each planned replacement
                                                          -> session capability -> scoped syntax initialization
write/tool render -> frozen projections + pure rendering
session_shutdown/replacement -> session capability cleared -> runtime resources disposed
```

Installation has a two-phase boundary. Discovery and option resolution build an ordered plan that stores every constructed definition before the first `registerTool` call; it does not retain installer closures. Pre-mutation failures fail startup through the lifecycle boundary. Each attempted name enters the lifecycle-owned tool set immediately before `registerTool`; only successful returns enter the installed set. This distinction handles Pi 0.84 mutating its extension registry before a refresh can throw. A visible nonbuiltin tool in the owned set remains retryable on a later start. Registration failures record a bounded status, later tools continue, and installed replacements keep the runtime live.
