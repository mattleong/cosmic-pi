# Herdr topology and ownership

Part of the [pi-subagents](../README.md) architecture documentation. See [ARCHITECTURE.md](../ARCHITECTURE.md) for the package overview, complete source map, and cross-cutting invariants.

## Herdr session ownership and retained reports

The Herdr CLI boundary never accepts a session selector and never emits `--session`: composition captures one bounded immutable ambient environment and supplies it to both CLI and harness services before each applies its narrower allowlist. Herdr 0.8 candidates require the parent's inherited `HERDR_SOCKET_PATH`; that exact captured socket is preserved through the sterile harness so native lifecycle hooks cannot silently report to a different/default server. Custom Pi/Claude/Codex config-home selectors are captured and preserved consistently. Later `process.env` or source-object mutation cannot redirect commands, probes, auth selection, or topology. The protocol-19 bundled schema and selected live snapshot, integration status, native executable/auth evidence, model/effort/context/write policy, exact 8/7/7 marker-validated integration files, Codex auth, and packaged Pi bridge files are checked without topology. Protocol or readiness failure is a typed candidate skip unless cleanup/outcome uncertainty makes fallback unsafe.

The host lazily creates one no-focus workspace/root tab for the parent session/cwd. Every readiness poll and every focus, activation, environment, secret, or start mutation revalidates the unique workspace/tab/pane/terminal tuple; process inspection is bracketed by those snapshots, and mismatched occupancy fails closed. It focuses the owned tab only while focus still matches launch evidence and causally confirms a harmless random marker; because Herdr 0.8 can drop the first accepted input in a never-focused workspace after session restore, one distinct harmless probe may be retried after refocusing. It restores the caller's prior tab only while its original tab/workspace/label tuple still exists and the owned tab still holds focus, never following ID reuse or overriding newer user focus after rollback or closure. It never attaches to retired standalone-extension state or a native restored run. Workspace/tab labels plus opaque IDs and every run's pane, terminal, runtime kind, generated agent name, canonical cwd evidence, and the full available native `agent_session` tuple (`source`, `agent`, `kind`, `value`) are exact ownership evidence. Generated names obey Herdr 0.8's 32-character lowercase grammar and combine a readable run prefix with a bounded digest of parent/run identity. Protocol 19 exposes no launch token that can bind later `agent_session` evidence to the original `agent start`; startup therefore requires that full tuple atomically in the start response. Missing session identity quarantines the provisional occupant rather than polling/adopting a possible replacement. One comparator is used by prompt, inspect, rollback, and close. A provisional occupant without complete evidence is never closed. Launch, prompt, stop, report-close, and finalization re-snapshot and revalidate; every observed provisional mismatch source (returned topology, process info, snapshots, start evidence, or pre-focus commit validation) is sticky across later ABA-looking snapshots. Committed runs likewise enter permanent quarantine after ownership mismatch or cleanup uncertainty, so automatic finalizers never retry an uncertain mutation. The final owned run closes the complete workspace only when it contains exactly the expected tab/panes/agents; otherwise only an exact owned pane closes. Cleanup confirmation and harness authorization require absence of every owned workspace/tab/pane/terminal/agent-name selector, including reparented survivors. Focus restoration uses that same non-stealing owned-tab predicate.

Before spending an activation probe, the host polls Herdr's read-only process/snapshot APIs until the new pane first reaches an available, unoccupied interactive shell; this avoids sending both bounded probes into a transient stale native TUI restored by the server. The environment marker precedes its final shell `exec`, so a queued harmless command must execute in the replacement shell before private secret input; the same causal input proof follows secret attestation, with process/snapshot checks before the single `agent start`. Neither mutation relies on marker output alone or runs while a prior command owns the pane. A bounded readiness miss rolls back exact provisional topology without retrying a mutation, and Herdr's confirmed pre-application `agent_pane_busy` rejection remains safe to roll back.

All three drivers prepare a monotonic assignment epoch through `SupervisorChannel` before `agent prompt`. Herdr 0.8's successful prompt response proves only ownership-checked text queueing plus delayed-Enter scheduling, so successful and outcome-uncertain dispatches enter the same bounded reconciliation. A causal accepted report for that epoch or a post-response lifecycle/state change emits `run_started`; absent evidence fails closed with `herdr_prompt_outcome_uncertain`. Accepted reports are buffered safely before `run_started`, but generic supervisor contacts are not claimed as start evidence. Launch first waits for causal sterile-environment and atomic secret markers, then requires exact native `agent_session` identity in the Herdr start result because delayed evidence cannot be tied safely to that launch. Missing-report polling begins only after confirmed start. Missing/dead/mismatched agents fail, and idle/done without causal accepted-report evidence fails after a short bounded reconciliation grace. Sustained `unknown` agent status after a confirmed start and without an accepted report likewise fails closed after its own bounded grace; accepted-report ownership is checked first so later status-only `unknown`/`idle`/`done` observations cannot overwrite a retained successful report, and a transient unknown blip recovers without erasing accumulated missing-report evidence. Supervisor report, not PTY text or native status, owns completion. For Herdr Pi only, the private bridge recognizes the fixed leading epoch marker at both input and agent-start boundaries, so a retained active-loop steer cannot inherit prior accepted state. The first possibly delivered explicit identity is immutable for that epoch; only a successful final stop may retry it or turn final Pi text into the same authenticated report event. Aborted/error turns and shutdown remain non-completion. Herdr capabilities are exactly `parent-contact`; steer/interrupt/resume/rename/live-read are omitted because protocol 19 does not confirm application outcomes safely for this ownership model.

`closeOnReport:true` closes the exact pane/workspace and private harness after the report. `closeOnReport:false` is read-only only: the service enters `reported`, retains topology/channel/harness, and `subagent_send` from that state uses `controls.start` with a new epoch and report generation without requiring the active-turn `steer` capability. Retained Pi runs can use Bash under the same no-mutation behavioral contract and still acquire no writer lease; Claude/Codex keep their read-only sandbox. Parent replacement/shutdown always closes retained topology. Writers always close, and writer lease `spawn-started` is committed before any harness/topology/process start.

Claude receives read-only inspection Bash through its mandatory sandbox, empty normal setting sources, `--no-session-persistence`, disabled nonessential traffic in generated settings, strict supervisor MCP, one marker-validated Herdr hook, the hardened local strict sandbox/scoped Edit policy, and fixed delegation/integration denials. Its writer cwd must be representable by the shared comma-delimited allowed-tool/scoped-Edit grammar during topology-free preflight. This disables resumable delegated-session transcript/history and the package creates no project report/history file. The exact limit is that inherited authenticated Claude may still maintain implementation-defined account/cache/diagnostic or provider-side records outside the project; the harness is not a zero-retention or offline boundary. Codex gets an isolated private `CODEX_HOME`, bounded auth copy or API-key loaded through a private script path, approval never, read-only/workspace-write sandbox, strict supervisor-only config, and disabled apps/plugins/multi-agent/web/network extras. Pi gets a fresh private session directory, explicit model/thinking, sterile child marker/environment, no discovered resources/context, Bash-enabled read-only inspection or writer tools, an orchestration denylist, the lifecycle integration, and one packaged bridge extension. Its private policy is appended to Pi's default coding prompt rather than replacing it. Pi Bash is not filesystem-sandboxed. Environment-sourced Pi model keys cross only through its 0600 private bootstrap script and are consumed/deleted from the delegated process environment by the bridge. Bridge tools are registered with `withCodePreviewShell`; its client multiplexes bounded correlated helper calls so a blocking question cannot block unrelated progress/report calls, and its per-assignment settled-response fallback cannot duplicate an explicitly accepted report.

## Module responsibilities

- `src/backend/herdr.ts` owns the shared Herdr Pi/Claude/Codex driver and report reconciliation.
- `src/backend/herdr-assignment.ts`, `herdr-ownership.ts`, and `herdr-shell-readiness.ts` own pure epoch, identity, and shell-readiness policy.
- `src/boundary/herdr-environment.ts`, `herdr-cli.ts`, `herdr-harness.ts`, `herdr-launch-safety.ts`, and `herdr-host.ts` own inherited environment, protocol I/O, private harnesses, safe launch mutation, and exact session topology.
- `src/boundary/host-pi-supervisor-extension.ts` and `pi-supervisor-bridge-client.ts` are the sole delegated-Pi supervisor bridge.

Backend-neutral report claims and notification delivery are documented in [Completion and delivery](completion-delivery.md).
