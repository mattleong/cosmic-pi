# Architecture

`pi-subagents` is an Effect-managed extension for session-scoped, profile-routed subagents. The current Phase One slices implement configuration/profile/public-start routing plus a capability-oriented backend seam while preserving the existing local Pi behavior.

## Version-4 routing domain

A normalized candidate has `host`, `runtime`, `model`, `effort`, `context`, `writeIntent`, `fastMode`, and `closeOnReport`. Routes are disabled, one candidate, or ordered candidates. Configuration has no denied/discouraged policy, execution, lifetime, or generic tool-policy fields.

All six `local|herdr` × `pi|claude|codex` combinations are syntactically representable. Cross-field decoding rejects:

- fork outside local Pi;
- parent-model selection outside local Pi;
- `closeOnReport: false` outside Herdr read-only candidates;
- fast mode outside supported Pi OpenAI routes or Codex's priority-tier-capable native path;
- unknown candidate keys, runtime-incompatible effort levels, or malformed native selectors (Pi registry IDs may use bounded `@` context variants such as `cursor/gpt-5.5@1m`; Claude's exact numeric long-context suffixes such as `[1m]` are supported without admitting general glob syntax).

A present-invalid route fails closed. Missing trusted-project routes inherit global routes; missing global routes use built-ins. A complete in-memory session route overlays that loaded persistent result and records source `session`; removing it reveals the exact activation-time base again. Every built-in is an explicit local Pi parent candidate using profile context, write-intent, and effort defaults with `fastMode: false` and `closeOnReport: true`. Omitted launch profiles always resolve to `generalist`; deprecated `defaultProfile` fields are ignored and removed on the next settings write, while `delegate` route/tool inputs decode only as a temporary compatibility alias.

Version 3 fails activation with an actionable migration diagnostic. Its removed policy fields are not decoded or silently discarded.

## Candidate planning and host resolution

Pure planning preserves declared order and resolves Pi model catalog/auth compatibility for local and Herdr Pi. Because sterile Herdr Pi disables extension discovery, the host boundary reads Pi's registered-provider provenance before model resolution and rejects every extension-registered provider before auth lookup or service ownership; provenance failure also fails closed. This provider-granular rule deliberately rejects a built-in provider while any extension overrides it, preventing credentials intended for extension routing from falling back to the built-in endpoint. Runtime credentials and environment-sourced Herdr-Pi API keys are resolved before service ownership and transferred only through the private ephemeral bootstrap; absent or malformed transferable credentials produce a typed candidate skip. The host boundary records dynamic typed skips in launch provenance. Host resolution continues to the next candidate only before service ownership begins.

All six adapters are implemented. The shared registry resolves host/runtime/context and performs bounded executable/auth/model-effort/write-policy/integration/harness readiness before a run scope, writer lease, supervisor channel, topology, or backend process is owned. Once `SubagentService.start` begins, lease marking, topology mutation, spawn, transport uncertainty, or control errors never trigger candidate fallthrough.

Selected host, runtime, route source, `fastMode`, and `closeOnReport` are retained in selection provenance, the internal start request, the run view, status output, and card details. Each public start batch captures one immutable profile snapshot before resolving its agents, so concurrent session edits cannot split a batch across route revisions. Pre-v4 persisted cards remain tolerantly renderable.

## Public launch contract

`subagent_start` accepts one required array of 1–12 agents. Each item contains only:

- required `task`;
- optional `profile`;
- optional `name`.

The TypeBox object is strict. Friendly validation and host resolution also reject legacy `execution`, `context`, `writeIntent`, `effort`, `backend`, and `model` fields with `[legacy_launch_override]` guidance.

Start is always background and nonblocking. The public tool executes all admitted batch items without waiting. Existing service foreground fields remain dormant staging compatibility only; no public path sets them. `subagent_await` retains the existing `all_finished` and `any_finished` semantics.

Main-agent prompt metadata follows a read-only-first adoption policy: before substantial work, check for at least two independent workstreams; launch one to three bounded read-only assignments early; skip delegation for trivial or tightly serial work; continue independent parent work after launch; and await only at a dependency or final-synthesis barrier because unclaimed completion reports are delivered automatically. Worker launches remain explicit implementation handoffs: the prompt requires the main agent not to edit and preserves the one-shared-cwd-writer rule.

`subagent_models` projects all complete v4 candidates as statically eligible when their adapter/context contract matches; dynamic executable/auth/integration/harness readiness remains launch-time.

## Local Pi ownership and safety

Local Pi children run in RPC mode over stdin/stdout with bounded/schema-decoded frames. A separate bounded Node IPC channel carries parent contact and peer notices. `backend/local-pi.ts` owns command-checked RPC correlation and emits normalized backend events through a bounded, backpressured queue; raw byte-budget ownership is acknowledged only after run orchestration consumes each normalized event. Run orchestration supplies every assignment-start control with a monotonic assignment epoch, and the adapter tags assignment-scoped normalized events with the active epoch. Definite start failure restores the adapter's prior epoch; outcome-uncertain failure retains the attempted epoch. Run orchestration does not construct or decode Pi RPC commands. Backend continuation state is an opaque token to orchestration; only the local Pi adapter translates its token into a Pi session-file launch argument, while `view.sessionFile` remains status metadata. Fresh children use a dedicated session directory; forked children receive a private copy of the stable parent branch. Runtime API keys cross through an ephemeral environment bootstrap rather than argv.

Writer children inherit active parent tools except recursive subagent and legacy Herdr orchestration tools. Read-only children receive only the conservative inspection allowlist. This is a capability restriction, not an OS sandbox or confidentiality guarantee.

`SubagentService` owns the run registry, backend scopes, and parent-owned writer leases. It resolves `realpath` for launch and diagnostics, but both the fast in-memory guard and disk slot are keyed by a bounded SHA-256 digest of the directory's stable local filesystem identity (`stat` device plus inode/file ID). Relative and symlink aliases collide, and renaming the directory does not change writer ownership. Before any backend driver spawn call, every writer must acquire and then durably mark the package-owned cross-process lease. The process-lifecycle seam invokes this preparation on initial start and every respawn. Read-only runs never canonicalize for or acquire this lease, and retained writers remain invalid.

The protocol-v2 slot is `<agent-dir>/subagents/writer-leases-v2/<sha256(device+inode)>.lease`; neither its bounded filename nor evidence exposes the cwd path or unhashed filesystem identity. Exclusive directory creation plus synced, bounded Effect Schema-decoded evidence establishes a `reserved` lease. Evidence contains its phase, an unguessable ownership token, filesystem-identity digest, parent PID, approximate parent-process start time, an unguessable owner/session nonce, parent session/run identity, and timestamps. `markSpawnStarted` token-checks the stable reservation, atomically replaces it with synced `spawn-started` evidence, confirms the same directory object and token, and only then permits the driver call. Failure or ambiguity forbids spawn. Transition artifacts, permission failures, malformed data, changing data, and every other uncertain observation remain locked.

Only an `ESRCH` parent-liveness result may enter orphan handling, and even then only stably decoded `reserved` evidence can be reclaimed. A dead `spawn-started` lease is never automatically reclaimed: detached local process groups and Herdr PTYs may survive their parent. Such a slot requires manual private-state recovery only after an operator independently verifies that the external backend and descendants are dead. Corrupt, transitional, and uncertain dead-owner evidence has the same fail-closed/manual-recovery requirement.

Dead-reservation takeover and normal release use the same deterministic, non-empty destination derived only from the old ownership token. Takeover atomically renames there, token-checks the moved evidence, and then contenders race through the exclusive creation primitive. Release prechecks the token, atomically renames the complete lease directory to that same old-token tombstone, and token-checks moved evidence; it never uses read-then-unlink/rmdir. The shared enduring destination prevents duplicate or delayed release **and** takeover operations from renaming a replacement lease across either kind of ABA cycle. Tombstones are private, each contains at most the bounded lease evidence, and retained history grows linearly with successfully released or reclaimed ownership tokens. They are not garbage-collected automatically because this protocol has no proof that an old delayed operation can no longer execute.

PID reuse cannot be eliminated portably with `kill(pid, 0)`. A reused/live PID therefore conflicts conservatively even if start/session evidence differs; process-start estimates and nonces strengthen diagnostics but never declare death. Coordination assumes same-host parent Pi processes use the same private agent directory on a local filesystem with stable device/inode identity and atomic directory create/rename semantics. Distinct agent homes and remote/distributed filesystems are outside this protocol. Windows writer admission fails with typed `unsupported_safe_writer_ownership` before canonicalization, lease acquisition, or spawn because leader exit plus `taskkill` cannot prove descendant termination; read-only runs remain allowed pending a native Job Object owner.

Backend scopes are service-owned and explicitly closed before lease release is authorized. If backend cleanup fails, release is never authorized. If token-checked tombstone release cannot be confirmed, session quarantine retains process capacity and writer ownership. An explicit `pending`/`running`/`settled` lease-preparation state lets shutdown settle an operation that never began while waiting for an uninterruptible ownership transition already in progress. Session shutdown applies backend-then-lease ordering to every owned run.

The supervisor channel is composed once with the shared backend registry. Local and Herdr Claude/Codex acquire one channel inside each backend scope; Herdr Pi loads the packaged private bridge/client against the same channel. Local Pi retains its existing RPC/IPC parent-contact transport.

Local Pi keeps its original completion transport: the last assistant response is captured from the existing RPC stream and `agent_settled` completes the assignment. Local Claude/Codex completion is owned exclusively by a supervisor MCP report; raw final CLI text and normal native turn/result completion do not settle the assignment. SupervisorChannel records exact accepted-report epoch evidence before acknowledging the MCP call. Claude successful assignment results and Codex normal `turn/completed` both query that exact epoch evidence directly, independent of adapter queue scheduling, so an accepted report wins behind progress/backpressure and a missing or wrong-epoch report fails immediately by protocol causality rather than hanging or using a scheduling sleep. If native transport closes before the supervisor-event forwarding fiber drains, the adapter reprojects that exact accepted evidence into its backend queue before ending it. Claude's epoch-zero native initialization result remains non-assignment evidence. Claude and Codex interruption retain their separate correlated native lifecycles and emit no completion-shaped run event. Every local candidate has `closeOnReport: true`, so accepted report completion closes process and channel scope immediately while retaining bounded projection data. No report or harness artifact is written into the project.

The backend-neutral report event is bounded and correlated by run plus assignment epoch. An adapter supplies a positive monotonic per-run sequence, a bounded retry identity (`deliveryId`), and optional opaque ownership evidence. Phase, epoch, sequence, and delivery identity are validated in one serialized commit; the watermark advances only with a committed report. Exact `(sequence, deliveryId)` retries are idempotent. Higher reports while idle are rejected without advancing the watermark, so a valid later assignment can reuse that unpoisoned delivery. Future adapters decode their foreign protocol before emitting this event.

One scoped `SupervisorChannel` binds only IPv4 loopback on an ephemeral TCP port and writes one 0600 connection document below a unique 0700 run directory in private agent state. A 256-bit token authenticates the connection and every bidirectional message with constant-time comparison; peers are loopback-checked, inputs are strict schema decodes, and sockets, lines, queues, maps, calls, strings, and writes are bounded. The metadata contains only the fixed packaged helper command, private config path, and Claude JSON/Codex TOML MCP fragments—no public profile fields, arbitrary command, user configuration, credentials, or environment.

Local Claude starts only `claude --print --input-format stream-json --output-format stream-json --verbose` with partial/replayed messages, an empty fixed settings-source list, strict MCP, explicit model/effort, no session persistence, and no slash commands or plugin arguments. Every launch requires current strict sandbox settings: enabled, failure when unavailable, no unsandboxed command fallback, strict empty network allowlist, and assigned-cwd filesystem write policy. Read-only excludes shell and mutation tools. Writers expose Bash through sandbox-only auto-allow and Edit through one canonical-cwd-scoped permission rule; Write and NotebookEdit remain unavailable, and bare Bash/Edit/Write are never permission grants. Unsupported writer path/platform policy fails typed preflight. The subprocess sandbox directly confines Bash; Edit remains the current CLI's path/symlink-enforced file-tool permission policy rather than an OS sandbox, and Web/model traffic is not an offline/confidentiality boundary.

Claude startup sends the official initialize control, then one `shouldQuery:false` input to obtain native `system/init` without inference. It validates cwd, native session, selected/resolved model, MCP config errors, and a connected `pi_subagents_supervisor` inventory containing all four mandatory tools before returning startup state. Stream-input acknowledgement requires a native replay from the active session; uncertain delivery closes the backend before returning the error so a delayed same-text replay cannot confirm a later retry. Initialization failure is post-spawn and never candidate fallback. Initial tasks/live guidance wait for exact native replay. Interrupt sends `cancel_queued:true` and remains correlated to its assignment until the control response, exact replayed marker, and exact `error_during_execution`/`aborted_streaming` result all arrive in either order; only that lifecycle is suppressed, while genuine result failures remain fatal.

Local Codex starts only `codex app-server --stdio --strict-config` against an isolated 0700 `CODEX_HOME`. Fast candidates enable only the isolated harness's `fast_mode` feature and send `serviceTier: "priority"` on both `thread/start` and `turn/start`; initialization fails closed unless `thread/start` confirms that tier. The boundary copies only a bounded, recursively validated `auth.json` from a safe custom source `CODEX_HOME` or the default source to 0600 private state, without passing the source path to the child or its auth-status probe; otherwise it permits the fixed `OPENAI_API_KEY` fallback. Harness creation is failure-atomic after its unique private directory exists, and unconfirmable partial cleanup returns `harness_cleanup_unconfirmed` while preserving private fail-closed state. No other credential/environment keys cross. Generated config includes only the private supervisor MCP server and disables apps, plugins, hooks, skills discovery, memories, multi-agent, browser/computer/image, web-search, network, and related extras. The accepted 0.145 generated v2 subset is `initialize`, `thread/start`, `turn/start`, `turn/steer`, `turn/interrupt`, their correlated responses, and bounded relevant turn/item/usage/warning notifications. Warning `{message}` is decoded separately from `configWarning`/`deprecationNotice` `{summary,details,...}`. Approval is `never`; native sandbox policy is read-only or workspace-write with network disabled. Server-initiated approval or other requests are protocol violations. Static current Codex effort policy permits only minimal/low/medium/high/xhigh/max because the generated effort schema itself is open string.

Assignment epochs are prepared monotonically before task issue, advance only after at least one current live authenticated helper acknowledges them, and become unready on disconnect until a new peer handshakes. Helper calls capture the observed epoch, so delayed prior-assignment events retain their old epoch. Progress and warning/question calls normalize to existing `supervisor_contact` events; the channel assigns report sequence and current captured epoch before emitting existing `BackendReport` data. Report `deliveryId` retries with identical text return the original sequence without a second event, while conflicting reuse fails. Only one question may be used per assignment and only one may block per run at a time; parent reply, MCP cancellation, socket loss, adapter cancellation, and scope close settle the exact owned correlation. Exact MCP caller cancellation emits a bounded epoch/request-correlated event so orchestration clears `waiting_for_parent` instead of retaining a dead question.

The standalone helper exposes only `supervisor_progress`, `supervisor_warning`, `supervisor_question`, and `supervisor_submit_report`. It dispatches up to 16 calls concurrently, so a blocked question does not block ping, progress, reports, cancellation, or unrelated responses; stdout and channel writes are serialized. It never silently retries an uncertain send. Parent death closes TCP and fails pending calls. Graceful scope release closes the listener and peers, ends the event queue, and removes only the bounded state owned by that run.

Every assignment has a monotonic never-reused epoch and a `preparing`/`issuing`/`running`/`reported` phase. Assignment-scoped events from older epochs, plus activity/tool/progress/question events while idle `reported`, are ignored; handle-scoped lifecycle warnings remain visible. A report received while `controls.start` is in flight is held in one bounded slot and committed only after start confirmation (or correlated `run_started` evidence following an outcome-uncertain result). Definite retained-start failure restores the prior immutable view, settlement, report/warning fields, active tools, and assignment state under the matching attempt token. Outcome uncertainty keeps the new assignment and warning. Start confirmation never overwrites an already committed fast report.

A `closeOnReport: false` run transitions from working to nonterminal `reported`, increments `reportGeneration`, retains its backend handle/PID, and counts as finished for the current `all_finished`/`any_finished` assignment. Guidance from `reported` uses the backend's assignment-start control on the same handle, clears the displayed prior report, and makes await target the next generation. Stop and session shutdown still close the scope. Service validation independently rejects retained writers and non-Herdr retained launches.

Session shutdown/replacement/tree navigation/reload closes all local children and exact session-owned Herdr topology, then tombstones safely releasable writer leases. A graceful shutdown is not crash recovery: parent death after `spawn-started` intentionally leaves a manual-recovery lock even after a surviving backend later exits. Leasing is owned above the six-driver registry, so every writer shares the same protocol without adapter-specific locking.

## Herdr session ownership and retained reports

The Herdr CLI boundary never accepts a session selector and never emits `--session`: composition captures one bounded immutable ambient environment and supplies it to both CLI and harness services before each applies its narrower allowlist. Herdr 0.8 candidates require the parent's inherited `HERDR_SOCKET_PATH`; that exact captured socket is preserved through the sterile harness so native lifecycle hooks cannot silently report to a different/default server. Custom Pi/Claude/Codex config-home selectors are captured and preserved consistently. Later `process.env` or source-object mutation cannot redirect commands, probes, auth selection, or topology. The protocol-19 bundled schema and selected live snapshot, integration status, native executable/auth evidence, model/effort/context/write policy, exact 8/7/7 marker-validated integration files, Codex auth, and packaged Pi bridge files are checked without topology. Protocol or readiness failure is a typed candidate skip unless cleanup/outcome uncertainty makes fallback unsafe.

The host lazily creates one no-focus workspace/root tab for the parent session/cwd. It never attaches to retired standalone-extension state or a native restored run. Workspace/tab labels plus opaque IDs and every run's pane, terminal, runtime kind, generated agent name, canonical cwd evidence, and the full available native `agent_session` tuple (`source`, `agent`, `kind`, `value`) are exact ownership evidence. Generated names obey Herdr 0.8's 32-character lowercase grammar and combine a readable run prefix with a bounded digest of parent/run identity. Protocol 19 exposes no launch token that can bind later `agent_session` evidence to the original `agent start`; startup therefore requires that full tuple atomically in the start response. Missing session identity quarantines the provisional occupant rather than polling/adopting a possible replacement. One comparator is used by prompt, inspect, rollback, and close. A provisional occupant without complete evidence is never closed. Launch, prompt, stop, report-close, and finalization re-snapshot and revalidate; a mismatch closes nothing and causes typed fail-closed cleanup quarantine. The final owned run closes the complete workspace only when it contains exactly the expected tab/panes/agents; otherwise only an exact owned pane closes. Prior user tab focus is restored when an automatic operation changed it.

All three drivers prepare a monotonic assignment epoch through `SupervisorChannel` before `agent prompt`. Herdr 0.8's successful prompt response proves only ownership-checked text queueing plus delayed-Enter scheduling, so successful and outcome-uncertain dispatches enter the same bounded reconciliation. A causal accepted report for that epoch or a post-response lifecycle/state change emits `run_started`; absent evidence fails closed with `herdr_prompt_outcome_uncertain`. Accepted reports are buffered safely before `run_started`, but generic supervisor contacts are not claimed as start evidence. Launch first waits for causal sterile-environment and atomic secret markers, then requires exact native `agent_session` identity in the Herdr start result because delayed evidence cannot be tied safely to that launch. Missing-report polling begins only after confirmed start. Missing/dead/mismatched agents fail, and idle/done without causal accepted-report evidence fails after a short bounded reconciliation grace. Supervisor report, not PTY text or native status, owns completion. Herdr capabilities are exactly `parent-contact`; steer/interrupt/resume/rename/live-read are omitted because protocol 19 does not confirm application outcomes safely for this ownership model.

`closeOnReport:true` closes the exact pane/workspace and private harness after the report. `closeOnReport:false` is read-only only: the service enters `reported`, retains topology/channel/harness, and `subagent_send` from that state uses `controls.start` with a new epoch and report generation without requiring the active-turn `steer` capability. Parent replacement/shutdown always closes retained topology. Writers always close, and writer lease `spawn-started` is committed before any harness/topology/process start.

Claude receives empty normal setting sources, `--no-session-persistence`, disabled nonessential traffic in generated settings, strict supervisor MCP, one marker-validated Herdr hook, the hardened local strict sandbox/scoped Edit policy, and fixed delegation/integration denials. Its writer cwd must be representable by the shared comma-delimited allowed-tool/scoped-Edit grammar during topology-free preflight. This disables resumable delegated-session transcript/history and the package creates no project report/history file. The exact limit is that inherited authenticated Claude may still maintain implementation-defined account/cache/diagnostic or provider-side records outside the project; the harness is not a zero-retention or offline boundary. Codex gets an isolated private `CODEX_HOME`, bounded auth copy or API-key loaded through a private script path, approval never, read-only/workspace-write sandbox, strict supervisor-only config, and disabled apps/plugins/multi-agent/web/network extras. Pi gets a fresh private session directory, explicit model/thinking, sterile child marker/environment, no discovered resources/context, fixed tool policy and orchestration denylist, the lifecycle integration, and one packaged bridge extension. Environment-sourced Pi model keys cross only through its 0600 private bootstrap script and are consumed/deleted from the delegated process environment by the bridge. Bridge tools are registered with `withCodePreviewShell`; its client multiplexes bounded correlated helper calls so a blocking question cannot block unrelated progress/report calls.

## Settings safety

`/subagents profiles` is a full-screen responsive Profiles → Route → Candidate workspace that presents every profile's active resolved route and source while editing Session, Global, or trusted-Project declarations. A single `s Scope` control cycles `Session → Global → Project` when trusted and `Session ↔ Global` otherwise, while the workspace explains `Session > Project > Global > Built-in` precedence. Session routes are complete copy-on-write overlays of the activation-time effective route, apply immediately to new launches, and visibly shadow persistent edits; global editing still warns when a project declaration wins. Profile search, visible currently-applicable route actions, breadcrumbs, configured-keybinding labels, decoded Kitty printable shortcuts, and consistent Enter-forward/Escape-back navigation avoid hidden nested menus. ## Projection and delivery

UI and tool renderers consume immutable projections. All public tool calls use bounded user-facing action summaries; non-start/await results persist bounded semantic profile routes, run cards, and per-target failures instead of reparsing prose. Cards expose run identity, profile/host/runtime/model route (using compact `model:effort ⚡` notation for fast models), write intent, retention, bounded timing/activity, humanized aggregate usage, state-aware recovery, and expanded provenance/capabilities. `subagent_models` renders effective source, defaults, candidate eligibility, and the explicit launch-check boundary. Start/await card details are versioned, deeply frozen, bounded, include only the latest report generation, and preserve explicit truncation/omission evidence when reports cannot fit. Collapsed results preview bounded first report lines; expanded cards wrap diagnostics and render a preserved report and error independently, while no-report completion and recovered omitted output are explicit. Progressive batch starts remain input-ordered, render pending/started/failed slots, count pending/failing launches, and animate active rows. `reported` is rendered as an idle retained resource with explicit next-assignment guidance, rename, and stop controls rather than as a dead process. Interrupt-capable backends that do not advertise resume remain stoppable and present stop/replacement recovery instead of suggesting an unsupported resume. The fleet keeps message/resume/rename input and action errors inside its full-screen overlay, consumes stop confirmation modally, and uses capability-aware actions.

Each accepted report creates one internal unresolved generation record. `completionClaims` maps each generation to one exclusive opaque owner token, never a refcount. Await atomically claims the current generation when already reported/completed or the next generation while working; a second await fails with typed `completion_claim_conflict`. Competing status observes bounded metadata with report text/assistant transcript redacted and receives no receipt. A receipt carries the owner token, and consumption succeeds only while that exact token still owns the generation. Cancellation releases only its matching token and requeues notification; complete rendering consumes before the scope release. The notifier serializes its own delivery ownership against claim acquisition and acknowledges `(runId, generation)` exactly once.

Resolved generation records are removed, while the immutable public projection retains only the latest bounded report for human UI. A retained run admits at most 64 unresolved generations; guidance fails with typed `report_delivery_backlog` beyond that bound. Total run history never exceeds 50 records: start admission first evicts the oldest terminal record with no unresolved/claimed report, process, or cleanup ownership, and otherwise fails with typed `history_outbox_capacity`. Thus total report/outbox memory is bounded by 50 × 64 plus the already bounded notification/event queues. Questions and warnings continue through their independent generation-aware slots.
