# Architecture

`pi-ask-user` is an Effect-managed Pi extension for structured user decisions.

## Source ownership

- `src/extension.ts` is the thin Pi registration entrypoint.
- `src/application.ts` owns the core session-runtime slot, trusted preview bootstrap, current-generation admission, deferred tool registration, `/ask-user`, and lifecycle/context handlers.
- `src/layer.ts` composes the current host callbacks into `AskUserService`. No host service or package-local runtime is added.
- `src/questionnaire/service.ts` validates blocking and authenticated owned calls. `queue.ts` owns one bounded FIFO shared with `async-service.ts`, which owns async request state, opening/completion/cancellation Deferreds, waiter ownership, retention, and presenter/delivery fibers. `async-model.ts` holds the public snapshots; `format.ts` formats answer and control text.
- `src/questionnaire/schema.ts` owns Pi TypeBox schemas and request types. Semantic validation and the pure reducer retain their existing roles. Drafts contain selected values or custom text plus an optional note, not copied keys or labels. One finalizer combines the question and draft into a public answer. Cancellation never returns drafts.
- `src/boundary/host-dialogs.ts` adapts abort-aware RPC answer, note, and final review calls. `host-tui.ts` owns the custom prompt, mount acknowledgement, synchronous callback revocation, and joins for admitted external-editor cleanup. Cosmic UI's `boundary/host-input-dock` draws questionnaires and local-extension forms in uniquely keyed above-editor widgets. An empty custom overlay retains keyboard focus and prompt lifecycle without painting over the editor or footer. The presenter owns widget removal on settlement, interruption, and mount failure. `host-ui.ts` retains only token-checked resume capabilities, mounted visibility, and fallback status, with no raw terminal listener. `host-activity.ts` publishes bounded question summaries from service and mounted-dialog transitions. Cosmic UI availability suppresses the fallback status; answering never depends on opening the activity manager.
- `src/boundary/host-delivery.ts` appends versioned branch receipts before calling the public custom-message sender, creates runtime generation IDs, reads active-branch receipt evidence, and checks bounded message metadata for context filtering.
- `src/boundary/host-prompt.ts` tracks Pi's coalesced public prompt lifecycle and this package's custom-call ownership. The application checks admission; the TUI boundary checks again immediately before mounting.
- `src/boundary/host-external-editor.ts` owns Pi settings, temporary files, and the inherited-terminal child process. Its named Promise boundary provides scoped file/process resources, requests termination on cancellation, removes owned files, and restarts the TUI. Trusted editor configuration and generated filenames are passed separately.
- `src/questionnaire/protocol.ts`, re-exported by `pi-ask-user/protocol`, defines plain root/child capabilities and bounded decoders. `host-proxy.ts` publishes the current root capability; `host-relay.ts` resolves the child relay at blocking-tool execution. The authenticated coordinator alone supplies run, assignment, and request ownership. Owned answers return only to the proxy caller, never through automatic root steering. A fixed Pi child marker requires the relay and forbids fallback RPC dialogs and child async registration, but does not authenticate ownership. The root capability retains at most 16 live owner tuples and rejects duplicate active identities. `cancel(owner)` aborts the exact captured root call synchronously and acknowledges only after its actual runtime Promise, including overlay/editor finalizers, settles. It does not wait on a foreign answer Promise. Revocation aborts owned calls before disposal; captured old cancellation handles can join only their own generation.
- `src/tools/` owns blocking and async definitions and Promise-shaped domain callbacks. All questionnaire tools, including async control, use the cooperative `pi-code-previews` shell.
- `src/ui/` owns synchronous presentation, input routing, previews, and pure layout. Questionnaires and local-extension forms use the full widget width and cap their height at 60% of terminal rows, leaving room for the input dock. Pi owns final allocation, so unusually crowded or tiny terminals can still clip widgets. Short dialogs keep natural height; `ui/viewport.ts` bounds long content, follows selection and editor cursor, and pages complete prompts, previews, and review text. Page, half-page, and first/last navigation stay outside Editor input. Resizing and hide/resume retain drafts and focus. `q` never cancels the questionnaire.
- `tests/` protects questionnaire semantics, serialization, lifecycle, ownership races, host boundaries, defensive replay rendering, and public dialog behavior.

## Local-extension forms

`questionnaire/form-protocol.ts`, also exported by `pi-ask-user/protocol`, defines the separate `OwnedFormCapability` and `ExtensionFormOwner`. `host-form-proxy.ts` publishes it only for the current local TUI/RPC generation, with at most 16 live exact-owner calls. It revokes admission synchronously and joins captured presentation cleanup on cancellation. This API does not impersonate child runs, replace the authenticated relay, register a tool, or create another runtime.

`form-service.ts` uses `AskUserService`'s existing FIFO and Activity transitions. `form-validation.ts` checks bounded flat typed fields and returned values; remote schemas and executable validators never enter this capability. Forms have at most 16 fields, 64 choices per enum field, and 64 KiB request/answer bounds. MCP separately limits total enum choices across a form to 64. `host-form-dialogs.ts` and `host-form-tui.ts` adapt RPC and TUI presentation under the existing prompt gate and owned-overlay cleanup. Pure `ui/form-*` modules own drafts, rendering, and input. Hide/resume keeps drafts private; settlement returns them only to the caller, without async delivery or persistence.

URL presentation shows the full inert URL and prominent host and returns user consent only. The complete normalized host stays pinned when it leaves room for content and actions. At smaller allocations the oversized host joins the scrollable URL/prose, without truncating its suffix. Validation feedback remains beside the editor when space allows; final review and consent semantics are unchanged. Ask User has no browser or fetch authority. MCP owns wire-schema conversion, private continuation state, authority rechecks, system-browser navigation, and manual resume. MCP also owns its one-second foreign-cancellation waiter and process-local unresolved-cleanup fence; that bound does not promise Ask User cleanup always settles. The [README](./README.md#private-forms-for-local-extensions) records field and byte limits.

## Async ownership and delivery

`AskUserService` constructs the async controller under its Layer scope. The controller forks a child scope for presenters and delivery work; a later parent finalizer revokes delivery before child shutdown. One immutable `Ref` array owns at most 16 request entries. New admission evicts only the oldest terminal entry without a waiter whose delivery is `sent` or `waiter`. Unacknowledged failures and undelivered answers are not evicted. Explicit await or unopposed cancel acknowledges a terminal opening failure with `delivery: waiter`, making it evictable after the waiter releases its claim. A full registry without an eligible entry rejects admission rather than growing. Entries retain bounded work descriptions and final outcomes, not completed question drafts or host callbacks.

All blocking, owned-child, local-extension form, and async requests share 16 pending FIFO slots, separate from the 16 retained async results. Queue admission is an atomic `Ref` transition linking each ticket to its predecessor. A cancelled waiting caller settles promptly, but its queue slot remains occupied until the predecessor finishes. Its interruptible session-owned drain prevents successors from skipping ahead and bounds cancellation churn. Session closure revokes admission and interrupts drains. Active overlay and editor cleanup complete before the ticket advances. Automatic result delivery runs outside the ticket.

Async ticket acquisition, registry insertion, and session-scope fork form a short uninterruptible commit. No admission lock is held while the user answers. An immediate opener waits only for the separate mount Deferred. A queued opener returns its pending ID with `presentation: queued` immediately; admission is not mount acknowledgement or an answer. Queued questionnaires open automatically in FIFO order. Its caller signal never owns the presenter. If the opening call is interrupted after admission, `status` can recover the request ID. Opening failure settles a failed request, releases the permit, and fails the mount Deferred. Presenter cancellation races the host through an Effect-owned Deferred; tool await interruption does not cancel it.

Waiter claims are atomic `Ref.modify` transitions. A live await or unopposed cancel caller owns result delivery for that request. Cancel still signals the presenter when another caller owns delivery, then waits non-consumingly for cancellation to settle. Completion records the answer before waking the waiter or attempting automatic delivery. The waiter prepares its result without publishing a tentative acknowledgement. Its finalizer uses one interruptible, owner-checked `Ref.update` to publish `waiter` and release the claim atomically. That transition is final completion: pending interruption prevents it, but cancellation after publication cannot revoke it or a successor's acknowledgement. If interruption wins, masked cleanup releases only the caller's still-owned claim and leaves the previous delivery state intact, then offers automatic delivery in the session scope. Failed openings remain `none` until acknowledged, never a synthetic pending answer. Status is non-consuming; list status returns metadata only so it cannot multiply full answer output by the retention limit.

Without a waiter, the service claims automatic delivery. The host emits a custom `pi-ask-user-async-answer` message with `deliverAs: "steer"` and `triggerTurn: true`. This can continue an idle agent but cannot interrupt Pi's current tool batch. Request and delivery IDs remain stable across messages and control results. Results are retained after every delivery attempt. A synchronous host failure records `failed` and schedules at most two retries, one second apart, in the session scope. These sleeps do not hold the dialog permit. Recovery through await suppresses retries; scope closure cancels them. Exhausted failures remain retained for status/await recovery.

Pi's public sender returns `void`. `sent` therefore means only that the call returned. Later host errors and model consumption are not acknowledged, so this package promises neither exactly-once delivery nor reliable acceptance. Repeated delivery IDs must be treated as the same result. A status read can overlap an already claimed automatic message.

## TUI lifecycle and pinned host workaround

The TUI boundary lazily imports the dialog, then checks Effect interruption before reading settings or calling Pi. Async admission rejects unrelated public UI prompts but accepts queue entries behind an owned questionnaire. Blocking and queued async presenters wait for the public gate after lazy loading. A second synchronous check immediately before `ui.custom` catches intervening prompts; a queued presenter retries that transient race without losing its request. Pi coalesces nested prompts, so the boundary does not treat events as per-dialog counters or clear public prompt activity when only its own dialog closes. Each custom call owns one callback AbortController, finish latch, bridge token, and overlay handle. Pinned Pi calls the component factory synchronously but mounts in a Promise continuation. `onHandle`, not factory execution, completes the opening Deferred. A finish requested before mounting is latched; a late mount immediately removes the revoked questionnaire without activating its bridge.

Pi 0.85's custom `done` implementation pops the global overlay stack rather than removing its own overlay. Hiding or focusing the questionnaire does not fix stack ownership. The isolated `finishOwnedOverlay` workaround uses only public APIs in one synchronous window:

1. remove the questionnaire through its owned handle;
2. mount an inert, noncapturing guard overlay;
3. call Pi's `done`, which pops that guard;
4. remove the guard idempotently in `finally`.

An unrelated overlay above a hidden questionnaire is left intact. There is no asynchronous yield, private stack access, or installed dependency patch. Remove this workaround when pinned Pi's `done` removes its own overlay by identity. Host tests exercise submission, interruption, another stacked overlay, and abort before mount. Cleanup detaches from a nonsettling `ui.custom` Promise. It synchronously revokes callback and editor admission authority, then joins nonrejecting settlement handles for every admitted editor before releasing the presenter's dialog permit or completing session disposal. The standalone editor runner retains process and temporary-file ownership through TUI restoration; process cancellation escalates after one second. Late editor successes and rejections cannot update a revoked dialog. The join intentionally waits for owned cleanup, not the arbitrary custom Promise, so a replacement cannot stop its TUI before the old editor restarts it.

An `Effect.callback` owns completion independently of Pi's custom Promise. Synchronous finish failures reject with a redacted `AskUserHostError`, including guard cleanup failure after `done` resolves. The finish latch prevents reentrant or stale retries; cleanup revokes failure ingress before closing. Failed handle removal or guard acquisition never falls back to unguarded `done`. A throwing handle may leave its overlay behind. The FIFO ticket still releases after editor cleanup, but a nonsettling Pi Promise also retains its public prompt span. Subsequent presentation waits for a real host prompt-end event or session replacement, never a synthetic reset that could steal a foreign prompt's input.

Pressing `b` uses the owned handle's `setHidden(true)`, suppresses the questionnaire widget, and preserves the mounted dialog's drafts. `/ask-user` or the activity manager's token-checked Resume action restores it with `setHidden(false)`. Activity rows publish queued, opening, mounted, hidden, and settled transitions; cancellation requires confirmation. Needs-input rows explicitly target the user, including authenticated child questionnaires. Settlement clears attention metadata. Standalone questions are roots. Only authenticated owned requests attach beneath `pi-subagents` run IDs. Settled summaries retain no drafts or cancellation callbacks; at most 16 settled rows remain. The main editor is never replaced or rewritten. Pi's UI-prompt notifications still include hidden custom dialogs; they do not pause agent execution.

## Session lifecycle and history

The factory registers callbacks and `/ask-user` without acquiring resources. `session_start` captures the host, skips modes without UI except explicitly marked Pi children requiring root relay, starts one core managed runtime, loads trusted preview settings, and only then registers tools from the current activation hook. TUI receives all three tools; RPC receives only the blocking tool, routed to the root for marked local and Herdr Pi children. Pi's `ctx.signal` is turn-dynamic and is not attached to the session slot, including tree restarts. Per-tool calls receive their own signals; explicit slot disposal still interrupts preview bootstrap and session work.

Shutdown, reload, session replacement, and successful tree navigation revoke admission and delivery before disposal. Tree navigation replaces the runtime because Pi otherwise keeps it alive. Old registered tool callbacks reject during replacement. The slot's synchronous deactivation clears the bridge and current generation; no questionnaire is durably restored.

Immediately before each send, the host synchronously appends a version-1 `pi-ask-user-async-delivery` custom entry containing only generation and delivery ID to the originating branch. At session start and tree navigation, the application snapshots generation/delivery pairs from these receipts on the active branch before yielding into replacement. Answer messages never establish their own provenance. Context filtering admits this package's messages only if they belong to the current generation or have active-branch receipt evidence. Valid historical answers survive resume/navigation. A stale queued message persisted on a different branch stays rejected across repeated navigation and reload. Receipts do not restore pending work or confirm model consumption. Other messages and other extensions' queues are untouched. If the branch read is unavailable, old-generation messages fail closed. Filtering affects model context, not the visible transcript.

## Modes, security, and rendering

`ui/compact-summary.ts` projects validated final questionnaire outcomes for the explicit cooperative-shell opt-in on all three tools. It shares the existing outcome projection and bounded async snapshot shape, without reading service state. Submission retains call question titles with one answer-count detail. A single short selected label may replace the count only when the answer key matches the single question and the label matches a supplied choice; multiple or long labels, custom answers, and incomplete args keep the count. Custom answers and notes never enter compact subjects; cancellation retains the original details. Live transcript summaries use decoded question titles/counts or control arguments. Async control falls back to request IDs because snapshots carry no titles; no cache is added. Known pending snapshots retain visible await guidance; overlays remain separate and unchanged. Inconsistent snapshots and opening failures decline compaction. Failed automatic delivery adds visible status/await recovery guidance. The default preview, overlays, execution, and automatic message rendering are unchanged.

RPC retains native `select`/`input` answer, optional-note, and review/edit/submit/cancel behavior. Its calls receive Effect-owned abort signals. Multi-select input accepts only valid choice numbers rather than reinterpreting malformed syntax as custom text. Ordinary JSON and print modes receive no questionnaire tools. Marked local and Herdr Pi children may register the blocking relay tool without a local UI. Native Claude/Codex interactions and `contact_parent` are not forwarded by this package.

Prompts, previews, answers, notes, and work descriptions are ordinary session content. They never enter errors, logs, or telemetry attributes. Validation errors identify only question/choice positions. Guidance forbids collecting credentials. Every text consumption boundary strips terminal controls, including automatic messages and status output.

Blocking and async renderers share private service-free Effect Schema projections and answer/fallback formatting in `src/ui/tool-render-projection.ts`. Blocking replay ignores notes and accepts only content arrays; async replay validates and displays notes and also accepts string content. They cap array cardinalities, return neutral content for malformed input, and sanitize fallback text parts independently. `src/ui/async-tool-render.ts` projects async tool cards and automatic answer messages into readable states, answers, and notes. Expanded views retain request/delivery metadata and full text, without implying model acknowledgement. Tool registration also installs the existing async custom-message type's renderer. Agent-facing content, details, and safety guidance are unchanged. Synchronous renderers never read the service or run Effects.

The application Layer owns `CodePreviewSchedulerService` in the same session runtime as its tools. Startup returns that scheduler to activation, which passes a token-checked scheduling capability to each cooperative wrapper. Replacement and shutdown close animation fibers; retained wrappers cannot schedule against a stale session. No animation depends on another extension's Jiti module instance.
