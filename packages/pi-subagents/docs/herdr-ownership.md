# Herdr topology and ownership

Part of the [pi-subagents](../README.md) architecture documentation. See [ARCHITECTURE.md](../ARCHITECTURE.md) for the package overview, complete source map, and cross-cutting invariants.

## Herdr session ownership and retained reports

The Herdr CLI boundary never accepts a session selector and never emits `--session`: composition captures one bounded immutable ambient environment and supplies it to both CLI and harness services before each applies its narrower allowlist. Herdr 0.8 candidates require the parent's inherited `HERDR_SOCKET_PATH`, `HERDR_ENV=1`, and calling `HERDR_PANE_ID`; the exact captured socket is preserved through the sterile harness so native lifecycle hooks cannot silently report to a different/default server. Custom Pi/Claude/Codex config-home selectors are captured and preserved consistently. Later `process.env` or source-object mutation cannot redirect commands, probes, auth selection, or topology. Before service ownership, readiness checks the protocol-20 schema and live snapshot, resolves `pane current --current` to one exact inherited pane/terminal/workspace/tab tuple, and validates integration status, native executable/auth evidence, model/effort/context/write policy, exact 8/7/7 marker-validated integration files, Codex auth, and packaged Pi bridge files. Any protocol other than 20, or a CLI/server protocol mismatch, blocks Herdr before topology changes and visibly retries the same runtime/model candidate on the local host. The derived candidate preserves effort, context, write intent, fast mode, and claims while forcing `closeOnReport:true`; if local preflight fails, normal ordered fallback continues. A missing or unresolvable calling pane is a typed candidate skip, as are other safe readiness failures; cleanup or outcome uncertainty never permits fallback.

Every launch re-resolves the calling Pi pane against a fresh snapshot. The first run in that workspace/tab splits the calling pane with `--no-focus`; later runs split the newest live owned subagent pane in the same current workspace/tab, preserving the parent pane's size after the first split. If the caller moves to another tab, that tab receives its own chain. The host never creates, adopts, or closes a user workspace/tab and never closes the calling Pi pane. Every readiness poll and every focus, activation, environment, secret, or start mutation revalidates the unique workspace/tab/pane/terminal tuple; process inspection is bracketed by those snapshots, and mismatched occupancy fails closed. Switching active/focused tabs does not invalidate a committed run: workspace/tab ID uniqueness and parent relationship remain ownership context, while labels and active/focus state are not ownership. The host focuses the target tab only while focus still matches launch evidence and causally confirms a harmless random marker; because Herdr 0.8 can drop the first accepted input after session restore, one distinct harmless probe may be retried after refocusing. It restores the caller's prior tab only while its original tab/workspace/label tuple still exists and the target tab still holds focus, never following ID reuse or overriding newer user focus after rollback or closure. It never attaches to retired standalone-extension state or a native restored run. Opaque workspace/tab IDs plus every run's pane, terminal, runtime kind, generated agent name, canonical cwd evidence, and the full available native `agent_session` tuple (`source`, `agent`, `kind`, `value`) are exact ownership evidence. Generated names obey Herdr 0.8's 32-character lowercase grammar and combine a readable run prefix with a bounded digest of parent/run identity. Protocol 20 exposes no launch token that can bind later `agent_session` evidence to the original `agent start`; startup therefore requires that full tuple atomically in the start response. Missing session identity quarantines the provisional occupant rather than polling/adopting a possible replacement. One comparator is used by prompt, inspect, rollback, and close. A provisional occupant without complete evidence is never closed. Launch, prompt, stop, report-close, and finalization re-snapshot and revalidate; every observed provisional mismatch source (returned topology, process info, snapshots, start evidence, or pre-focus commit validation) is sticky across later ABA-looking snapshots. Committed runs likewise enter permanent quarantine after ownership mismatch or cleanup uncertainty, so automatic finalizers never retry an uncertain mutation. Cleanup always targets one exact owned subagent pane and first requires another pane to remain in the user-owned tab, refusing closure rather than knowingly collapsing a tab/workspace after the caller disappears. Confirmation plus harness authorization require absence of every owned pane/terminal/agent-name/native-session selector, including reparented survivors. Focus restoration uses the same non-stealing target-tab predicate.

Before spending an activation probe, the host polls Herdr's read-only process/snapshot APIs until the new pane first reaches an available, unoccupied interactive shell; this avoids sending both bounded probes into a transient stale native TUI restored by the server. Marker waits inspect the bounded visible pane viewport because protocol 20 may keep a new shell's prompt and first executed command out of `recent` output until the viewport scrolls. If agent detection briefly lags behind exact foreground-shell process evidence after activation, the host sends no further input and boundedly waits until both sources again agree that the provisional pane is unoccupied. The environment marker precedes its final shell `exec`, so a queued harmless command must execute in the replacement shell before private secret input; the same causal input proof follows secret attestation, with process/snapshot checks before the single `agent start`. Neither mutation relies on marker output alone or runs while a prior command owns the pane. A bounded readiness miss rolls back exact provisional topology without retrying a mutation, and Herdr's confirmed pre-application `agent_pane_busy` rejection remains safe to roll back.

All three drivers prepare a monotonic assignment epoch through `SupervisorChannel` before `agent prompt`. Herdr 0.8's successful prompt response proves only ownership-checked text queueing plus delayed-Enter scheduling, so successful and outcome-uncertain dispatches enter the same bounded reconciliation. A causal accepted report for that epoch or a post-response lifecycle/state change emits `run_started`; absent evidence fails closed with `herdr_prompt_outcome_uncertain`. Accepted reports are buffered safely before `run_started`, but generic supervisor contacts are not claimed as start evidence. Launch first waits for causal sterile-environment and atomic secret markers, then requires exact native `agent_session` identity in the Herdr start result because delayed evidence cannot be tied safely to that launch. Missing-report polling begins only after confirmed start. Missing/dead/mismatched agents fail, and idle/done without causal accepted-report evidence fails after a short bounded reconciliation grace. Sustained `unknown` agent status after a confirmed start and without an accepted report likewise fails closed after its own bounded grace; accepted-report ownership is checked first so later status-only `unknown`/`idle`/`done` observations cannot overwrite a retained successful report, and a transient unknown blip recovers without erasing accumulated missing-report evidence. Supervisor report, not PTY text or native status, owns completion. For Herdr Pi only, the private bridge recognizes the fixed leading epoch marker at both input and agent-start boundaries, so a retained active-loop steer cannot inherit prior accepted state. The first possibly delivered explicit identity is immutable for that epoch; only a successful final stop may retry it or turn final Pi text into the same authenticated report event. Aborted/error turns and shutdown remain non-completion. Herdr capabilities are exactly `parent-contact`; steer/interrupt/resume/rename/live-read are omitted because protocol 20 does not confirm application outcomes safely for this ownership model.

`closeOnReport:true` closes the exact owned subagent pane and private harness after the report. `closeOnReport:false` is read-only only: the service enters `reported`, retains topology/channel/harness, and `subagent_send` from that state uses `controls.start` with a new epoch and report generation without requiring the active-turn `steer` capability. Retained Pi runs can use Bash under the same no-mutation behavioral contract and still acquire no writer lease; Claude/Codex keep their read-only sandbox. Parent replacement/shutdown always closes retained topology. Writers always close, and writer lease `spawn-started` is committed before any harness/topology/process start.

Claude receives read-only inspection Bash through its mandatory sandbox, empty normal setting sources, fixed `CLAUDE_CODE_SKIP_PROMPT_HISTORY=1`, disabled nonessential traffic in generated settings, strict supervisor MCP, one marker-validated Herdr hook, the hardened local strict sandbox/scoped Edit policy, and fixed delegation/integration denials. Interactive Claude rejects the print-only `--no-session-persistence`; the documented environment replacement suppresses prompt-history/session-transcript writes without moving the inherited authentication boundary, so delegated sessions are absent from resume/continue/up-arrow history. Its writer cwd must be representable by the shared comma-delimited allowed-tool/scoped-Edit grammar during mutation-free preflight. The package creates no project report/history file, but inherited authenticated Claude may still maintain implementation-defined account/cache/diagnostic or provider-side records outside the project; the harness is not a zero-retention or offline boundary. Codex gets an isolated private `CODEX_HOME`, bounded auth copy or API-key loaded through a private script path, approval never, read-only/workspace-write sandbox, strict supervisor-only config, and disabled apps/plugins/multi-agent/web/network extras. Its exact generated `SessionStart` hook is discovered through the native app-server, its opaque current hash alone is persisted through `config/batchWrite`, and the same process must re-list it as trusted before topology mutation. A fixed bootstrap prompt then runs that startup hook; the packaged compatibility helper supplies a private fallback for Codex's nullable transcript field to the marker-validated Herdr integration and returns `continue:false`, so Herdr receives native session identity atomically in `agent start` while Codex stops before model inference. Pi gets a fresh private session directory, explicit model/thinking, sterile child marker/environment, no discovered resources/context, Bash-enabled read-only inspection or writer tools, an orchestration denylist, the lifecycle integration, and one packaged bridge extension. Its private policy is appended to Pi's default coding prompt rather than replacing it. Pi Bash is not filesystem-sandboxed. Environment-sourced Pi model keys cross only through its 0600 private bootstrap script and are consumed/deleted from the delegated process environment by the bridge. Bridge tools are registered with `withCodePreviewShell`; its client multiplexes bounded correlated helper calls so a blocking question cannot block unrelated progress/report calls, and its per-assignment settled-response fallback cannot duplicate an explicitly accepted report. Calls remain Effects inside the delegated session runtime and become Promises only at Pi tool handlers. The current runtime owns interruption and joining of active calls plus helper cleanup, while stale tool generations fail before dispatch.

## Module responsibilities

- `src/backend/herdr.ts` owns the shared Herdr Pi/Claude/Codex driver and report reconciliation.
- `src/backend/herdr-assignment.ts`, `herdr-ownership.ts`, and `herdr-shell-readiness.ts` own pure epoch, identity, and shell-readiness policy.
- `src/boundary/herdr-environment.ts`, `herdr-cli.ts`, `herdr-harness.ts`, `herdr-codex-hooks.ts`, `herdr-codex-session-hook.mjs`, `herdr-launch-safety.ts`, and `herdr-host.ts` own inherited environment, protocol I/O, private harnesses, Codex hook trust/bootstrap compatibility, safe launch mutation, and exact session topology.
- `src/boundary/host-pi-supervisor-extension.ts` and `pi-supervisor-bridge-client.ts` are the sole delegated-Pi supervisor bridge. The client exposes scoped Effect calls without its own close method; the extension's session runtime owns call and helper lifetime.

Backend-neutral report claims and notification delivery are documented in [Completion and delivery](completion-delivery.md).
