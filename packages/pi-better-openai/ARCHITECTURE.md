# Better OpenAI architecture

## Purpose

Adds OpenAI subscription usage, fast-mode request injection, provider-native compaction, image generation, settings, and footer output to Pi.

## Host surface

- Flag/command: `--fast` and `/fast`.
- Commands/tools: `/openai-usage`, settings commands, and the image tool/command registered under `src/image/`.
- Events: session lifecycle, agent/turn/model/message changes, `session_before_compact`, `before_provider_headers`, and `before_provider_request`.

## Source map

- `src/extension.ts` is the thin Pi package entrypoint.
- `src/application.ts` coordinates commands, host events, projections, and one session runtime.
- `src/layer.ts` composes usage, fast-mode, image, platform, and file/Sharp Layers.
- `src/auth/codex-auth.ts` owns synchronous lossy JWT and registry parsing plus effectful auth-file and model-registry readers. Each reader returns credentials or `undefined` and fails with `CodexAuthError`. The resolver runs both readers concurrently and interruptibly, then uses local Effect `Result` values to apply the documented registry, file, and failure precedence. Decoded tokens remain `Redacted` until usage or image HTTP code constructs an authorization header.
- `src/usage/controller.ts`, `src/fast/service.ts`, `src/compaction/service.ts`, and `src/image/service.ts` are the feature Context service doors.
- `src/usage/projection.ts` owns frozen usage projection policy, and `debug.ts` owns deterministic diagnostics. `format.ts` defines the usage HTTP schema and projects its decoded root and primary bucket directly. It still decodes the unknown additional-limit entries before selecting the Spark bucket.
- `src/image/register.ts` owns image host names, registration, result formatting, and renderer guards. `service.ts` captures one context/config snapshot, resolves request options once, and orchestrates auth, HTTP, validation, and saving. `protocol.ts` builds requests from those resolved values and schema-decodes provider events into a normalized internal union.
- `src/image/compact-summary.ts` supplies a pure semantic opt-in to the cooperative preview shell. It classifies validated image details, uses the full literal saved path or a shortened prompt as its subject, keeps saved-path metadata on expansion, and declines unknown results or attachment-bearing errors. Typed incomplete states project warning issues. Text-only failures retain all diagnostic text with unknown issue coverage, so the original renderer still owns their presentation. A failed status without complete diagnostics also keeps unknown coverage. Pi still owns native result images; execution and session resources are unchanged.
- `src/image/input.ts` owns input MIME detection and workspace containment. `stream.ts` owns bounded SSE framing and terminal outcomes. `output.ts` owns strict base64 decoding, output-format metadata, output containment, generated-byte validation, and publication. `types.ts` retains only contracts and constants shared across those owners.
- `src/config/schema.ts` owns config shapes and defaults, `options.ts` owns setting descriptors (update decoding is shared core `decodeSettingUpdate`), and `store.ts` is the persistence door. `src/fast/controller.ts`, `src/fast/routing.ts`, `src/fast/models.ts`, and `src/image/protocol.ts` contain deterministic policy and protocol logic.
- `src/boundary/` isolates Pi UI, provider-header and cached-transport adaptation, schema-encoded and response-bounded OpenAI compaction HTTP, and Sharp. Best-effort UI effects call the total `pi-cosmic-core` host callback adapter and add no ignored error channel. Footer and usage projection code call the shared core OAuth host helper directly.
- `src/ui/primitives.ts` projects frozen provider state into plain footer contributions. Application orchestration queries Cosmic UI's v2 ownership, readiness, and visibility policy. Cosmic UI is the only custom-footer owner; providers use its sanitized keyed-status helper when no custom footer is active. Provider config has no footer mode or usage-display switch. Hidden usage suppresses automatic requests and both output paths, while the explicit usage command remains available. Visibility changes invalidate pending usage results and refresh newly visible usage. Deactivation removes contributions and clears provider status. Image tools retain the cooperative code-preview shell. The application merges its animation scheduler into the image session runtime and returns it with the fast-mode ingress through startup activation. Image registration receives a generation-checked scheduler callback; replacement and shutdown revoke scheduling and dispose ticks without relying on shared extension modules.
- `src/settings/controller.ts` registers settings commands with finite argument completions and pure command dispatch from `pi-cosmic-core`. It owns write settlement, authoritative projection refresh, category-summary reconciliation, and the outer `pi-cosmic-ui/manager/settings-surface` adapter with the package's guarded host rendering. Redacted raw configuration is rendered with standard JSON serialization. Cosmic UI projects config descriptors and owns the shared category submenu and diagnostic text panel; Better OpenAI supplies plain rows, persistence actions, and package-specific summaries. The outer adapter owns search; the small nested category lists do not create a second search input. `diagnostics` remains the only diagnostics verb, and its picker item id is `diagnostics`.

## State and resources

Usage, fast mode, compaction, and image work are scoped services. They publish immutable projections for synchronous request injection and rendering. Fast mode serializes transitions with one `SynchronizedRef` before publishing its frozen boundary snapshot. Its snapshots contain only owned boolean and string state, so cloning and freezing are total by contract. In-memory publication and persisted transitions keep publication uninterruptible; persisted transitions run it through config persistence's durable `afterCommit`, so the committed document and authoritative fast state cannot diverge. Fast-mode startup returns its scoped injection ingress through the session slot, so only the current activation can install it and deactivation immediately restores a no-op boundary. Omitted project-trust input is treated as untrusted; project-local configuration is read only after literal-true trust. OpenAI checkpoints live in normal branch-local Pi compaction entries under typed extension details; their kept boundary preserves the original Pi transcript for tree navigation. Image streaming, file handles, and background refresh work are owned by the session runtime. Output writing opens, identifies, writes, and syncs the temporary file inside a nested scope, so its handle closes before publication. The outer pathname acquisition retains identity-checked cleanup. Image publication commits at the exclusive hard link. After that link succeeds, verification may report a positive identity mismatch but never removes the destination, which may already be a foreign replacement.

Sharp runs only in the shipped `src/boundary/sharp-decoder.mjs` one-shot process. `boundary/sharp.ts` opts into core `runBoundedProcessNode` with fixed `process.execPath` and helper path, no shell or caller argv/environment. Both sides reject stdin over 60 MiB. The child fully decodes all animation pages with strict error handling, a 40-million-pixel limit, sequential reads, and uchar sRGB raw output of at most four channels. Sharp cache is disabled and concurrency is one, only inside the child. Only bounded, schema-decoded format JSON crosses back; native errors, stderr, and pixels never reach callers.

One module-private immediate semaphore shares admission across session runtimes. Busy calls fail rather than queue image buffers. Its permit covers the runner's entire process scope, including cancellation cleanup. The 30-second execution deadline terminates the process, with a two-second cleanup confirmation budget and forced SIGKILL fallback. Sharp's cooperative 30-second raw timeout is secondary and does not bound metadata. Stream destruction is not native cancellation. Core's finalizer reports explicit child-exit confirmation through `onCleanup`, even on interruption or stream failure. Sharp defaults to unconfirmed and latches disabled before releasing admission unless cleanup confirms exit. A failed or partial spawn without a returned handle also disables decoding until restart, since the platform cannot prove no child survived. Confirmed cancellations remain reusable; a successful scope return or kill call alone is not confirmation. If the OS cannot terminate a child, core's platform finalizer can wait beyond these budgets for actual exit; ownership and the permit remain held, so shutdown has no unconditional wall-clock guarantee. The subprocess and pixel limits constrain work but are not an OS memory sandbox.

## Lifecycle

```text
session_start -> application -> layer -> abort-aware preview-settings bootstrap
                              -> usage + fast + image services -> current-session activation
current-session activation -> register image command/tool with captured preview shell settings
command/event -> runtime service -> projection -> footer/UI or request injection
Pi compaction trigger -> OpenAI /responses/compact -> custom checkpoint -> request projection
session_shutdown -> fibers/resources disposed -> projections reset
```
