# Local backends: Pi, Claude, Codex, writer pools and leases, and the supervisor channel

Part of the [pi-subagents](../README.md) architecture documentation. See [ARCHITECTURE.md](../ARCHITECTURE.md) for the package ownership map, [Completion and delivery](completion-delivery.md) for assignment/report ownership, and [Herdr ownership](herdr-ownership.md) for remote topology.

## Local Pi ownership and safety

Local Pi children run in RPC mode over stdin/stdout with bounded/schema-decoded frames. A separate bounded Node IPC channel goes directly to the root process and carries parent contact, peer notices, ancestor outcomes, and authenticated coordinator proxy calls. `boundary/local-pi-ipc.ts` is the only owner of raw `child.send`/`process.send`, message and disconnect listeners, bounded callback settlement, and schema decoding for both directions. It passes typed contact events to `child-process.ts`; `backend/local-pi.ts` owns command-checked native RPC correlation and maps those typed contacts without seeing raw IPC values. The backend emits normalized events through a bounded, backpressured queue, and raw event ownership is acknowledged only after run orchestration consumes each normalized event. Run orchestration supplies every assignment-start control with a monotonic assignment epoch, and the adapter tags assignment-scoped normalized events with the active epoch. Definite start failure restores the adapter's prior epoch; outcome-uncertain failure retains the attempted epoch. Run orchestration does not construct or decode Pi RPC commands. Backend continuation state is an opaque token to orchestration; only the local Pi adapter translates its token into a Pi session-file launch argument, while `view.sessionFile` remains status metadata. Fresh children use a dedicated session directory; forked children receive a private copy of the stable parent branch. Runtime API keys cross through an ephemeral environment bootstrap rather than argv. `boundary/host-child-pi.ts` owns one-shot credential consumption/scrubbing and the eligible `before_provider_request` priority-tier hook shared by local and delegated Pi. Local Pi consumes credentials during child extension registration; delegated Pi consumes them at first session start before validating the private bridge flag, preserving the earlier scrubbing points.

`boundary/host-child.ts` creates one session-runtime slot for the child bridge, which owns one managed runtime for the current started child session. A package-local scoped Layer attaches the IPC listener and detaches it when replacement or shutdown closes the runtime. Preview settings load through the runtime's cancellation signal before activation. Only the current session identity and slot token may register or execute fresh proxy tools, `contact_parent`, and the subtree manager; a reload first removes their active names. A partial registration removes those names and closes the runtime. Each question and proxy call owns one exact Deferred map entry through `acquireUseRelease`. Response callbacks complete that Deferred synchronously, while release deletes only the same waiter identity and sends cancellation only under the established delivery rules. Listener release and shutdown reject all remaining correlations unconditionally. A disconnect callback does so only while its listener still belongs to the current session, so a detached old listener cannot reject the replacement session's waits. Controls from a detached or superseded listener receive no acknowledgement.

Pi 0.84.4 continues queued steering after `abort`, so resumable interruption first closes run-level turn-input admission and waits for admitted guidance, parent replies, and descendant notifications to drain. Parent replies receive a correlated child acknowledgment after the waiting tool is resumed (or a typed ownership rejection if the question is gone). Notifications receive a correlated acknowledgment after the child synchronously admits `pi.sendMessage`; an acknowledgment-uncertain notification remains owned by that first ancestor instead of falling through and risking duplicate delivery. Replies and notifications share the adapter's session-local turn-control semaphore with interruption. Once it owns that semaphore, interruption sends and confirms an IPC barrier. Node IPC ordering proves the child processed every earlier turn input before the adapter issues correlated `clear_queue`, discards the returned steering and follow-up text, and sends `abort`. New guidance, parent replies, and ancestor notification delivery are rejected after `pauseRequested`; paused ancestors are skipped. Barrier, clear, or transport failure and uncertainty suppress later interruption commands and release the pause claim. Clear uncertainty uses `clear_queue_outcome_uncertain`, distinct from post-abort `interrupt_outcome_uncertain`; only the latter keeps a pending pause that late child settlement may confirm.

At every local or Herdr Pi launch, the root coordinator snapshots the root Pi's current active tool names and project-trust decision. `writeIntent` does not filter those names. Only competing coordinator/orchestrator implementations are denied; the public extension still exits under `PI_SUBAGENT_CHILD`, and a packaged private extension registers authenticated `subagent_*` proxies plus the subtree manager. Proxy requests cannot carry ancestry: the root binds them to the channel's run ID and authorizes every target against that subtree.

An active name is not an implementation transfer. The child can use it only when its trust mode discovers the providing built-in, extension, or package, or when the package explicitly installs the private integration. The snapshot is immutable for that launch. A nested start returns to the root for a fresh root snapshot, so child-local active-tool toggles do not control grandchildren.

Pi read-only is a no-mutation prompt and writer-lease policy, not capability confinement, a filesystem sandbox, or a confidentiality boundary. It receives the same trusted-tool snapshot as a Pi writer and does not acquire a writer lease. In a trusted local or Herdr Pi child, active/discoverable Code Mode is consequently available for either intent. The model applies `writeIntent` and exact-file claims when it writes the Code Mode program. The interpreter does not recheck those claims, and its direct nested built-ins bypass Pi tool middleware, approvals, registered overrides, and `pi-subagents` per-file claim observation. Code Mode therefore changes observation, not the cooperative authority model. Native Claude/Codex launches retain their fixed adapter-specific tools and sandboxes and do not consume the Pi snapshot.

## Writer pools, cooperative claims, and cross-process safety

The root `SubagentService` owns the complete run tree, backend scopes, and one writer pool per canonical cwd. Nested Pi writer requests enter the same admission path, so writer leases and disjoint claims remain tree-wide even though active-run limits are per parent. It resolves `realpath` for launch and diagnostics, while both the fast in-memory guard and disk slot are keyed by a bounded SHA-256 digest of the directory's stable local filesystem identity (`stat` device plus inode/file ID). Relative and symlink aliases collide, and renaming the directory does not change writer ownership. The first pool member acquires and durably marks the package-owned cross-process lease before any member may spawn; concurrent members wait for that same preparation. The lease remains held until the last member confirms backend cleanup. Read-only runs never canonicalize for or join a pool, and retained writers remain invalid.

A writer without `writes` owns the whole cwd exclusively. A writer with `writes` owns normalized exact workspace-relative paths in the session registry, and admission rejects case-insensitive overlap with active members and start reservations. Dynamic grants and revocations use the parent-only `subagent_claims` tool while the worker is blocked on a parent claim question with no other active tool. A confirmed paused violation offender is also eligible while its pool admission is paused, its run ID remains in the pool's offender set, and it has no active tool. Ordinary paused writers and non-offending peers are not eligible. The run view and persisted tool card mark only current offenders; the write audit remains historical. Peers may announce contracts, but only the parent changes claims. Absolute paths and the case-insensitive outside-workspace audit marker remain ungrantable.

An observed out-of-claim native file-tool call pauses new writer admission and starts owner-scoped containment in one uninterruptible orchestration step. A running backend is interrupted only when it supports both interruption and resume. Starting or non-resumable active backends stop instead. Any interrupt failure or uncertainty falls back to normal stop, and orchestration logs only when that stop also fails. Admission remains closed until the parent reviews the audit and containment state. For a resumable paused offender, the parent may grant intended safe claims, reopen admission, resume with the authoritative claims, and await again. An outside-workspace write or non-resumable offender requires confirmed stop cleanup, explicit admission reopening, and a corrected replacement. A likely mutating Bash command increments a bounded heuristic-notice count in the write audit but does not create a sticky run warning or trigger interruption.

Per-file claims are cooperative, not filesystem isolation. Claim comparison is lexical after NFC normalization and conservative case-folding; it does not prove that two in-workspace symlink or hard-link paths reference different files. Native edit, write, and Bash remain unchanged and can physically modify the whole assigned cwd. Observation is asynchronous and post-hoc, so a violating mutation may land before interruption; the extension never rolls it back automatically. A violation pause survives final-member cleanup as a resource-free session tombstone, so releasing the lease does not silently reopen admission; the parent can resume it by referencing the historical offending run. Unconfirmed process or lease cleanup quarantines the entire cwd pool because the surviving process cannot be confined to its declared claims.

The protocol-v2 slot is `<agent-dir>/subagents/writer-leases-v2/<sha256(device+inode)>.lease`; neither its bounded filename nor evidence exposes the cwd path or unhashed filesystem identity. Exclusive directory creation plus synced, bounded Effect Schema-decoded evidence establishes a `reserved` lease. Evidence contains its phase, an unguessable ownership token, filesystem-identity digest, parent PID, approximate parent-process start time, an unguessable owner/session nonce, parent session/run identity, and timestamps. `markSpawnStarted` token-checks the stable reservation, atomically replaces it with synced `spawn-started` evidence, confirms the same directory object and token, and only then permits the driver call. Failure or ambiguity forbids spawn. Transition artifacts, permission failures, malformed data, changing data, and every other uncertain observation remain locked.

Only an `ESRCH` parent-liveness result may enter orphan handling, and even then only stably decoded `reserved` evidence can be reclaimed. A dead `spawn-started` lease is never automatically reclaimed: detached local process groups and Herdr PTYs may survive their parent. Such a slot requires manual private-state recovery only after an operator independently verifies that the external backend and descendants are dead. Corrupt, transitional, and uncertain dead-owner evidence has the same fail-closed/manual-recovery requirement.

Dead-reservation takeover and normal release use the same deterministic, non-empty destination derived only from the old ownership token. Takeover atomically renames there, token-checks the moved evidence, and then contenders race through the exclusive creation primitive. Release prechecks the token, atomically renames the complete lease directory to that same old-token tombstone, and token-checks moved evidence; it never uses read-then-unlink/rmdir. The shared enduring destination prevents duplicate or delayed release **and** takeover operations from renaming a replacement lease across either kind of ABA cycle. Tombstones are private, each contains at most the bounded lease evidence, and retained history grows linearly with successfully released or reclaimed ownership tokens. They are not garbage-collected automatically because this protocol has no proof that an old delayed operation can no longer execute.

PID reuse cannot be eliminated portably with `kill(pid, 0)`. A reused/live PID therefore conflicts conservatively even if start/session evidence differs; process-start estimates and nonces strengthen diagnostics but never declare death. Coordination assumes same-host parent Pi processes use the same private agent directory on a local filesystem with stable device/inode identity and atomic directory create/rename semantics. Distinct agent homes and remote/distributed filesystems are outside this protocol. Windows writer admission fails with typed `unsupported_safe_writer_ownership` before canonicalization, lease acquisition, or spawn because leader exit plus `taskkill` cannot prove descendant termination; read-only runs remain allowed pending a native Job Object owner.

Backend scopes are service-owned and explicitly closed before pool membership is detached. Stop and shutdown also wait for every admitted backend spawn attempt to settle before closing its scope, so a spawn cannot acquire into a closed scope after writer ownership is released. Non-final members detach only after confirmed cleanup; the final member alone authorizes lease release. If any backend cleanup fails, that member remains attached and release is never authorized. If token-checked tombstone release cannot be confirmed, the whole pool remains quarantined and retains process capacity and writer ownership. An explicit pool `pending`/`preparing`/`held`/`failed`/`releasing`/`quarantined` state plus one shared Deferred lets shutdown distinguish interruptible pre-ownership acquisition, attached waiters, and a narrow ownership commit already in progress. `acquireRelease` preserves an uninterruptible acquired-value/finalizer handoff while the lease boundary explicitly restores interruption for validation, stable reads, and waits; cleanup may therefore stop promptly before its release rename, while exclusive mkdir/evidence, reserved→spawn-started, takeover, and tombstone rename/fsync regions remain indivisible and fail closed. Session shutdown applies spawn-settlement → backend cleanup → lease ordering to every owned run.

## Supervisor channel and completion ownership

The supervisor channel is composed once with the shared backend registry. Local and Herdr Claude/Codex acquire one channel inside each backend scope; Herdr Pi loads the packaged private bridge/client against the same channel. Local Pi retains its existing RPC/IPC parent-contact transport.

Local Pi uses its RPC completion transport: the last assistant response is captured from the existing RPC stream and `agent_settled` completes the assignment. Herdr Pi preserves Pi's default coding-assistant prompt and appends the private supervisor policy. Its bridge resets report state at each `before_agent_start`, records only final assistant text whose low-level run stopped successfully, and waits for `agent_settled` so automatic retries or compaction cannot be mistaken for completion. An explicitly accepted report suppresses the fallback; if an explicit submission failed, fallback retries the same delivery identity and text, otherwise it uses one deterministic per-assignment identity. Aborted/error turns and session shutdown never promote partial text. The bridge client's `call` returns an Effect and allocates its request ID only when that Effect starts. The delegated extension forces bridge acquisition during runtime startup but returns no client value; Pi tool Promises use the current session slot to run calls with their abort signal. Runtime disposal interrupts and joins those calls and then releases the scoped helper. Local Claude/Codex completion is owned exclusively by a supervisor MCP report; raw final CLI text and normal native turn/result completion do not settle the assignment. SupervisorChannel records exact accepted-report epoch evidence before acknowledging the MCP call. Claude successful assignment results and Codex normal `turn/completed` both query that exact epoch evidence directly, independent of adapter queue scheduling, so an accepted report wins behind progress/backpressure and a missing or wrong-epoch report fails immediately by protocol causality rather than hanging or using a scheduling sleep. If native transport closes before the supervisor-event forwarding fiber drains, the adapter reprojects that exact accepted evidence into its backend queue before ending it. Claude's epoch-zero native initialization result remains non-assignment evidence. Claude and Codex interruption retain their separate correlated native lifecycles and emit no completion-shaped run event. Every local candidate has `closeOnReport: true`, so accepted report completion closes process and channel scope immediately while retaining bounded projection data. No report or harness artifact is written into the project.

The backend-neutral report event is bounded and correlated by run plus assignment epoch. An adapter supplies a positive monotonic per-run sequence, a bounded retry identity (`deliveryId`), and optional opaque ownership evidence. Phase, epoch, sequence, and delivery identity are validated in one serialized commit; the watermark advances only with a committed report. Exact `(sequence, deliveryId)` retries are idempotent. Higher reports while idle are rejected without advancing the watermark, so a valid later assignment can reuse that unpoisoned delivery. Future adapters decode their foreign protocol before emitting this event.

The Effect platform split is deliberate. Ordinary supervisor networking, framing, request correlation, interruption, and scope ownership use unstable Effect Socket and RPC APIs pinned by the workspace. Security-sensitive configuration reads and state cleanup retain the Node boundary because Effect FileSystem has no `lstat` or `O_NOFOLLOW` equivalent. Foreign MCP/Codex JSON-RPC stdio uses the shared byte-bounded parser because `Stream.splitLines` does not impose a maximum incomplete-line or aggregate queued-byte bound. The standalone supervisor helper uses that parser too, preserves CRLF and final unterminated frames, and writes a bounded invalid-request response before closing overflowed stdin; validated frames then feed Effect queues or RPC clients. A tool call's interruptible RPC operation returns response data without touching stdout. Its `Exit` selects success, failure, or cancellation, then one uninterruptible serialized-writer commit publishes and acknowledges exactly one frame. Writer close still runs before active-call and socket interruption. The import-free `supervisor/mcp-contract.ts` is the sole owner of MCP registration, tool names, snake_case argument objects, nonblank/delivery patterns, and the 16,384/32,768/256 character bounds. The helper serverInfo name `pi-subagents-supervisor`, private Pi CLI flags, backend report limits, parent reply bound, transport framing/call limits, and concurrency caps are separate identities.

One scoped `SupervisorChannel` binds only IPv4 loopback on an ephemeral TCP port and writes one 0600 connection document below a unique 0700 run directory in private agent state. Open uses staged Effect acquisition for the run directory, Effect NodeSocketServer listener, private config, and Effect RPC v3 server. Validation and listener setup remain interruptible; the private config writer is one bounded uninterruptible commit followed by an explicit interruption checkpoint, so cleanup never races an unsettled file handle and still removes every acquired stage before publication. Supervisor channels and spawned helper RPC sessions construct an underlying-uninterruptible `Effect.cached` close inside masked acquisition before finalizer registration. Explicit close, partial cleanup, and scope release reuse its complete success or failure without retrying resource cleanup. The supervisor close shuts peer sockets and the server scope before removing private state. Each connection has an Effect-owned authentication deadline that ends on authentication, detachment, or channel disposal. A 256-bit token authenticates every RPC request with constant-time comparison; peers are loopback-checked and capped, Effect RPC schemas decode every payload/result/error, and NDJSON framing, queues, maps, calls, and strings are bounded. Assignment updates use a server stream plus explicit adoption RPC, blocking questions use transport interruption plus explicit reply confirmation, and report delivery remains idempotent by bounded delivery identity. The erasable-TypeScript helper retains only the external MCP JSON-RPC stdio adapter and an Effect RPC client. Its minimal `.mjs` launcher uses the package-owned Jiti dependency so the same typed source runs from installed `node_modules`, where Node's native type stripping is intentionally disabled. Metadata contains only that fixed packaged helper command, private config path, and Claude JSON/Codex TOML MCP fragments, with no public profile fields, arbitrary command, user configuration, credentials, or environment.

## Local Claude

Local Claude starts only `claude --print --input-format stream-json --output-format stream-json --verbose --forward-subagent-text` with partial/replayed messages, an empty fixed settings-source list, strict MCP, explicit model/effort, no session persistence, and no slash commands or plugin arguments. Its generated settings refuse cross-session input because these headless children use the private supervisor channel for parent contact and cannot review an inbound-message prompt; the shared Herdr Claude policy applies the same refusal. Every launch requires current strict sandbox settings: enabled, failure when unavailable, no unsandboxed command fallback, strict empty network allowlist, and assigned-cwd filesystem write policy. Read-only exposes Bash for inspection/validation through sandbox-only auto-allow while excluding Edit, Write, and NotebookEdit and explicitly denying Bash writes to the assigned cwd. Writers expose the same sandboxed Bash and Edit through one canonical-cwd-scoped permission rule; bare Bash/Edit/Write are never permission grants. Unsupported Bash-sandbox platforms and writer path policies fail typed preflight. The subprocess sandbox directly confines Bash; Edit remains the current CLI's path/symlink-enforced file-tool permission policy rather than an OS sandbox, and Web/model traffic is not an offline/confidentiality boundary. `Agent`, `Task`, `TaskOutput`, `TaskStop`, and `SendMessage` are allowed. Their work inherits this parent policy and lease, remains inside the Claude process tree, and updates only the parent run's bounded native activity summary.

Claude startup sends the official initialize control, then one `shouldQuery:false` input to obtain native `system/init` without inference. It validates cwd, native session, selected/resolved model, MCP config errors, and a connected `pi_subagents_supervisor` inventory containing all four mandatory tools before returning startup state. Every outbound stream input carries a fresh UUID; acknowledgement requires the native replay of exactly that UUID from the active session, with no text matching. A delayed or duplicate replay of a bounded set of already-confirmed UUIDs is acknowledged silently. User frames with a non-null `parent_tool_use_id` belong to native-agent forwarding rather than top-level stream-input replay. Their text becomes assignment activity, while forwarded tool results retain the nested tool lifecycle used by write-claim observation. Claude-owned, synthetic, unqualified `task-notification` and `auto-continuation` messages own one subturn/result inside the active assignment; a private identity and the result FIFO cover older frames that omit their UUID. Qualified task-notification subkinds such as cross-session peer delivery remain foreign and fail closed. Rejections retain only bounded classification flags, never message text, UUIDs, session IDs, or parent tool IDs. Uncertain delivery closes the backend before returning the error so a delayed replay cannot confirm a later retry. Native results correlate to their originating input by `user_message_uuid` when reported, otherwise by the adapter-owned issue-order FIFO; the correlated initialization-probe result is a nonfatal artifact independent of any assignment epoch, eliminating the initialization/assignment race. Cumulative assistant usage repeated for the same native message id is deduplicated by nonnegative deltas under a total-token definition that includes cache-read/cache-write tokens, the final result's cumulative usage and known `total_cost_usd` estimate reconcile as one uncounted remainder, and a regressing native total warns rather than subtracts. Accepted supervisor reports are buffered for a ten-second bounded native-result-or-exit grace so usage/cost enters the backend event queue before report settlement closes the process scope; timeout or transport exit flushes the accepted report so missing telemetry cannot hang completion. Initialization failure is post-spawn and never candidate fallback. Interrupt sends `cancel_queued:true` and remains correlated to its assignment until the control response, exact replayed marker, and exact `error_during_execution`/`aborted_streaming` result all arrive in either order; only that lifecycle is suppressed, while genuine result failures remain fatal. If the public interrupt times out uncertainly, the lifecycle stays exactly owned — a second interrupt is rejected as ambiguous — and a late marker+result pair settles the assignment through `run_settled` so orchestration pauses instead of failing; transport closure is the safe boundary that clears lingering ownership.

## Local Codex

Local Codex starts only `codex app-server --stdio --strict-config` against an isolated 0700 `CODEX_HOME`. The private configuration enables `[agents]` and `multi_agent` under Codex's runtime limits. Fast candidates enable only the isolated harness's `fast_mode` feature and send `serviceTier: "priority"` on both `thread/start` and `turn/start`; initialization fails closed unless `thread/start` confirms that tier. The boundary copies only a bounded, recursively validated `auth.json` from a safe custom source `CODEX_HOME` or the default source to 0600 private state, without passing the source path to the child or its auth-status probe; otherwise it permits the fixed `OPENAI_API_KEY` fallback. Harness creation is failure-atomic after its unique private directory exists, and unconfirmable partial cleanup returns `harness_cleanup_unconfirmed` while preserving private fail-closed state. No other credential/environment keys cross. Generated config includes only the private supervisor MCP server, enables native agents, and disables apps, plugins, hooks, skills discovery, memories, browser/computer/image, web-search, network, and related extras. The accepted 0.145 generated v2 subset is `initialize`, `thread/start`, `turn/start`, `turn/steer`, `turn/interrupt`, their correlated responses, and bounded relevant turn/item/usage/warning notifications. Only known executable item types (`commandExecution`, `fileChange`, `mcpToolCall`, `webSearch`) own a `tool_started`/`tool_finished` lifecycle; bounded `fileChange` entries preserve every source path and update move destination for claim observation, and a claimed writer's recognized file mutation without an established path fails closed as a violation; `agentMessage`, `reasoning`, and unknown future informational items surface as activity or are acknowledged without fabricating tool entries, while schema-bounded `collabAgentToolCall` and `subAgentActivity` items update native activity. Unknown native shapes fail the protocol instead of being treated as ordinary activity. Warning `{message}` is decoded separately from `configWarning`/`deprecationNotice` `{summary,details,...}`. Approval is `never`; native sandbox policy is read-only or workspace-write with network disabled. Server-initiated approval or other requests are protocol violations. An interrupt that times out uncertainly retains its exact turn/epoch lifecycle — a second interrupt is rejected as ambiguous — and a late matching interrupted turn completion settles through `run_settled` as a pause rather than a protocol error. Static current Codex effort policy permits only minimal/low/medium/high/xhigh/max because the generated effort schema itself is open string. Codex reports no client-side cost, so its usage cost remains unknown rather than a known `$0`.

## Module responsibilities

Detailed responsibilities of the source files owning the behavior above:

- `src/backend/model.ts` — capability-oriented driver plus normalized readiness preflight, launch/event/handle/control, startup, bounded report-generation, and exit contracts for `local|herdr` × `pi|claude|codex` combinations.
- `src/backend/service.ts` and `src/layer.ts` — one shared backend registry, fail-before-ownership readiness resolution, and ordered composition of all six local/Herdr drivers. The composition root reuses one constructed backend Layer for service provision and its final merge so Layer memoization shares the registry.
- `src/backend/local-pi.ts` and `local-pi-protocol.ts` — Pi-specific native RPC correlation, usage, typed parent-contact mapping, correlated descendant-notification acknowledgment, normalized runtime events, and the single pure Effect Schema definition for native RPC plus both IPC directions.
- `src/backend/local-cli-events.ts` — shared raw wire-event ownership for the local Claude/Codex adapters: when one raw frame produces one or more normalized events, its transport ownership and byte budget stay attached through the final queued event until orchestration consumes it; adapter-internal events carry no raw owner, and a failed owning enqueue acknowledges the raw frame immediately.
- `src/backend/local-cli-interruption.ts` contains the pure shared Exit classifier for Claude/Codex interrupt ownership. Interruption-only causes and typed `interrupt_outcome_uncertain` failures retain ownership; success, definite failure, and defects release it. Each adapter still owns its own correlated terminal evidence and late-settlement behavior.
- `src/backend/local-claude.ts`, `local-claude-protocol.ts`, `local-claude-correlation.ts`, and `local-supervisor-prompt.ts` — Claude 2.1.220 stream-JSON initialization/native-init/MCP inventory validation, UUID-correlated replay/result confirmation, per-message-id usage deduplication with result-level usage/cost reconciliation, exact interrupt-marker/result lifecycle ownership (including late settlement after the public timeout), strict supervisor-report instructions, and MCP report ownership. `local-claude-correlation.ts` isolates the pure usage arithmetic plus the bounded sent-UUID window and result-expectation map/FIFO, including synthetic-origin selection that cannot consume ordinary UUID-less results; the handle retains report buffering, the ten-second grace, interrupts, control responses, the assignment epoch, and initialization.
- `src/backend/local-codex.ts` and `local-codex-protocol.ts` — generated Codex 0.145 app-server v2 JSON-RPC request/notification subset, authenticated helper-readiness gating, dual-evidence interruption, fail-closed unowned interruption, causal report-completion checks, current warning variants, usage/tool normalization, and MCP report ownership.
- `src/backend/claude-policy.ts` — pure foreign Claude CLI policy shared by local and Herdr harnesses: the scoped-Edit cwd rule grammar/types, fixed inspection/read/write/denied tool constants, strict sandbox settings interfaces/builder, allowed-tool logic, and the local Claude argv builder. It imports no Effect and no Node APIs; callers pass the boundary-prevalidated writer cwd policy in.
- `src/boundary/child-process.ts` — low-level local Pi native RPC spawn, fresh/fork setup, launch-time trusted-tool activation, private run-state reclamation, fail-closed process release, process-tree ownership, and typed contact-event integration.
- `src/boundary/local-pi-ipc.ts` — the sole parent/child raw Node IPC adapter. It validates both wire directions, bounds send callbacks, preserves definite-versus-uncertain delivery evidence, reports malformed child contacts, and detaches message/disconnect listeners idempotently.
- `src/boundary/claude-writer-cwd.ts` — narrow platform path adapter: the only owner of the absolute-path decision (`node:path`) before the pure Claude policy grammar builds one cwd/scoped-Edit rule pair for local and Herdr preflight/argv policy.
- `src/boundary/local-cli-harness.ts` — private local CLI harness/auth/config filesystem lifecycle: launch and catalog harness roots, sanitized environment and approved API-key selection, Codex config builders, failure-atomic Effect acquisition/removal with custom-source Codex auth-copy ownership, and cancelable bounded auth probes without an internal Effect runner. It owns no wire transport and never imports the `LocalCliProcess` service.
- `src/boundary/local-cli-transport.ts` — local CLI wire transport contracts and ownership: child spawn, bounded stdout/stderr/JSONL event queue with byte-budget backpressure, frame writes, `awaitExit`, and fail-closed platform-consistent process-tree termination/release. Adapters import `LocalCliWireEvent`/`LocalCliOutboundFrame`/`LocalCliHandle` from here directly.
- `src/boundary/local-cli-process.ts` — the reduced `LocalCliRuntime`/request/service door: preflight and probe orchestration plus `makeLocalCliProcess` and the stable Context.Service/Layer composition over the harness and transport boundaries; it re-exports none of their symbols.
- `src/boundary/writer-lease.ts` — package-local Node boundary for canonical launch paths plus stable device/inode directory identity, bounded/schema-decoded phase evidence, durable reserved→spawn-started marking, atomic same-host acquisition/dead-reservation takeover, liveness probing, and token-derived release tombstones under private agent-directory state. `src/run/writer-pool.ts`, `admission.ts`, and `record-cleanup.ts` own session pool membership, disjoint-claim admission, first-acquire/last-release ordering, and whole-pool quarantine.
- `src/supervisor/mcp-contract.ts` and `src/boundary/supervisor-channel.ts`, `supervisor-rpc-protocol.ts`, `supervisor-mcp-helper.mjs`, and `supervisor-mcp-helper.ts` — one import-free MCP semantic contract, backend-neutral Effect RPC v3 over scoped loopback Effect sockets, and the packaged erasable-TypeScript MCP stdio adapter/Effect RPC client consumed by local Claude/Codex and delegated Pi. The standalone helper owns one scoped `NodeRuntime.runMain` program, shares the bounded line parser used by the other JSONL boundaries, and commits exactly one response per tool call before its stdout writer closes ahead of active-call or socket cleanup. Accepted-report evidence remains queryable during native transport shutdown, and transport interruption cancels exact in-flight questions without destroying later assignments. The boundary returns adapter-owned connection and fixed MCP metadata; it is not registered as a public Pi tool.
- `src/boundary/host-child-pi.ts`, `pi-supervisor-bridge-client.ts`, and `host-pi-supervisor-extension.ts` — shared credential/priority request policy plus scoped delegated-Pi MCP bridge acquisition, Effect-native calls, current-runtime Promise adaptation, stale-tool guards, report coalescing/fallback, and runtime-owned call interruption/helper cleanup.
- `src/supervisor/protocol.ts` — shared Effect RPC definitions and schema-bounded transport contracts for authentication, assignments, contacts, questions, acknowledgements, reports, errors, and the normalized `supervisor_contact|report` event subset. It consumes MCP text/delivery semantics from `mcp-contract.ts` rather than owning a second copy.
