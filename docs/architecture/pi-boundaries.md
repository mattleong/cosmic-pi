# Pi and platform boundaries

Effect application code is separated from APIs that Pi or third-party libraries require in another shape.

## Approved boundaries

### Pi registration

Extension factories only register callbacks; they do not acquire background resources. `session_start` creates one managed runtime for the started session, and callbacks delegate to it. A callback may pass Pi's `AbortSignal` to the runtime. The runtime is never recreated per event or command. Runtime creation cannot be owned by the runtime being created, so `pi-cosmic-core` provides one small host-boundary session slot for generation checks, replacement, abort-listener removal, and idempotent disposal; it owns no application polling or state.

### Shutdown

The Pi lifecycle boundary disposes the runtime and interrupts session fibers. Finalizers own timers, subscriptions, streams, file handles, HTTP agents, child sessions, and cached resources. Cosmic UI materializes the session CWD and AbortSignal capability through its bounded host-callback boundary before mutating or replacing the prior session. Capture first installs an owned native `AbortController` forwarder and only then reads the source's initial aborted state, so an abort cannot be lost before runtime registration. Pi's agent-run signal is turn-dynamic and commonly absent at `session_start`, so every checkpoint separately captures the current run signal at synchronous admission and retains that exact capability for cancellation listening and post-provider delivery checks. Capture failure shuts down the prior slot instead of leaving stale work alive. Deactivation, failed or superseded startup, and short-lived event work release source listeners exactly once. Cosmic UI generation-checks delayed shutdown and failed-start resets, so old cleanup cannot clear replacement context, totals, footer contributions, or projections. Cosmic UI and Better OpenAI also revoke a session-owned publication flag synchronously on deactivation. Late durable commits may update private state, but cannot restore cleared projections or invoke retired repaint/notification callbacks.

### User dialogs

`pi-ask-user` adapts Promise-shaped RPC dialogs in `host-dialogs.ts` and TUI overlays in `host-tui.ts`. RPC calls receive Effect-owned abort signals. TUI async tools wait for the mount acknowledgement, never the answer; a session-scope presenter owns the answer Promise and domain cleanup independently of tool interruption. Pinned Pi mounts after factory return and its custom `done` pops the global overlay stack. Cosmic UI's shared owned surface (below) holds pre-mount finishes, removes only the owned handle, synchronously adds an inert noncapturing guard, calls `done`, and removes the guard in `finally`. This public-API workaround protects unrelated stacked overlays and can be removed once pinned Pi closes by identity. The synchronous dialog bridge retains only a token-checked resume capability and status, with no hidden raw input listener. `host-delivery.ts` adapts void-returning custom-message steering; successful return is not delivery acknowledgement. Retained results and stable delivery IDs support recovery. Session/tree replacement revokes send authority. Before sending, the boundary synchronously appends a versioned custom-entry receipt to the originating branch. Context filtering admits current-generation messages or generation/delivery pairs backed by receipts on the active branch, never by answer messages alone. Repeated navigation cannot promote a stale queued message. Other extensions' queues remain untouched. Coalesced public UI-prompt events gate async admission, with a second guard after the lazy import, run by the surface's admission hook in the same synchronous frame as `ui.custom`; closing the owned dialog does not clear an unrelated nested prompt's activity.

Ask User revokes callbacks and editor admission synchronously at finalization, then joins every admitted editor's process, temporary-file, and TUI-restoration cleanup before releasing the dialog permit or transferring the session. It does not await an arbitrary `ui.custom` Promise. Late editor settlement cannot update the revoked dialog.

### Native codemode and tool search

Pi owns native `codemode` execution, tool dispatch, cancellation, and result handling. `pi-code-previews` supplies renderer-only callbacks through one factory-time public resolver after exact `builtin:codemode` metadata admission. It never calls or intercepts the native factory, replaces its execution definition, or enables an excluded or inactive tool. Later MCP activation needs no presentation reload. The custom `pi-code-mode` process runner, settings surface, retention service, and cross-extension adapters are retired.

Native `tool_search` presentation requires exact `builtin:tool-search` public source metadata and its captured preview-tools selection, independent of activation. Bounded own-data `details.loaded` receipts supply neutral listing counts, not current availability or domain success. Expansion keeps all arguments and output/recovery text; Pi keeps native images. The renderer reuses first-ready replay and the originating scheduler, never registers execution, reads artifacts, searches tools, or activates matches. Native search alone owns discovery and activation.

`pi-subagents` runs dynamic workflow scripts in an in-process `CodemodeSandbox` from `@earendil-works/pi-codemode` (`src/boundary/codemode-sandbox.ts`). Pi's package owns that VM; the runner applies Pi's own 256 MiB codemode memory bound. Workflow scripts get no Pi tools; the sandbox exposes only the runner's `__workflow.agent`, `event`, and `load` members, and the runner owns cancellation through the run's scope. An outer native codemode script may call `subagent_workflow` only while Ultracode activates its direct registration. Its separate success-only `pi-subagents/workflow` v1 contract preserves start receipts and authoritative status/list/stop observations. Workflow agents retain ordinary writer authorization, claims and worktree-review requirements, unlike native `subagent_start`'s read-only tree policy. Ending or aborting the outer script does not undo an admitted workflow; start is not completion, and terminal workflow state is not child-cleanup confirmation.

### Synchronous TUI rendering

Cosmic UI's `boundary/host-viewport.ts` reads live terminal dimensions for one custom UI opening. Its retained options getters and component height callback share the pure `manager/viewport.ts` calculation. Pinned Pi 1.0.2, unchanged since 0.86, evaluates the options factory once at mount but reads retained properties during rendering, so hosts must pass the options object without copying it. The adapter owns no listeners, runtime, focus, or cleanup. Embedded children consume allocated dimensions; compact dialogs retain natural height within the allocation. Pi 1.0 runs fullscreen by default: overlays still compose over the whole terminal, but widgets, inline editor-slot surfaces, and the footer share a bottom dock that shrinks to fit the terminal, and a component taller than its share is clipped from the bottom, except that the visible window follows a line carrying the cursor marker.

Cosmic UI's `boundary/host-surface.ts` owns one `ctx.ui.custom` opening for questionnaires, the Activity manager, `/tasks`, the `/subagents` fleets and profile dashboard, `/code-previews health`, and every inline settings picker. It owns the factory and done latches, the finish held until `onHandle`, admission beside `custom`, the external close handed out before `custom`, dock and viewport placement, and the pinned-Pi guarded close; inline surfaces call a guarded `done` directly. Callers keep domain lifecycle and error wording; a command's own view opens through `openCommandSurface`, which rejects a failed opening, and other Promise callers map a failed opening themselves. Core's `host-command.ts` registers each extension's one slash command and routes and completes its subcommands. Cosmic UI's `boundary/host-settings-command.ts` builds the shared `settings` subcommand for Cosmic UI, Code Previews, Background Task, Subagents, and Better OpenAI: it owns completions, `help` and `status`, optional scopes, guarded diagnostics, validation messages, signal capture, the shared apply, and the inline settings list with its guarded host callbacks, while each extension keeps its rows, persistence call, and after-apply refresh. Better OpenAI and Cosmic UI capture originating-session authority per settings invocation through `withInvocationAuthority`; the shell checks it beside every apply, delayed notification, picker display, and after-apply callback without reshaping Pi's context. Native `/mcp` keeps Pi's server management interface.

Pi render methods remain synchronous. Better OpenAI, Cosmic UI, and code-preview services own state transitions and publish deeply frozen plain snapshots; their renderers read synchronous projections. Cosmic UI has one narrow live-data exception for Pi's synchronous footer, session, model, thinking-level, and context-usage getters. Each value is materialized through core's `invokeHostCallback` with a neutral fallback before layout code uses it. Code previews expose one narrowly documented exception: the current Shiki highlighter is a third-party synchronous render capability paired with immutable generation/theme/language metadata. Initialization, language loading, callbacks, replacement, and disposal remain Effect-owned. The render cache belongs to one highlighter object and theme pair. Releasing a stale highlighter cannot discard a newer owner's cache. Synchronous renderer entrypoints should not import Effect runtimes, full services, or session capabilities. A renderer must not build a Layer, read an effectful Ref, or run an Effect.

### Tool renderer installation

`pi-code-previews` requires Pi 1.0.1 or later and is tested with 1.0.2. It registers one stable `pi.registerToolRenderer` resolver during factory loading. Session starts publish an originating presentation owner after trusted settings load, never accumulate resolvers. Public `getAllTools`/`getCommands` metadata controls exact builtin admission; only public renderer fields from `next()` are retained. Siloed `third-party/` adapters have a separate static registry and exact public package/source/name admission. Supported npm-installed `pi-web-access` names receive renderer-only composition; missing, duplicate, renamed, or unsupported ownership stays downstream. External execution and activation are untouched, and no provider import or filesystem discovery is involved. Settings choose builtin/codemode presentation, not execution or exposure. Native factories and managers are neither composed nor intercepted.

Write alone registers a real execution hook for before-write evidence under Pi's mutation queue. It accepts only builtin or proven prior package ownership, preserves inactive selection through `defaultActive`, records attempted ownership before mutation, and records successful installation after registration returns. A refresh failure after mutation remains retryable without foreign takeover. Discovery failures stop startup; a bounded write registration error leaves other presentation and its runtime available.

Workspace-owned tools that register during `session_start` use the public `registerCodePreviewReplay` bridge in their own factories. It registers only a resolver, stages normal and fixed-self-shell variants from the same trusted settings, and publishes renderer fields only after the tool's public source matches the owning extension's unique command. Readiness is first-startup-only; failed/aborted startup closes adoption, shutdown retires it, and later rows fall through to current registered definitions. Each owner retains its existing mode gates, execution registration, activation/exposure, and token-checked scheduler. Async questionnaire answers and OpenAI image custom messages register their service-free renderers at factory time too; per-render presentation policy stays separate from gated tool registration and message delivery authority. `/reload` and session replacement reconstruct history before startup, so tests exercise the same retained row rather than resolving a fresh renderer after registration.

`withCodePreviewRenderers` in `tools/cooperative-tools.ts` is the one renderer composition, shared by the owned-definition `withCodePreviewShell` and builtin/native renderer factories. It captures shell appearance, calls supplied renderers unbound, and does not require execution/schema for renderer-only use. Owned-definition wrapping preserves those fields. Pi's mandatory `ToolRenderContext` shape remains derived from `ToolDefinition` because the root does not re-export that named type.

`application/renderer-row.ts` retains replay calls/results behind a fixed self shell before startup; rows resolved after readiness use ordinary renderers in Pi's own shell. Cold fallback preserves downstream self-shell content or reproduces Pi's default background. First-ready adoption reconstructs complete retained arguments and results with the originating owner's captured appearance. Owner retirement synchronously revokes/cancels its scheduler before Effect disposal; old rows cannot borrow replacement settings or animation authority. `selfShell: true` preserves this framing for every appearance mode, using a combined native-like background in preview/on.

The [tool presentation standard](tool-presentation.md) governs every workspace-owned visible tool. `toolCallCollapsedStyle` defaults to `preview`; trusted settings load before wrapping, and wrapping captures style until reload. Compact tools use Pi's fixed `self` shell. Pure `planCompactPresentation` owns generic fallback and outcome reconciliation, never domain classification. Ordinary collapsed calls have one semantic heading; all retained children contribute attention before row selection. Unknown outcomes never become success merely because Pi returned without an error flag.

In compact expansion, opted-in content callbacks supply unique arguments, source, diffs, output, or reports beneath one shared heading. Each omitted callback keeps its original slot. Valid semantic summaries use content callbacks; malformed or missing summaries retain original rendering. Preview style retains original callbacks.

Component failures use safe raw output without replaying renderers. Original and content-only slots keep independent `lastComponent` caches; shared state, invalidation, mouse routing, and scoped timing remain intact. Operation identities are not default display labels. Rendering never changes execution, approvals, result bytes, native images, or the host transcript separator.

Built-in compact summaries apply to eligible `read`, `bash`, `write`, `edit`, `grep`, `find`, and `ls` renderer presentation. Cooperative tools may supply a semantic summary provider. Missing or declined providers use generic compact rows with full details on expansion and never imply domain success. Cooperative hosts also compose the public `CodePreviewSchedulerService.layer` into their own session runtime and pass a token-checked `scheduleAnimation` callback. Pi's isolated Jiti loaders do not share the previews extension's module-local capability. The same injected scheduler drives compact icons and ordinary preview duration refresh; replacement/shutdown disposes its fibers, and unavailable scheduling is not cached as an active subscription. `preserveSelfShell` applies only to preview mode; compact mode wraps all cooperating tools. Neither compact mode nor its settings change active tool selection, execution, approvals, result contents, or native images. Pi's host-owned blank separator and separately rendered native images are outside the extension text-row budget.

### Tool schemas

Pi tool parameter declarations may use TypeBox or literal JSON Schema. Tool output declarations are generated from authoritative Effect Schema contracts; producers encode structured results with the matching codec. Core's shared pure adapter, `toPiToolOutputSchema`, makes that generated JSON Schema self-contained for Pi; Subagents, Background Tasks, Ask User, and Better OpenAI use it rather than package-local copies. The Effect schema remains authoritative, and the generated JSON Schema is only its declaration for Pi. Tool execution delegates to Effect immediately. This exception applies to schema representation, not implementation logic.

### Third-party libraries

Promise/callback libraries such as Pi APIs and Shiki are wrapped once with the appropriate Effect constructor in a named adapter. Their native errors are translated into typed domain failures.

Sharp runs only in Better OpenAI's fixed packaged `src/boundary/sharp-decoder.mjs` helper through core's opt-in bounded process adapter. No build, shell, caller argv, or caller environment is required. Parent and child cap input at 60 MiB. The child decodes all pages under a 40-million-pixel limit into uchar sRGB raw data with at most four channels; cache is disabled and concurrency is one inside the child. Only bounded, schema-decoded format JSON returns, never pixels, stderr, or native errors. One module-private immediate semaphore rejects busy calls across runtimes rather than queuing image buffers.

The permit covers process scope closure. A 30-second execution deadline requests process termination, with a two-second cleanup-confirmation budget and forced SIGKILL fallback. Sharp's cooperative raw timeout is secondary; stream destruction is not native cancellation. Core explicitly reports exit confirmation through a cleanup callback on success, interruption, and failure, including uncertainty during incomplete acquisition. This is necessary because the pinned spawner can swallow kill failure. Unconfirmed cleanup disables decoding until process restart. OS exit failure can prolong scope closure beyond these budgets while ownership and admission remain held. These work limits are not an OS memory sandbox.

### Native MCP presentation

Standalone native MCP presentation now belongs to Code Previews' same stable renderer resolver, independent of builtin/codemode preview selection and with no startup toggle. Existing tools/resources require exact builtin MCP source metadata. Missing historical aliases require a unique independently builtin-owned `/mcp` manager and remain conservative; ambiguous names never acquire guessed remote identities. Foreign definitions fall through to downstream renderers.

Pi alone owns `/mcp`, its lifecycle, configuration, authentication, connections, execution, activation, exposure, permissions, results and native images. Code Previews never calls or intercepts `createMcpExtension`, registers the manager or MCP execution definitions, or edits user configuration. The standalone `pi-mcp-previews` package is retired; previously installed copies must be removed manually from every scope and Pi reloaded.

The retired `pi-mcp` gateway, SDK adapters, schema-validator process, Keychain store, retention services, and private Ask User continuation integration have no compatibility layer. Migration is manual; see [native MCP and codemode migration](../migrations/native-mcp-codemode.md).

### Cross-extension events

Cosmic UI events carry plain data and explicitly checked function capabilities. Providers import the narrow `pi-cosmic-ui/protocol` and `pi-cosmic-ui/client` subpaths, never the extension root. Events never carry Effect services, Layers, refs, scopes, fibers, or runtimes. The host answers discovery synchronously and applies footer events synchronously to its keyed contribution store, which publishes only a frozen contribution snapshot. An event emitted during another operation queues behind it, with at most 128 reentrant operations per outermost operation. While no session is active the store keeps at most 128 distinct keys, evicting the oldest; a session that activated clears it on deactivation. Hostile callbacks are isolated behind a fallback, and callback errors and payloads are never retained.

The activity protocol uses a host-activation nonce and producer registration identity in addition to the stable session ID. Widget availability is acknowledged only after successful installation and revoked on disposal. Producers retain their fallback UI until acknowledgement. Action and lazy-detail capabilities recheck generation and revision, receive an abort signal, and return bounded redacted content. Cosmic UI owns the manager overlay through the shared owned surface; closing it cannot pop a newer questionnaire.

Ask User owns a bounded FIFO shared by blocking, async, and explicitly routed Pi-child questionnaires. Child relays carry structured requests through the authenticated subagent coordinator, which supplies assignment ownership. Parent-agent coordination questions remain separate. The root capability exposes exact-owner cancellation acknowledgement, so subagent cleanup joins questionnaire/editor finalizers without making the answer wait uninterruptible. Native supervisor and async child questionnaires are not routed by this protocol.

## Cryptographic boundaries

Core owns synchronous Web Crypto entropy/UUID generation for Pi callbacks and indivisible native ownership commits. SHA-256 text identities use a pure UTF-8 implementation so existing persistence keys, leases, and replay hashes do not gain an asynchronous gap. Supervisor authentication instead uses Effect-owned native HMAC verification; it rechecks logical shutdown and connection revocation after the native wait and before publishing authentication. No Node crypto import is hidden through reflection, and no diagnostic severity is reduced for these boundaries.

### Code-preview settings, syntax, write, and deferred-render boundaries

The settings service contract is `load`, `save`, and `flush`. Code Previews reads no MCP startup settings; renderer-only MCP presentation leaves all native resources and lifecycle callbacks independently owned by Pi. Each service keeps one complete save context in a private `Ref`; building its Layer does not publish settings. A process-local coordinator uses one module-level semaphore and monotonic admissions to serialize work across live and one-shot runtimes. Publication currency advances only after a successful publication. A failed or interrupted newer operation therefore cannot suppress an older success. Loads update private state and publish conditionally while returning defensive clones. A one-shot save rehydrates and saves under one permit without publishing the intermediate load. A stale save exits before `modifyObject`, and global `flush` waits behind work from every Layer. Atomic replacement keeps lock order coordinator, document lock, then the lock-free `afterCommit` Ref update and conditional publication. Interruption cannot leave the renamed document ahead of the renderer projection. The syntax service contract is only `initialize`; status comes from the synchronous projection, while replacement and finalization stay private to the scoped service.

The write service contract is `rememberBeforeWrite`. Before-write correlation is owned by a serialized Effect projection. Tool result rendering performs a non-destructive lookup in a bounded, deeply frozen snapshot, so duplicate renders and call-ID reuse remain deterministic until eviction or scope cleanup. Write admission captures the originating token-bound session capability. Native Pi write owns path resolution, the canonical cross-tool mutation queue, and abort checks around its operation callbacks. There is no outer queue wrapper or package-local `withPathLock`. The captured runtime owns the interruptible queue wait; cancellation, replacement, or shutdown aborts the native invocation without waiting for its held predecessor. Pi's delayed queue entry checks that signal before invoking any operation. Native codemode dispatch belongs to Pi's tool pipeline.

`boundary/host-write.ts` bridges Pi's Promise-only operation callbacks into scoped Effect workers using the invocation's services and scope. Its callback Promises join those workers without an abort signal, keeping Pi's queue held until admitted masked work settles. Directory creation is masked separately. The before-read remains interruptible after native queue admission; the write callback then checks abort before its masked direct write and correlation commit. An applied write publishes matching before-write evidence before interruption becomes observable. Direct mutation preserves Pi's symlink, hard-link, inode, and open-descriptor semantics without introducing an atomic replacement.

`DeferredPreview` uses accurately named deferred same-thread publication. No worker was added: the checked baseline used five `bench:render-boundaries` runs whose representative 250-line diff CPU medians were 6.109–6.346 ms (committed median 6.329 ms) and cancellation publication medians were 2.653–3.033 ms. The harness now performs three warmups plus nine raw timed samples, reports both sample lists and medians, and fails when the diff median exceeds the committed baseline by more than 10%; absolute 50 ms CPU and 100 ms cancellation budgets remain secondary responsiveness guards. The work is pure but a live Theme/TUI result and Shiki capability are not serializable; worker transfer would add complexity without an observed responsiveness problem. Reconsider only if profiling exceeds the blocking budget and a serializable preparation phase improves it without more than a 10% median render regression.

### Remaining unsafe Effect calls

The remaining unsafe Effect calls are localized and documented. Process-global `Semaphore.makeUnsafe` values appear only where independently built runtimes must share admission. The core keyed process coordinator serializes access to the same resolved file and removes idle key entries after their final users exit. Its registry-reference claim is masked through release-handler installation, then interruption is restored for permit waiting and caller work. The code-preview settings coordinator uses one private permit across live and short-lived Layers. Better OpenAI's Sharp boundary adds one module-private immediate semaphore across runtimes. The shared core synchronous-ingress adapter owns exactly one `Queue.offerUnsafe` call and exposes only bounded plain-data results while a scoped Effect fiber drains work. Ask User's `host-tui.ts` uses one `Deferred.doneUnsafe` call at Pi's synchronous `onHandle` callback. Validated `DateTime.makeUnsafe` conversions are likewise intentional integration points that should remain narrow.

## Forbidden internal boundaries

Application services must not:

- call `Effect.run*` or a managed runtime,
- construct unmanaged Promises or timers,
- use global fetch or direct filesystem I/O,
- expose native `Error` or `unknown` in an Effect error channel,
- leak implementation service requirements through public methods.
