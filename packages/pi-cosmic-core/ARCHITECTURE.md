# Cosmic Core architecture

## Purpose

`pi-cosmic-core` is publishable infrastructure shared by the extensions. It does not register a Pi extension and contains no provider- or feature-specific orchestration. Its public barrels and `src/` tree ship as TypeScript and load through Pi/Jiti; there is no generated distribution or plain-Node package contract.

## Public surface

- Package root: managed runtime/session slot, Pi service, projections, refresh/ingress coordination, typed platform/config adapters, the Pi tool output-schema adapter, security helpers, and subscription formatting compatibility.
- `pi-cosmic-core/testing`: deterministic HTTP/document/lifecycle/telemetry test Layers, paused and interrupting scheduler fixtures, bounded worker polling, and a fake `taskkill` helper for the Windows tree terminator. `host.ts` holds the SAFETY-cast Pi host fixtures (`extensionApiFixture`, `extensionContextFixture`, `opaqueFixture`), the frozen identity `plainTheme`, the hostile `failingTheme`, and `deferredPromise`, with only type imports from Pi. `extension-host.ts` holds `recordingExtensionHost`, Pi's registry as one loaded extension sees it: multi-handler sequential event dispatch, commands, tools with default activation, sourced `getAllTools`/`getCommands` metadata, and the tool-renderer resolver chain. `steps.ts` holds the runner-neutral Promise steps and a `macrotask` flush, and `gallery.ts` the presentation-gallery directory and section writer. `ipc-child.ts` holds the real-process harness: `temporaryDirectory` and `spawnIpcChild`, which runs a TypeScript fixture through `jiti/register`, records IPC messages from spawn, drains stderr into a bounded tail, bounds each wait (a timeout reports the messages received, exit status and stderr), and kills the child on scope close. In-memory documents record each executed public store call as `operation:path` in `operations`.
- `pi-cosmic-core/testing/sdk`: real Pi SDK sessions with faux inference for end-to-end tests: offline in-memory models, quiet settings and resources, a scoped print-mode session (abort, then `session_shutdown`, then dispose), and `fauxCodemodeSession`, which loads one extension beside Pi's builtin codemode and drives one faux tool-call turn per `call`. It is a separate entry because it imports Pi's SDK and `@earendil-works/pi-ai` values, which the main testing entry avoids.

## Source map

- `src/runtime/` defines Pi-owned execution boundaries (`runtime.ts`, `session-runtime.ts`, `pi-api.ts`) plus `host-bootstrap.ts`, the shared `Effect.tryPromise` adapter for best-effort Promise prerequisites. The package root exports Effect's scoped `provide` unchanged as `provideBuiltLayer` for host and test entry points. The session slot returns Effect-owned startup values only to the current activation and exposes activation state without duplicating package-local flags. Host bootstrap forwards Effect's abort signal, detaches loaders that ignore cancellation, contains late settlement, and records a redacted debug diagnostic on failure.
- `src/coordination/` provides scoped concurrency primitives (`refresh-coordinator.ts`, `subscription-refresh.ts`, `synchronous-ingress.ts`). The single-flight refresh coordinator transitions ownership and its one merged follow-up through atomic `Ref` updates. Registration through cleanup installation is masked; owner work and joiner waiting remain interruptible. Identity-checked cleanup settles the shared Deferred and permits reuse even when admission is interrupted. Subscription polling uses an Effect v4 `Latch` pulse, so `release` wakes only pollers already awaiting it and does not retain early wakes. An owner's interruption replayed to a joined poller does not end polling; only the poller's own interruption does. Subscription validation, commit, and consumer invalidation state changes share a fiber-reentrant transactional lock. Invalidation keeps its non-retained wake pulse. `listeners.ts` holds `notifyListeners`, which delivers to a snapshot, skips listeners removed mid-delivery, and contains throws.
- `src/platform/` contains typed Node, HTTP, document, file, process-coordination, bounded child-process, and agent-directory adapters. `process-coordinator.ts` is a module function, `withProcessLock`, over a process-global keyed registry, so `JsonDocumentStore` serializes each resolved path across independently built Layers without a service requirement. Registry admission stays masked through release-handler installation; permit waiting and caller work remain interruptible, and the final user removes the key. `shell-process-names.ts` is the pure interactive-shell process-name classifier used by process readiness checks. `nodeProcessLayer` is an opt-in capability and is never merged into the file or network platform Layers. `node-builtins.ts` is the single raw Node builtin door (`process.getBuiltinModule`) for SafeFile's `O_NOFOLLOW` opens and bigint inode identity checks, pure synchronous containment helpers, and the Windows `taskkill` spawn; Effectful SafeFile normalization uses the injected `Path.Path` service. `process-tree.ts` owns process signalling and the Windows tree terminator. `signalProcessGroup` and `signalProcess` never signal a pid that is not a positive safe integer and classify the result as present, absent (ESRCH only), permission (EPERM), or failed; each core call site keeps its own policy for those results. `terminateWindowsProcessTree` runs a bounded `taskkill /T [/F]`: an error event always fails, a nonzero exit counts as success only when the caller's `targetExited` says the target has already exited (checked when the Effect runs, which also skips the spawn), and interruption or the deadline synchronously detaches, adds a late-error listener, sends SIGKILL, and unrefs without awaiting the helper. `ProcessTreeError` messages carry only a bounded errno code. Callers own graceful/force policy, POSIX leader fallbacks, and their error mapping. The bounded process adapter exposes normalized exit evidence and owns detached spawning, output limits, process-group termination, force escalation, and scoped cleanup. Its optional `onCleanup` observer receives explicit exit confirmation during scope finalization on success, failure, and interruption. Kill success alone is insufficient; confirmation checks the acquired handle's exit-backed running state. Failed acquisition reports uncertainty because the platform may own a child before returning a handle. Confirmation has a deadline, but the platform's subsequent finalizer may still wait for OS exit. Atomic JSON modifications may return `write: false` to complete a lock-protected comparison without creating or rewriting a document or running an after-commit hook.
- `src/http/headers.ts` owns pure case-insensitive header merging used by OpenAI compaction. Later sources win with their casing; null deletes a header without mutating inputs. Provider schemas stay in their packages.
- `src/config/` contains the scoped configuration store, the shared config-error factory (`document-ops.ts`), and tolerant-field decoding. `makeScopedConfigStore` is core's single scoped resolver: existence alone decides project precedence, so a malformed project document still wins `configPath`; an untrusted project path gets no exists or read call; an unreadable document logs a warning and contributes no values. The store takes the package's tagged error class and derives its "Unable to <operation> <label> configuration." factory. `resolveCommittedConfig` derives the committed scope from `current.configPath`. `commitPreferredScope` is the shared atomic settings commit: it reads the global document as the overlay fallback for a project commit (optionally tolerating an unreadable one with a warning), then runs the change, resolution, and `afterCommit` inside one `modifyConfig` commit. pi-subagents, pi-code-previews, and pi-directory-models keep their own resolvers and trust gates.
- `src/schema/decode.ts` owns `decodeUnknownOrUndefined`, the one tolerant decode for untrusted values: schema mismatches, hostile getters and proxies, and decode defects all yield `undefined`.
- `src/schema/tool-output.ts` owns `toPiToolOutputSchema`, the shared pure adapter from an authoritative Effect schema to a native Pi tool `outputSchema`. pi-subagents and pi-background-task use it. It moves Effect's generated draft 2020-12 definitions under the root `$defs`, rejects any `$ref` that is not a direct local definition with `ToolOutputSchemaError`, and returns a deeply frozen value. The JSON Schema describes the encoded side of `Schema.toCodecJson(schema)`, and producers encode `structuredContent` with that codec. It is only a declaration for Pi: decoding, encoding, and validation stay with the Effect schema, and tool policy and execution stay in the consumer.
- `src/text.ts` owns pure string budgets: `safeTextPrefix`/`safeTextSuffix` never split a surrogate pair, and `utf8Prefix`/`utf8Suffix` take the longest code-point prefix or suffix within a UTF-8 byte budget. Their per-code-point sizes agree with `utf8ByteLength`, including three bytes for a lone surrogate, so callers can account kept and dropped bytes exactly.
- `src/projection.ts` serializes private authoritative `Ref` transitions with a private `Semaphore`. Lock waiting, update work, and projection preparation remain interruptible. External publication, internal snapshot publication, and the backing `Ref.set` share one narrow uninterruptible commit. Rejected preparation or publication leaves state and the internal snapshot unchanged. Snapshots reject non-finite numbers and true object cycles with typed paths while preserving acyclic shared references.
- Core code uses exact `effect/Predicate` variants where a named refinement helps. `src/runtime-values.ts` keeps the public object-or-null guard and runtime type-name classifier as direct `typeof` compatibility helpers.
- `src/security.ts` owns shared redaction/plain terminal sanitization. Its JWT helper decodes only the second segment with Effect `Base64Url` and `Result`, accepts padded or unpadded Base64URL, ignores later signature segments, and returns `undefined` for a missing or invalid payload. `extractJwtClaim` layers a from-string payload schema on that helper and `redactedTokenSchema` builds the shared `Redacted` OAuth-token field schema with a caller-provided label. `src/security/terminal-styled.ts` owns linear per-channel parsing and bounded safe visual-SGR preservation for terminal log UIs that must strip every active control sequence.
- `src/settings-completion.ts` owns pure `/<extension> settings` argument completion (`completeSettingsArguments`): descriptor-ordered id matching, caller-supplied extra verbs, case-insensitive prefixes (ids match case-insensitively in both stages, and value completions carry the canonical id that dispatch matches exactly), and the `null`-on-no-match host contract. It also owns the write-side settings family: `SettingsOptionDescriptor` with its JSON-string field schemas, the `InvalidSettingError` contract, and the `decodeSettingUpdate` factory that decodes one settings update into a document patch (`sectionSettingValue` composes the dotted-id patch). `makeUsageSettingDescriptors` owns the three shared subscription-usage descriptors over the type-only `SubscriptionUsageConfig` and accepts the provider-specific visibility description. Provider schemas, defaults, and clamping stay in each provider package. It has no UI dependency.
- `src/settings-dispatch.ts` owns pure `/<extension> settings` argument dispatch (`dispatchSettingsCommand`): a closed OpenInteractive/Help/Status/Apply/Invalid tagged result with exact finite-value matching and no hidden verb aliases. Callers own all side effects and message wording; provider settings share Cosmic UI's `pi-cosmic-ui/boundary/host-settings-command` shell. It has no host dependency.
- `src/subscription-format.ts` owns shared subscription countdown/percent/token/status-line formatting helpers.
- `src/host-session.ts` owns pure Pi host session capture helpers (UI mode, trust, cwd/signal). Trust fails closed unless a captured callback returns literal `true`; absent, malformed, false, or throwing host values are untrusted. `invokeBestEffort` contains synchronous callback failures and passes the result to `containThenable`, which reads `then` exactly once and attaches no-op handlers to a returned object or callable thenable. Best-effort notifications and the session slot's activation, deactivation, and start-failure hooks use it.
- `src/host-command.ts` registers each extension's one slash command (`registerExtensionCommand`) and owns its pure subcommand routing, completion, overview, and usage line. Subcommands can be added or replaced by name after load, such as one that needs a session; handlers run synchronously and a throw becomes a rejected command.
- `src/session-capability.ts` owns both sides of the synchronous `{ version, sessionId, respond }` session-capability event query. On the provider side, `makeSessionCapabilityProtocol` decodes each hostile query once with a non-empty, optionally bounded session id and a function `respond`; a normalized `respond` is best effort. On the consumer side, `querySessionCapability` emits one query and collects the candidates the caller accepts until `emit` returns or an optional limit is reached; a throwing `emit` or acceptance marks it failed. Owning packages keep their host listeners and gate order, candidate checks and selection policy, and public protocol names.
- `src/usage-projection.ts` owns shared usage eligibility/clearing projection transitions. `src/usage-controller.ts` captures exactly the shared `Path.Path`, `JsonDocumentStore`, `JsonHttpClient`, and `Tracer.Tracer` services in one explicit `Context` pinned onto effects that escape the construction Layer. `UsageRefreshControllerOptions` intentionally takes a provider-only `Context`. The captured shared context is merged second so it overrides provider key collisions; the controller never captures the whole ambient context. Its store option is the `ScopedConfigStore` operation subset the controller uses, and settings updates commit through `commitPreferredScope`. `formatUsageDebugReport` reads the shared projection fields and takes only provider identity, endpoint, and interval details. `synchronizeState` is optional: when omitted, the controller composes eligibility with `withUsageEligibility` and its `hiddenStatusText`. `timedDiagnosticResult` bounds one provider diagnostic fetch at the shared 10-second deadline and maps failures and timeouts onto a sanitized `Result<A, string>`.
- `src/usage-controller.ts` accepts the presentation owner's background-request policy independently of provider config. Hidden usage skips automatic requests; explicit notified requests still fetch. Visibility participates in the refresh key, preventing late results from restoring hidden usage. Core owns no custom-footer renderer. Context clearing and durable config installation run under the refresh commit gate. Refresh commits never acquire settings/document locks; persistence acquires those before its gated `afterCommit` installation. An originating-session publication callback guards each boundary snapshot and actual host notification; retired private/durable commits may finish without restoring cleared projections.
- `src/security/sha256.ts` owns pure SHA-256/UTF-8 identities via the directly declared `fast-sha256` dependency, preserving synchronous persistence keys and replay diagnostics. `src/platform/native-crypto.ts` owns Web Crypto entropy and UUIDv4 formatting for synchronous Pi callbacks and native ownership commits; Effectful callers capture failures at their existing typed I/O boundaries. `src/platform/token-verifier.ts` creates private non-extractable HMAC keys and verifies complete secrets through native Web Crypto, with typed redacted failures and interruptible waits. No cryptographic operation uses a reflected Node import or an internal Effect runner.
- `src/testing/` contains multi-consumer fakes and probes only.

Public barrels (`index.ts`, `testing.ts`) re-export these modules; consumers import from `pi-cosmic-core` / `pi-cosmic-core/testing`, not internal paths.

## Cross-process ownership

`CrossProcessLock` is an opt-in same-host capability, separate from file and network Layers. Callers supply the actual shared resource namespace, not a session or agent directory, and own a private root through `directory`; exclusion covers only callers sharing that root. `tryAcquire` is its only door: one synchronous, non-waiting attempt that retires a dead quiescent owner and retries once, so `undefined` means a live owner holds the slot. Its caller owns the returned lease, including release. A `recovery-required` failure at admission names the `slot` directory that needs manual recovery, such as a dead owner's pending native work or damaged evidence. The Node boundary validates ownership, permissions, bounded schema records, and no-follow file opens. Short synchronous filesystem commits use `node-builtins.ts`; callers own any retry policy.

Acquisition fsyncs a complete nonempty candidate before atomic publication. A failed post-publication durability check retires that exact quiescent owner before failure. Recovery requires positive PID-death evidence and a quiescent journal, never heartbeat age. Dead-owner recovery leaves a nonempty `.retired-<token>` barrier to prevent a stale reclaimer from moving a successor. Normal release instead uses `.released-<token>` and attempts validated deletion of only that exact owner's record and directory. Successful normal transactions leave no growing release history; failed cleanup may leave a released artifact. Old `.retired`, token-specific recovery barriers, crash candidates, and malformed artifacts remain. There is no online garbage collector, count threshold, or global storage bound.

A lease journals native mutation admission before an uncancellable call. Interruption retains ownership until the actual native completion callback clears the journal and releases the exact owner. A dead `native-pending` owner fails closed. PID death, elapsed time, and a new login do not prove that a separate native service settled. Offline maintenance must stop all participating processes and reclaimers, inspect artifacts individually, and independently establish native settlement before touching pending evidence. Do not erase the lock root or active, malformed, or native-pending evidence as routine cleanup. Core has no reset CLI and cannot automate settlement proof. Callers own durable credential quarantine and recovery messaging; deleting coordination evidence cannot replace that quarantine. Private metadata contains no credential values.

## JSON documents

Every JSON-document store implements the atomic `modifyObject` alongside `exists`, `readObject`,
and `writeObject`. The in-memory adapter uses the same codec. Feature stores own
structural/schema validation.

## Dependency rule

Core may depend on Effect and platform libraries, but never on an extension package. Extension-specific policies, controllers, UI, session harnesses, and provider schemas stay in their owning package. A helper moves here only after multiple packages require the same contract.

## Lifecycle

```text
Pi session adapter -> makePiManagedRuntime -> application Layer
                  -> makePiSessionRuntimeSlot for replace/start/dispose
scoped services -> finalizers interrupt fibers and release resources
Effect state -> frozen projection -> synchronous host renderer
```

Pi owns the TTY; `console.log` from Effect would corrupt the editor/input region, so no host
logger ever writes to stdout/stderr.

`makePiRuntime` / `makePiManagedRuntime` take an optional `PiHostLogTarget`. With one, they
install `piHostFileLoggerLayer`: the span-event logger plus a JSONL sink at
`<agentDirectory>/logs/<packageName>.jsonl` (mode `0o600`, append, batched, flushed when the
runtime scope closes). Without one they fall back to `piHostLoggerLayer`
(`Logger.tracerLogger` only), which has no diagnostic sink of its own because no extension owns
a span exporter. Every session runtime passes a target; pre-session / standalone runners that
bypass the managed runtime still provide the bare `piHostLoggerLayer`.

`piHostFileLoggerLayer` is deliberately `Layer<never, never, never>`. Directory resolution,
directory creation, and file opening are all absorbed into a discarding logger, so a broken log
sink can neither fail a session start nor widen the `Layer.Error` that Pi session-runtime
facades carry. `agentDirectory` is a thunk for the same reason: the Pi host resolves it lazily
and may throw, and that throw must land inside the fail-safe region.

The host log is rotated at session start after it reaches the 1 MB threshold; it has no
in-session hard cap. High-volume feature logs still need their own bounded or rotating sink.
