# Architecture

`pi-subagents` is an Effect-managed Pi extension for session-scoped child-agent processes. Pi RPC and Claude Code CLI children share one backend-neutral run model while retaining backend-specific protocols and capabilities.

## Source map

- `src/extension.ts` — thin Pi registration entrypoint and child-recursion guard.
- `src/layer.ts` — session Layer composition. The application layer exposes `SubagentService`, `SubagentProfileService`, and the single `SubagentConfigStore` persistence door; filesystem and path internals stay private.
- `src/application/` — tool, command, notification, and session lifecycle wiring. Activation captures host inputs once, invalidates the prior runtime before settings I/O, and uses generation-based latest-wins preparation so stale async loads cannot reactivate an abandoned session.
- `src/boundary/child-process.ts` — child backend dispatch plus the Pi RPC process, session-fork, and process-tree adapter.
- `src/boundary/bounded-line-parser.ts` — shared UTF-8-safe Pi/Claude line room with per-frame and aggregate queued-byte limits plus decoder-tail and final-unterminated-frame flushing.
- `src/boundary/claude-preflight.ts` — process-cached, single-flight Claude CLI readiness probe (`claude auth status --json`): executable presence and CLI authentication only, run before the first claude-cli spawn; concurrent probes share one process, success is cached per command, and failures are never cached.
- `src/boundary/claude-process.ts` — installed `claude -p` process ownership, CLI-managed authentication, explicit native-tool policy, and NDJSON transport.
- `src/boundary/process-tree.ts` — shared detached process-group termination, including post-leader-exit POSIX cleanup.
- `src/boundary/claude-protocol.ts` — bounded Claude stream-json decoding and backend-neutral event translation.
- `src/boundary/host-child.ts` — child-only `contact_parent` Pi extension and IPC bridge. This headless child-boundary tool intentionally bypasses the parent TUI's `pi-code-previews` shell because no interactive preview host exists in the RPC child.
- `src/boundary/host-profile-resolution.ts` — Pi host model-registry/auth capture plus concrete profile-start resolution. It consumes pure ordered plans, enforces hard denies on deterministic raw selectors and resolved canonical models before any registry auth lookup, runtime API-key resolution, or Claude preflight, decodes host-reported thinking levels (unknown values clamp to the shared `high` inheritance default instead of being forwarded), and builds the concrete backend request and provenance, distinguishing backend-only launches with inherited/defaulted models from explicit backend+model overrides.
- `src/boundary/native-clock.ts` — synchronous native clock isolated for Pi render callbacks.
- `src/boundary/host-environment.ts` — process-role detection.
- `src/boundary/host-notifier.ts` — exception-safe, generation-aware parent delivery acknowledgements for completions, questions, and warnings; routine progress remains projection-only.
- `src/boundary/host-ui.ts` — synchronous immutable fleet projection bridge and disposable manager repaint ticker.
- `src/config/` — the single profile-policy persistence door. `schema.ts` owns bounded v2 Effect Schema decoding, `options.ts` owns global/project merge and deny matching, and `store.ts` owns reads, typed settings inspection, and atomic profile patches for global `<agent-dir>/pi-subagents.json` plus trusted project `<cwd>/<CONFIG_DIR_NAME>/pi-subagents.json`. Routes are one required-effort candidate, an ordered non-empty candidate array, or `disabled`; selectors are exactly `parent`, canonical `pi/<provider>/<model-id>`, or validated `claude-cli/<alias-or-full-id>`. Missing project routes inherit the complete global route, while any present-invalid global or project route fails closed for that profile. Every existing document must declare numeric version `2`; v1 has no migration path. Patches preserve unrelated fields/routes, revalidate trust/version under the persistence door, and compare the inspected document inside the atomic modification lock to reject concurrent external edits.
- `src/profiles/` — fixed profile vocabulary and pure role guidance (`definitions.ts`), v2 route/policy contracts (`model.ts`), deterministic ordered candidate planning (`resolve.ts`), and the session-loaded `SubagentProfileService` (`service.ts`). Built-ins use the neutral `{ model: "parent", effort: "default" }` route. `default` resolves to the built-in profile effort, then parent effort when absent, and stays soft; concrete candidate efforts and per-launch overrides are hard.
- `src/run/` — backend/capability and run models, normalized child events, transport-specific Pi protocol decoders, errors, bounded structured child-session timelines, projection, and scoped fleet owner. `service.ts` remains the sole registry/lock owner and reauthorizes model denies immediately before reservation; `completion.ts`, `rate-limit.ts`, `process-lifecycle.ts`, and `control.ts` are internal policy/orchestration rooms. `coordination.ts` owns the shared orchestration-tool denylist, parent-message bounds, profile-guidance injection, and child prompts; the denylist is still applied at both the tool and the process boundary. `model-catalog.ts` is the pure explicit model-discovery and selector-resolution room: accepted-selector discovery lines with a truthful 100-result truncation marker (shown only when matches were actually dropped), AND-semantics ranked search, deterministic Pi selector resolution, and claude-cli/Pi selector mismatch detection.
- `src/tools/subagent.ts` — the focused agent-facing tool suite (`models`, `start`, `list`, `status`, `await`, `send`, `reply`, lifecycle, and rename), with strict non-overlapping parameter contracts, a discriminated lifecycle schema, final model-output bounding, partial-failure projection with machine-actionable failure codes, and cooperative `pi-code-previews` shell rendering.
- `src/tools/details.ts` — versioned deeply frozen start/await card snapshots, bounded persisted fields, tolerant legacy decoding, and hostile/malformed-detail fallback support.
- `src/ui/session-output.ts` — shared width-aware child-session presentation for fleet details, with grouped activity, Markdown final reports, and optional technical metadata.
- `src/settings/controller.ts` — `/subagents` fleet dispatch plus TUI-only `/subagents profiles` orchestration for Global/trusted-Project scope selection, staged single-route edits, discouraged confirmation, atomic save, and reload warnings.
- `src/settings/ui/model-picker.ts` — pure searchable model-choice construction plus the TUI picker. Denied models are omitted; authenticated Pi capability metadata, Parent capability, Claude readiness caveats, current markers, and capability-filtered efforts are presented.
- `src/ui/` — pure responsive fleet presentation, run-state glyph/color projection, scroll projection, and terminal-text sanitization. Fixed-width activity frames and responsive grouped footer fitting come from `pi-cosmic-ui/manager`, shared with `/ps`.

## Ownership

### Runtime and registry ownership

`SubagentService` is the only run-registry owner. It allocates run ordinal/name reservations atomically and prefixes IDs with an opaque per-runtime namespace, preventing collisions across concurrent starts and replacement runtimes. Every child process is acquired in a child Scope forked from the session runtime. Closing the session runtime aborts and terminates every process, settles pending requests, and clears the host projection. A successful `session_tree` event replaces that runtime, so children rooted in the abandoned branch are stopped silently and the selected branch starts with an empty fleet.

### Backend startup and protocol validation

Profile discovery and launch share one contract: `subagent_models` exposes all seven fixed profiles, their effective ordered candidates, default context/effort, and static eligibility alongside accepted explicit selectors. The agent-facing start schema is discriminated by backend: the `backend: "auto"` variant has no launch-time `model` field and resolves the selected profile or configured `defaultProfile`, while the concrete `pi`/`claude-cli` variant may carry a model override while retaining profile guidance. Built-ins contain no model aliases and select the parent candidate. Pi config selectors are canonical and resolve exactly against the authenticated catalog. Claude aliases are never substituted for exact-version requests.

Automatic selection applies per-launch effort first, then candidate effort. Candidate `default` uses the built-in profile effort and then parent effort, all as a soft preference; concrete values are hard. Denied, discouraged, unavailable, incompatible, and preflight-failing candidates are skipped in declared order before service start. Once one candidate reaches `SubagentService.start`, no later candidate is tried. Disabled/invalid routes deterministically fail with `profile_no_eligible_model`. Denied models are hidden from discovery/settings, Claude choices are unavailable to automatic launch in untrusted projects, and discouraged models require explicit selection (with confirmation in settings). `SubagentService.start` reauthorizes hard denies before reservation. Automatic Claude candidates share one cached preflight per resolution. Only `oracle` defaults to forked context; an unavailable parent branch fails instead of degrading to fresh.

Child Pi processes run in RPC mode. Standard Pi RPC uses stdin/stdout; a separate Node IPC channel carries `contact_parent` requests and peer-awareness notices. Claude children run the installed `claude -p` command with streaming JSON input/output, the CLI's normal authentication resolution, safe mode, and backend-owned read-only or writer tool allowlists. Before the first claude-cli spawn in the extension process, the process boundary runs a bounded, cached, single-flight `claude auth status --json` preflight that verifies only executable presence and CLI authentication — never model availability. Only an explicit, unambiguous positive auth value succeeds and is cached. Explicit negative auth carries `claude_cli_unauthenticated`; missing executables carry `claude_cli_not_found`; empty, malformed, ambiguous exit-zero output and other incompatible probes carry `claude_cli_preflight_failed`. Failures are not retried as transient initialization failures and are not cached, so a corrected installation or login is picked up on the next launch. The Phase 1 flag contract is verified against Claude Code 2.1.220; `--tools` restricts the available native tools, while role-specific `--disallowedTools` entries provide a second deny layer. Claude raw messages are decoded and translated before entering shared run state. Terminal result decoding requires the result discriminant but tolerates optional-field drift. Assistant text is accepted up to the transport envelope and clipped only at bounded projection/session-output boundaries; oversized terminal report text is likewise clipped at the existing projection bound. Structured Claude rate-limit events distinguish allowed requests with unavailable overage, paid-overage continuation, and actual rejection. Settlement is correlated by limit key and turn so an allowed event for one window cannot cancel another window's rejection; resume and authoritative completion clear turn-local state while preserving per-window threshold history. All utilization updates refresh the UI, while parent notifications are limited to the first 80%, 90%, and 95% crossing in each reset window, the first paid-overage continuation, and rejection. Active or available paid overage remains non-terminal and uses allowance-exhaustion wording. Only rejection combined with explicitly unavailable overage starts a short grace period for the authoritative result envelope; ambiguous limit events defer to that result rather than terminating a usable session. Backend capabilities prevent unsupported operations from being approximated: Phase 1 Claude runs support fresh start, completion, stop, local rename, and continuation after completion, but not steering, interruption, forked Pi context, peer notices, or parent contact. Agent-facing tool descriptions, detailed status output, and typed capability errors expose those limits with exact-tool recovery guidance before or after an attempted operation. The process boundary tags transports, and each is decoded against only its permitted bounded protocol schema. Both transports use the shared bounded line room, which preserves split UTF-8, enforces per-frame and aggregate queued-byte budgets, and flushes decoder tails plus the final unterminated frame at EOF. Pi blocking parent questions execute sequentially, and the parent claims each question before sending its single reply. Fresh Pi children use a dedicated session directory with filesystem-safe session/run segments. Forked Pi children receive a private copy of the stable parent branch, never the live parent file; non-portable provider thinking blocks are removed from that copy. Runtime-only Pi API keys cross the process boundary through an ephemeral environment bootstrap rather than process arguments.

### Process lifecycle and cleanup

Child finalization bounds transport writes and uses backend-specific graceful shutdown before process-tree termination. POSIX cleanup signals the detached process group even after its leader exits and performs a final forced group sweep. Live Windows trees use a bounded `taskkill`; once the leader has exited, PID-based sweeping is deliberately skipped to avoid targeting an unrelated PID-reused process until a native Job Object adapter is introduced. Completed processes close their owned scope immediately while session identity and output remain in the run record; a later resume reacquires a process from the Pi session file or Claude session ID. Claude initialization has a separate 60-second readiness deadline. Because stream-json emits `system/init` only after receiving its first user frame, the service submits the initial task frame before awaiting initialization, then verifies the complete role-specific resolved tool set for both read-only and writer runs before accepting startup. Terminal events observed during initialization are deferred until model/session/tool-policy state commits, preventing an immediate result from racing scope closure. A single fresh-process retry is allowed only for transient spawn, initialization-stream, or readiness failures; policy, authentication, model, permission, and limit errors fail without retry. Steady-state RPC remains bounded to 10 seconds. Process exit is observed only after stdio closes, buffered RPC events drain before exit settlement, exited handles cannot signal stale PIDs, and failed writers retain ownership until external scope cleanup completes. Stop cleanup continues independently when its requesting tool is cancelled. Resume waits at most ten seconds for prior cleanup and reports `cleanup_timeout` rather than polling forever; capacity failures distinguish active saturation from transient cleanup-owned slots.

### Controls and settlement

RPC registration, failure ownership, and stop-time response sweeping are serialized by the service lock. RPC transport sends race their response Deferred so stop or run failure interrupts a blocked send promptly. Terminal state transitions are atomic and monotonic; stop is a no-op for terminal records, and starting or terminal records may be renamed locally without contacting a process. Foreground questions, pauses, and settlements release the owning tool waiter exactly once. Accepted replies, interrupts, and resumes commit in the session scope if their requesting tool is cancelled. Task-submission certainty is tracked independently so a writer is never automatically retried after its initial task may have been accepted. Interrupt settlement is correlated independently from the RPC response so delayed abort responses cannot turn a pause into completion, and post-pause parent contacts are ignored. Ambiguous send, reply, interrupt, resume, and writer-start outcomes carry operation-specific `*_outcome_uncertain` codes and tell the parent to inspect status before retrying; uncertain operations are neither retried nor unsafely rolled back. Launch metadata follows local rename so a later respawn receives the current name. Child-controlled stdout, stderr, transcripts, identifiers, and management messages are bounded; stderr included in direct boundary errors is sanitized and redacted. Successful and failed Claude result envelopes both contribute their reported usage before terminal settlement. Unknown protocol values are decoded with Effect Schema before entering run state, including normalization of Pi's structured RPC model descriptor and Claude's string model identifier. Token-delta activity publication is coalesced to one update per second so streaming children do not repeatedly clone and render the fleet.

### Completion delivery and notifications

The service owns revision-driven fleet waiters, completion claims, acknowledgement generations, and an Effect-clock delivery scheduler. The public await conditions are `all_finished` and `any_finished`; “finished” projects the internal completed, failed, and stopped terminal states into user-facing language. Either condition also returns early when a selected Pi run enters `waiting_for_parent`, rendering its question and exact `subagent_reply` call so the parent can answer and await again instead of deadlocking behind its own active tool call. `await` acquires selected-run claims with an atomic Effect bracket before sleeping on revision Deferreds, updates one partial tool result on state changes, and releases claims on success, attention, timeout, or cancellation without touching child scopes. `status` and `await` hold a completion claim through generation receipt rendering and consumption, preventing automatic delivery from racing a full tool result. Foreground start uses the same render-before-consume claim discipline as status/await. Only reports represented in full by the final bounded tool result are consumed; cancellation or truncation releases the claim, so the report remains notification-eligible. Unclaimed completions are batched and delivered with generation IDs. The host notifier sizes every chunk using its actual continuation header, resets deduplication at session deactivation, and acknowledges only successfully sent chunks. Unacknowledged completion and actionable question/warning generations retry with exponential backoff capped at 30 seconds while relevant. Superseded questions/warnings are dropped, while 51+ consecutive failed sends remain retained instead of being evicted by notifier-local deduplication. Steer delivery joins an active orchestration run instead of accumulating behind its final response. Routine progress is projection-only; questions and warnings remain actionable parent messages. Non-triggering warnings use steer delivery so they appear immediately while the parent is idle or after its active tool batch, rather than waiting for another user prompt.

### UI and projection ownership

The UI and host notifications consume immutable projections. Await progress and completed start/await cards carry versioned, deeply frozen, bounded snapshots from `tools/details.ts`; tolerant decoding accepts legacy persisted details and falls back to sanitized bounded text for malformed or hostile values. Each card persists only the presentation fields needed for profile and selection provenance. Model-facing status/start/await output renders that provenance, compact cards identify the profile, expanded cards show selection details, and `/subagents` exposes the complete provenance under technical details. Run history is the structured `sessionEvents` timeline plus `finalText`, with no parallel string transcript. The renderer uses shared humanized state labels, status-aware headers, the fleet state palette, and Pi’s thinking-effort palette. Width-aware summary components align wide columns, preserve names and statuses before truncating models, and fall back to multi-line narrow rows. Await projections show the same name/model/effort/status fields as completed summaries, animate active glyphs from the cooperative shell’s render clock, and clearly project timeout, cancellation, and first-finished outcomes. Collapsed cards and partial launch failures stay compact and advertise expandable reports explicitly. Fleet rows hide run IDs by default and expose them only in technical mode; session output labels reports neutrally rather than claiming they were sent to the parent. Expanded bounded reports use the host Markdown component; model-facing tool content independently retains the full report for completion acknowledgement. They never own child sessions or processes. Session startup activates no runtime when cooperative tool registration throws; it shuts down the slot, accumulates every partially registered tool name across repeated failures, and disables those names before a later successful registration restores the exact set.

## Write coordination

Every launch declares `writeIntent: "writer" | "read-only"`. `subagent_start` has one canonical strict request shape: a required `agents` array containing one to twelve independent per-agent specifications. Each specification is a strict backend-discriminated union: automatic profile routing structurally excludes a launch-time `model`, while explicit `pi`/`claude-cli` routing may include one. Fresh task text must be non-whitespace and self-contained with relevant paths, constraints, evidence, and a concrete deliverable. At most one foreground item is allowed per call so one child question cannot be hidden behind another foreground waiter. Launch failures are reported by item while successful peers remain owned by the session service, and foreground starts publish progress after process readiness before waiting. Every tool object rejects excess properties. The remaining agent operations use focused schemas so provider-generated optional fields cannot introduce unrelated target or action forms; interrupt, resume, and stop share a discriminated `subagent_lifecycle` union, and only its resume member can contain a message. The child-only `contact_parent` schema is likewise strict and bounds non-whitespace messages. Multi-target status, guidance, and lifecycle calls collect per-run successes and typed failures instead of failing fast after potentially applying or resolving an unreported subset. Duplicate IDs are normalized, stale status IDs remain model-visible beside valid results, and failure codes are rendered in tool content rather than existing only in render metadata. The service permits only one active writer in the shared cwd. Pi writers receive the parent active tools except recursive orchestration tools. Pi read-only children receive only the conservative inspection allowlist (`read`, `grep`, `find`, `ls`, and the web content tools); shell, mutation, orchestration, and unknown extension tools are excluded at both tool resolution and process launch. Claude children instead receive a backend-owned native-tool allowlist: read-only runs omit and explicitly deny mutation and shell tools, while writer runs add Edit, Write, and Bash. Read-only Claude runs still permit WebFetch and WebSearch, so read-only describes local workspace mutation rather than network isolation. Pi peer notices make shared-workspace concurrency explicit. True parallel writers are deferred until isolated worktrees are implemented.
