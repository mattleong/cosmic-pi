# Architecture

`pi-subagents` is an Effect-managed extension for session-scoped, profile-routed background subagents across local and Herdr hosts. The root Pi session is depth 0 and owns one managed runtime, coordinator, profile/config state, backend registry, run tree, writer pools, completion outbox, and fleet projection for every descendant. Nested Pi processes are authenticated proxy clients. They never construct independent application services. Replacement or shutdown closes the complete tree leaf-first.

## Ownership map

- `src/extension.ts`, `src/application/`, and `src/layer.ts` register Pi callbacks, capture session capabilities, compose the runtime, and preserve the complete Current Session profile baseline plus dirty routes across allowed replacement paths. The shared session-runtime slot owns latest-start replacement and cancellation. Runtime startup runs preview settings as an interruptible best-effort bootstrap, then returns the initial projection and tool runtime as prepared activation data. Only the current slot token may register tools or publish activation state. `makeRuntime` captures tree and reload profile handoffs after the slot has disposed the prior runtime.
- `src/config/` is the strict version-6 data boundary. Global and trusted-project documents use the same named-set shape; selected partial sets layer project over global over built-ins. It reads legacy versions 4 and 5, maps root routes into set `default`, and migrates only fully valid legacy data on save. `store.ts` is the only persistence door and owns optimistic exact-document set/default/route/nesting mutations plus atomic seven-profile snapshot creation. `src/profiles/` owns built-ins, named-set resolution, canonical candidate validation, revisioned Current Session baselines and dirty routes, and one-revision whole-session replacement.
- `src/run/` owns immutable ancestry, per-parent direct-child admission, depth checks, subtree authorization, immutable launch-time routing, cooperative exact-file claims, root writer pools, process/control transitions, native-agent summaries, retained assignments, completion claims and ancestor-first delivery, bounded terminal-history reclamation, and the synchronous tree projection. One pure predicate identifies runs that need parent action, including real questions, pauses, and paused writer admission, so service awaits and tool results agree. `tree.ts` owns pure ancestry, visibility, count, and leaf-first ordering rules. `session-owned.ts` owns the one claim-then-owner-scoped-commit mask shared by session-owned launch, retry, reply, interrupt, stop, and resume, so cancelling a waiter never abandons ownership while owner-scope closure still interrupts the commit. Subtree stops join descendant cleanup, including already-stopping and terminal descendants, before closing ancestors. Terminal outcomes remain unchanged. `record-cleanup.ts` masks owned scope closure through backend and writer-lease release and cleanup-outcome publication because closing a scope cannot be retried after interruption. Joiners and pre-close spawn waits remain interruptible. An interrupted pre-close owner relinquishes its claim without settling cleanup disposition; awakened joiners or late launch compensation reclaim it. A stalled owned release keeps shutdown waiting rather than falsely confirming cleanup. Shutdown disables projection publication without blocking late cleanup state commits or private run-state reclamation. `tool-policy.ts` owns the root Pi active-tool snapshot, the competing-orchestrator denylist, and canonical authenticated proxy names.
- `src/domain/` holds deterministic leaf policy with no Pi, Node, or service dependencies. `routing.ts` is the shared routing vocabulary (host, runtime, context, write-intent, and per-runtime effort types plus their decoders) that profiles, config, run orchestration, and backends depend on without forming a cycle; `write-claims.ts` owns write-claim normalization, bounds, and pairwise conflict detection shared by admission, tool decoding, and lease coordination.
- `src/backend/` contains the six local/Herdr Pi, Claude, and Codex drivers plus their pure protocol and policy modules. `local-cli-interruption.ts` classifies shared Claude/Codex control exits without owning either adapter's correlated lifecycle. A selected driver owns execution after readiness succeeds; fallback never crosses an ownership boundary.
- `src/boundary/` contains Pi, Node, process, filesystem, Herdr, native-catalog, writer-lease, RPC, and supervisor adapters. `herdr-attestation.ts` owns private startup receipts and Effect-owned validation; `herdr-harness.ts` composes their fixed atomic shell commands, while `herdr-launch-safety.ts` and `herdr-host.ts` bracket every receipt with exact topology and shell checks without mutating workspace/tab focus. `host-child.ts` gives each local child session one managed runtime. Its local scoped Layer owns the IPC listener, and reload registers fresh token-checked proxy definitions only after interruptible preview bootstrap. Bridge opening forks a parent-owned child scope before initialization. Failed or interrupted initialization closes that child immediately even if the parent scope stays open; success retains it until parent release. RPC process and supervisor-channel acquisitions construct one underlying-uninterruptible `Effect.cached` close before finalizer registration, so explicit close, partial cleanup, and scope release reuse the same complete outcome. `host-child-pi.ts` shares one-shot credential scrubbing and the eligible OpenAI priority request hook between local and delegated Pi children. `local-claude-debug.ts` owns the exact opt-in gate and bounded private metadata ledger; it keeps no raw protocol content and cannot affect run success. Supervisor tool execution returns plain response data; one outer writer commit publishes exactly one MCP response before writer shutdown proceeds.
- `src/settings/` owns commands, the framed profile workspace, saved-set library, fixed-target route edits, replacement previews, snapshot saving, and cancellable model catalogs. `profile-workspace.ts` retains the original profile/candidate/field pages, Advanced controls, and full-page pickers; shortcuts and single-candidate skipping reduce navigation without replacing the presentation. It serializes saves, remembers selections, and adds a candidate only after model selection. `profile-dashboard.ts` closes each host screen before opening the next and preserves the editor page, field, candidate, and expansion state. Target and snapshot dialogs remain separate framed screens. `src/settings/ui/` contains pure projections, selectors, and rendering built on shared `pi-cosmic-ui` framing and model pickers. Runtime catalogs and route policy remain package-owned; cancellation keeps unavailable configured models unchanged.
- `src/tools/` owns Pi tool schemas, root/proxy execution, strict private proxy decoding, persisted detail schemas, bounded text formatting, and cooperative renderers over `pi-cosmic-ui/tool` headers, components, and disclosure affordances. `model.ts` contains plain tool outcome and profile DTOs, `execute-models.ts` owns the whole `models` action (static profile-route discovery, its formatted text, and compact details), `execute-start.ts` owns the whole public start-batch orchestration (request validation, the one profile snapshot per batch, route resolution, partial outcome publication with hostile update containment, and request-ordered receipts), while `execute.ts` keeps action dispatch, authorization, await mutable state and cancellation, and final tool result projection, and `subagent.ts` is only the registration door. List cards render parent-before-child; hierarchy run rows use one stable width-bounded line per run, with tree identity and state glyph first, route metadata next, and lower-priority details truncated at narrow widths. Root TUI start and await executions acquire short-lived presentation leases. When the above-editor activity widget is available, their partial result components render no duplicate hierarchy; non-TUI, nested, and failed-widget paths keep the bounded live-card fallback. Settled collapsed cards retain durable summaries, exceptional launch evidence, recovery, and report disclosure. Expanded await cards render reports before the static settled hierarchy, suppress routine per-run diagnostics, retain exceptional fallback, warning, retention, writer, and failure evidence, and hide progress once an assignment finishes. Hidden task, report, failure, and recoverable fallback sections use one accent disclosure affordance with a `ctrl+o` hint. Await details still distinguish requested targets from bounded report-free descendant context, and only requested observations participate in completion claims. `src/ui/` owns pure fleet, activity-panel, and run presentation. Its `run-presentation.ts` leaf shares bounded age, short ID, and sanitized route/model projection without choosing panel or tool width policy. Its `run-tree-rows.ts` leaf owns the single parent-before-child walker and box-drawing branch renderer behind both the tool card hierarchy and the fleet/activity hierarchy; the two projections keep their policies explicit there (cards dedupe ids, promote missing/self/unknown-parent orphans, and surface cycles as roots; fleet scopes to the visibility root, never renders it, supports collapse, and drops out-of-scope orphans). The persistent panel reads the same frozen root projection, shows every starting, running, stopping, waiting, or paused run plus required ancestors, marks leased await targets with `◎`, and emits no lines for retained-only or terminal-only state. Persistent rows below 100 columns show profile plus a provider-free `model:effort` label; wide rows show profile, host/runtime, and the full provider/model route. Optional activity and elapsed time use only the remaining one-line width. `src/boundary/host-activity-widget.ts` owns Pi widget installation, projection/render caching, presentation leases, footer suppression, stale-context guards, and disposal. `src/boundary/host-refresh-ticker.ts` owns adaptive stop-before-start host ticker replacement shared by the persistent widget and full-screen fleet. The full-screen fleet projects the authenticated subtree into one parent-before-child hierarchy, expands all branches initially, uses Left/Right to collapse or expand a selected subtree, and uses Enter to inspect the selected run. A nested caller cannot render or select nodes above or beside its visibility root. `src/settings/proxy-controller.ts` registers the packaged nested-Pi subtree manager without owning remote state.
- `src/boundary/host-activity.ts` registers the root session's Cosmic UI activity provider from frozen fleet projections. It projects the complete authorized root tree, including terminal history and completed ancestors, and publishes launch/await presentation leases without moving run ownership. Credentials are redacted before summaries or selected details leave the producer. Actions recheck cancellation, the session token, item revision, and current capabilities before entering the authoritative service runner with the host's abort signal. Destructive actions declare their confirmation scope, including descendant shutdown for stop. Selected-item details use the same checked capability and stay bounded. Replacement and shutdown revoke registration and callbacks. `host-ui.ts` removes the legacy widget only after Cosmic UI acknowledges installed provider UI, restores it when that acknowledgement is lost, and keeps presentation leases and footer fallback intact. Parent-contact questions remain parent orchestration, not user questionnaires. `/subagents` remains the advanced manager.
- `src/supervisor/` owns the import-free MCP argument contract and Effect RPC v3 protocol.

## Structured child questionnaires

`host-ask-user.ts` consumes the versioned `pi-ask-user/protocol` root capability and publishes checked child relays over existing authenticated transports. Only explicit blocking `ask_user` requests from local Pi or Herdr Pi enter this path. `pi-ask-user` remains the sole tool registrar and must be discoverable in the child; missing relay/capability fails closed. Native Claude/Codex, asynchronous child questionnaires, ordinary `contact_parent` questions, and raw `extension_ui_request` forwarding are not supported.

The root derives owner run, assignment epoch, and request ID from coordinator state, never tool arguments. A separate strict 128 KiB decoder keeps questionnaires out of `SubagentToolInput`. `run/questionnaire-lifetime.ts` owns assignment validity, revocation signals, cleanup joins, and at most 256 request-ID tombstones per assignment. Replayed answered or cancelled identities cannot reopen a dialog. Publication revokes queued, visible, or hidden waits on pause, stop, settlement, and assignment replacement; process cleanup joins their finalizers outside the service lock. Shutdown revokes before leaf-first release. The root boundary installs exact capability/owner cleanup before the interruptible answer wait. Its narrow masked finalizer joins `cancel(owner)` on success, failure, and interruption; aborting a Promise alone does not acknowledge root dialog/editor cleanup. A stalled owned cleanup keeps stop and shutdown waiting. Local child reload cancels tracked questionnaire correlations before detaching the old IPC listener. Capability generation and assignment validity are rechecked before returning answers. Deliberate cancellation remains a cancelled outcome, not an invitation to retry through another UI.

## Invariants

- A public or proxied start batch captures one profile and nesting-policy revision. Default policy is 12 direct children and depth 3, with strict bounds of 1 through 32 and 0 through 8. Admission counts active direct children and race reservations for one parent only. There is no tree-wide active-run budget. A node at max depth cannot spawn.
- Every run has immutable `parentRunId` and `depth`, anchored at the virtual `root` node. Root views contain the complete tree. Authenticated nested views contain the caller and its descendants, and target authorization rejects ancestors and siblings. Natural intermediate completion leaves descendants running. Explicit stop and root shutdown close leaf-first. Subtree stop claims every target, including its parent-stop flag, and forks the complete sequential traversal into the session scope before restoring waiter interruption. Retry successors keep the predecessor parent while existing descendants stay on the predecessor.
- A public start batch captures one profile snapshot. Candidate fallback is readiness-only; explicit retry advances strictly through the frozen route after confirmed cleanup. Herdr protocol readiness is one deliberate exception to literal host selection: any version other than protocol 20, or a CLI/server protocol mismatch, retries that same candidate on the local host before advancing the route. The fallback preserves runtime, model, effort, context, write intent, fast mode, and claims, forces `closeOnReport:true`, and records a prominent warning.
- Every local or Herdr Pi launch separately snapshots the root Pi's current active tool names; nested callers never substitute child-local tool toggles. Write intent does not filter the snapshot. Only competing coordinator/orchestrator implementations are denied, while package-owned `subagent_*` names resolve to authenticated proxies. Before ownership, the snapshot must pass count, exact comma-free name, control-character, per-name, and aggregate UTF-8 bounds so Pi's CLI parser cannot normalize or inject another activation. A name activates only an implementation discoverable by the child under its root-derived project trust. Herdr additionally disables skills, prompt templates, and context files. Native Claude/Codex policies do not consume this snapshot.
- Pi read-only is prompt and writer-lease coordination, not capability confinement. In a trusted Pi child, active/discoverable Code Mode retains its direct nested built-in authority: nested calls bypass Pi middleware, approvals/overrides, and per-file claim observation. Every process, pane, helper, transport, private harness, writer pool, and writer lease belongs to the session runtime. One cross-process cwd lease protects each session pool; claimless writers are exclusive, while claimed writers must be pairwise disjoint. Claims coordinate unchanged native tools rather than sandboxing them. A native claim violation atomically pauses pool admission and starts owner-scoped containment. Only a backend with both interrupt and resume may pause; other active offenders stop. Failed interruption falls back to normal stop. The parent alone may grant safe missing claims to a confirmed paused offender, reopen admission, resume it, or stop and replace it. Any unconfirmed member cleanup quarantines the whole cwd pool, preserving fail-closed writer ownership.
- Reports are in-memory assignment generations. Retained next-assignment admission stops at 63 unresolved reports, reserving generation 64 for a later terminal backend failure; no run records generation 65. Close-on-report resume paths retain the hard 64-generation bound.
- The local Pi IPC bridge and delegated Herdr Pi supervisor bridge expose the same proxy tool set. The server binds each request to its authenticated caller run and ignores ancestry fields because the proxy schema cannot carry them. Parent proxy executions live in one `${runId}:${requestId}`-keyed FiberMap owned by the service scope: per-run bounded concurrency, exact duplicate-identity conflict responses, nonblocking forked cancellation interrupts, and scope-finalizer interruption of surviving executions after the leaf-first shutdown. The parent channel and delegated bridge share one supervisor contract. Each local question or proxy call acquires its exact correlation entry and releases only that waiter identity. Current-listener disconnect or runtime closure rejects every remaining waiter. Listener release performs that rejection unconditionally, but a detached old listener's later disconnect callback cannot reject correlations owned by the replacement session. Stale listeners do not acknowledge controls, and stale reload definitions reject without reaching the current runtime. Questions are interruptible, reports are idempotent, and the MCP helper writes one response frame per call even when cancellation races stdout backpressure.
- Resumable local Pi interruption closes run-level turn-input admission before RPC. Already admitted guidance, acknowledged parent replies, and descendant notifications drain first; notification IPC is acknowledged after the child admits `pi.sendMessage`, while acknowledgment uncertainty stays owned by the selected ancestor rather than duplicating fallback delivery. One Effect semaphore and a correlated IPC barrier prove that earlier child inputs were processed before the complete `clear_queue` → `abort` sequence. Paused or pause-pending runs reject later turn inputs. The adapter sends `abort` only after correlated queue-clear success and discards the returned queue text. Barrier, clear, or clear-transport uncertainty suppresses later commands and releases the run-level pause claim; uncertainty after `abort` keeps the existing pending-pause behavior.
- Herdr startup gates never depend on terminal visibility or focus. Every split keeps `--no-focus`, and every launch/input/rollback/close mutation targets the exact owned pane ID while `pi-subagents` issues no workspace/tab focus command. Parent harness paths are validated before the exclusive run-directory mkdir commits ownership. Its cleanup latch starts enabled, is withheld synchronously before `splitPane`, and is reenabled only after definite split non-application, confirmed provisional rollback, or confirmed hosted close with every owned selector absent. Scope release runs hosted close, the topology uncertainty guard, then conditional harness removal. Activation, sterile-environment readiness, post-environment shell input, secret readiness, and post-secret shell input each publish a unique token to a unique initially absent path inside the run's 0700 harness. The pane command writes a 0600 temporary file and atomically renames it; Node polls boundedly under Effect and rejects symlinks, non-regular files, identity drift, oversized values, and wrong or partial content. Terminal markers are diagnostic only. A first focus-free activation timeout permits one harmless retry only after exact ownership revalidation and another available-shell wait; a second miss fails with the typed pane-input error and rolls back exact confirmed ownership rather than focusing. Closing a focused owned pane remains exact and lets Herdr choose any successor focus naturally.
- Herdr Pi mirrors the root project's trusted/untrusted discovery decision while always disabling skills, prompt templates, and context files. Private lifecycle and supervisor integrations remain explicit, and owned proxy tools use `withCodePreviewShell`.
- Claude and Codex native agents stay inside their parent run and sandbox. They do not enter the Pi registry, depth calculation, or writer admission. Claude classifies `parent_tool_use_id` frames as native-agent forwarding, refuses cross-session input in the generated settings shared by local and Herdr launches, and requires same-session UUID authority for adapter-input replay. One narrow exception owns Claude 2.1.259's same-session active-assignment command-queue replay of a complete task-notification envelope when synthetic/origin metadata is absent; its fresh UUID is internal subturn evidence, never an alias for adapter input. Every near miss remains unexplained. Unexplained replay stays fail closed until the supervisor proves an exact-epoch accepted report; only then may the adapter warn and reproject that report for normal close-on-report settlement. Digest equality is diagnostic evidence, never authority. The default diagnostic and optional private tail contain classification metadata only. Known native events update a bounded active/total/latest summary; unknown native protocol shapes fail closed.
- Current Session is the only active working set. It starts from a complete baseline resolved through trusted Project, Global, and built-in defaults. Per-profile edits apply to later launches immediately, while saved-set edits never change Current Session. Applying a valid saved set resolves and previews all seven routes, then replaces the baseline and clears dirty routes with one expected revision; active runs remain unchanged. Saving Current Session holds the profile service's revision lock through one full-snapshot store action, rejects fail-closed inherited routes or a changed session revision, and does not select a default. Invalid sets remain visible but cannot be applied or selected as defaults; Project-set status includes inherited Global failures. Route-invalid sets can be repaired, structurally invalid sets must be deleted and recreated, and malformed unnamed defaults remain clearable. Clearing a selected default keeps the saved set and restores lower-layer inheritance. Project trust is rechecked before every Project write.
- Settings catalog refresh is nonblocking and cancelable. The editor captures its originating activation before inspection and submits refresh through that session's application runner with editor cancellation. Replacement revokes submission and delayed inspection results. The registry receives an Effect-owned signal; a noncooperative Promise cannot retain the fiber or publish after interruption. A successful non-aborted refresh atomically replaces one immutable root-registry Pi-model snapshot; failure or abort retains the prior generation, and each picker captures one generation.
- Persisted tool details are strict version 2, privacy-projected, deeply frozen, and canonically bounded to 48,000 characters. Optional bounded write-claim, audit, current-violation-offender, awaited-target, descendant-context, and admitted failed-start recovery fields are additive within version 2. Failed-start recovery is published only after the complete cleanup barrier and derives retry eligibility from authoritative run facts. Await context cards never carry descendant reports. Older history uses bounded sanitized text fallback.
