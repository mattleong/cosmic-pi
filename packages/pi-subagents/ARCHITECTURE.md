# Architecture

`pi-subagents` is an Effect-managed extension for session-scoped, profile-routed background subagents across local and Herdr hosts. The root Pi session is depth 0 and owns one managed runtime, coordinator, profile/config state, backend registry, run tree, writer pools, completion outbox, and fleet projection for every descendant. Nested Pi processes are authenticated proxy clients. They never construct independent application services. Replacement or shutdown closes the complete tree leaf-first.

## Ownership map

- `src/extension.ts`, `src/application/`, and `src/layer.ts` register Pi callbacks, capture session capabilities, compose the runtime, and preserve temporary profile routes across the allowed replacement paths.
- `src/config/` is the strict version-5 data boundary. It reads version 4 with default nesting policy and upgrades on save. `store.ts` is the only persistence door. `src/profiles/` owns built-ins, canonical candidate validation, route resolution, and revisioned session overlays for routes and nesting policy.
- `src/run/` owns immutable ancestry, per-parent direct-child admission, depth checks, subtree authorization, immutable launch-time routing, cooperative exact-file claims, root writer pools, process/control transitions, native-agent summaries, retained assignments, completion claims and ancestor-first delivery, bounded terminal-history reclamation, and the synchronous tree projection. `tree.ts` owns pure ancestry, visibility, count, and leaf-first ordering rules. `tool-policy.ts` owns the root Pi active-tool snapshot, the competing-orchestrator denylist, and canonical authenticated proxy names.
- `src/backend/` contains the six local/Herdr Pi, Claude, and Codex drivers plus their pure protocol and policy modules. A selected driver owns execution after readiness succeeds; fallback never crosses an ownership boundary.
- `src/boundary/` contains Pi, Node, process, filesystem, Herdr, native-catalog, writer-lease, RPC, and supervisor adapters. `herdr-attestation.ts` owns private startup receipts and Effect-owned validation; `herdr-harness.ts` composes their fixed atomic shell commands, while `herdr-launch-safety.ts` and `herdr-host.ts` bracket every receipt with exact topology and shell checks without mutating workspace/tab focus. `host-child-pi.ts` shares one-shot credential scrubbing and the eligible OpenAI priority request hook between local and delegated Pi children. Supervisor tool execution returns plain response data; one outer writer commit publishes exactly one MCP response before writer shutdown proceeds.
- `src/settings/` owns command orchestration, pure route edits, the replace-only immutable root-registry Pi model catalog, and the stateful disposable profile workspace. `src/settings/ui/` contains only pure selectors, model-choice projection, and rendering.
- `src/tools/` owns Pi tool schemas, root/proxy execution, strict private proxy decoding, persisted detail schemas, bounded text formatting, and cooperative renderers. List cards render parent-before-child; hierarchy run rows use one stable width-bounded line per run, with tree identity and state glyph first, route metadata next, and lower-priority details truncated at narrow widths. Root TUI start and await executions acquire short-lived presentation leases. When the above-editor activity widget is available, their partial result components render no duplicate hierarchy; non-TUI, nested, and failed-widget paths keep the bounded live-card fallback. Settled collapsed cards retain durable summaries, exceptional launch evidence, recovery, and report disclosure. Expanded await cards render reports before the static settled hierarchy, suppress routine per-run diagnostics, retain exceptional fallback, warning, retention, writer, and failure evidence, and hide progress once an assignment finishes. Hidden task, report, failure, and recoverable fallback sections use one accent disclosure affordance with a `ctrl+o` hint. Await details still distinguish requested targets from bounded report-free descendant context, and only requested observations participate in completion claims. `src/ui/` owns pure fleet, activity-panel, and run presentation. The persistent panel reads the same frozen root projection, shows every starting, running, stopping, waiting, or paused run plus required ancestors, marks leased await targets with `◎`, and emits no lines for retained-only or terminal-only state. `src/boundary/host-activity-widget.ts` owns Pi widget installation, projection/render caching, presentation leases, footer suppression, stale-context guards, and disposal. `src/boundary/host-refresh-ticker.ts` owns adaptive stop-before-start host ticker replacement shared by the persistent widget and full-screen fleet. The full-screen fleet projects the authenticated subtree into one parent-before-child hierarchy, expands all branches initially, uses Left/Right to collapse or expand a selected subtree, and uses Enter to inspect the selected run. A nested caller cannot render or select nodes above or beside its visibility root. `src/settings/proxy-controller.ts` registers the packaged nested-Pi subtree manager without owning remote state.
- `src/supervisor/` owns the import-free MCP argument contract and Effect RPC v3 protocol.

## Invariants

- A public or proxied start batch captures one profile and nesting-policy revision. Default policy is 12 direct children and depth 3, with strict bounds of 1 through 32 and 0 through 8. Admission counts active direct children and race reservations for one parent only. There is no tree-wide active-run budget. A node at max depth cannot spawn.
- Every run has immutable `parentRunId` and `depth`, anchored at the virtual `root` node. Root views contain the complete tree. Authenticated nested views contain the caller and its descendants, and target authorization rejects ancestors and siblings. Natural intermediate completion leaves descendants running. Explicit stop and root shutdown close leaf-first. Retry successors keep the predecessor parent while existing descendants stay on the predecessor.
- A public start batch captures one profile snapshot. Candidate fallback is readiness-only; explicit retry advances strictly through the frozen route after confirmed cleanup. Herdr protocol readiness is one deliberate exception to literal host selection: any version other than protocol 20, or a CLI/server protocol mismatch, retries that same candidate on the local host before advancing the route. The fallback preserves runtime, model, effort, context, write intent, fast mode, and claims, forces `closeOnReport:true`, and records a prominent warning.
- Every local or Herdr Pi launch separately snapshots the root Pi's current active tool names; nested callers never substitute child-local tool toggles. Write intent does not filter the snapshot. Only competing coordinator/orchestrator implementations are denied, while package-owned `subagent_*` names resolve to authenticated proxies. Before ownership, the snapshot must pass count, exact comma-free name, control-character, per-name, and aggregate UTF-8 bounds so Pi's CLI parser cannot normalize or inject another activation. A name activates only an implementation discoverable by the child under its root-derived project trust. Herdr additionally disables skills, prompt templates, and context files. Native Claude/Codex policies do not consume this snapshot.
- Pi read-only is prompt and writer-lease coordination, not capability confinement. In a trusted Pi child, active/discoverable Code Mode retains its direct nested built-in authority: nested calls bypass Pi middleware, approvals/overrides, and per-file claim observation. Every process, pane, helper, transport, private harness, writer pool, and writer lease belongs to the session runtime. One cross-process cwd lease protects each session pool; claimless writers are exclusive, while claimed writers must be pairwise disjoint. Claims coordinate unchanged native tools rather than sandboxing them. Any unconfirmed member cleanup quarantines the whole cwd pool, preserving fail-closed writer ownership.
- Reports are in-memory assignment generations. Retained next-assignment admission stops at 63 unresolved reports, reserving generation 64 for a later terminal backend failure; no run records generation 65. Close-on-report resume paths retain the hard 64-generation bound.
- The local Pi IPC bridge and delegated Herdr Pi supervisor bridge expose the same proxy tool set. The server binds each request to its authenticated caller run and ignores ancestry fields because the proxy schema cannot carry them. The parent channel and delegated bridge share one supervisor contract. Questions are correlated and interruptible, reports are idempotent, and the MCP helper writes one response frame per call even when cancellation races stdout backpressure.
- Herdr startup gates never depend on terminal visibility or focus. Every split keeps `--no-focus`, and every launch/input/rollback/close mutation targets the exact owned pane ID while `pi-subagents` issues no workspace/tab focus command. Activation, sterile-environment readiness, post-environment shell input, secret readiness, and post-secret shell input each publish a unique token to a unique initially absent path inside the run's 0700 harness. The pane command writes a 0600 temporary file and atomically renames it; Node polls boundedly under Effect and rejects symlinks, non-regular files, identity drift, oversized values, and wrong or partial content. Terminal markers are diagnostic only. A first focus-free activation timeout permits one harmless retry only after exact ownership revalidation and another available-shell wait; a second miss fails with the typed pane-input error and rolls back exact confirmed ownership rather than focusing. Closing a focused owned pane remains exact and lets Herdr choose any successor focus naturally.
- Herdr Pi mirrors the root project's trusted/untrusted discovery decision while always disabling skills, prompt templates, and context files. Private lifecycle and supervisor integrations remain explicit, and owned proxy tools use `withCodePreviewShell`.
- Claude and Codex native agents stay inside their parent run and sandbox. They do not enter the Pi registry, depth calculation, or writer admission. Known native events update a bounded active/total/latest summary; unknown native protocol shapes fail closed.
- Settings catalog refresh is nonblocking and cancelable. A successful non-aborted refresh atomically replaces one immutable root-registry Pi-model snapshot; failure or abort retains the prior generation, and each picker captures one generation.
- Persisted tool details are strict version 2, privacy-projected, deeply frozen, and canonically bounded to 48,000 characters. Optional bounded write-claim, audit, awaited-target, descendant-context, and admitted failed-start recovery fields are additive within version 2. Failed-start recovery is published only after the complete cleanup barrier and derives retry eligibility from authoritative run facts. Await context cards never carry descendant reports. Older history uses bounded sanitized text fallback.
