# Code Previews architecture

## Purpose

Provides syntax-highlighted previews, structured diffs, safer write/edit presentation, settings, and cooperative tool-shell APIs.

## Host surface

- Commands: preview health and settings (`settings/controller.ts`, `commands/health.ts`); both guard non-TUI hosts and fall back to plain notifications instead of opening custom UI.
- Events: `session_start` and `session_shutdown`.
- Tool surface: installed replacements for supported built-in tools and the public cooperative shell wrapper. The extension never changes Pi's active tool names.

## Source map

- `src/extension.ts` is the thin Pi package entrypoint.
- `src/application/lifecycle.ts` coordinates runtime replacement, settings startup, syntax initialization, and renderer installation. It uses the shared host-session capture, fail-closed trust, and best-effort notification boundaries.
- `src/application/capability.ts` is the canonical named bridge used by synchronous callers. Its `activeCapability` is the sole authority for active checks, runtime execution, deferral, and scheduling. Inactive defer/schedule calls return no-op cancellers. Each installed run capability checks its captured runtime-slot token before calling the mutable slot. Cleanup is unconditional.
- `src/application/scheduler.ts` owns deferred and fixed-cadence renderer callbacks in a scoped `FiberSet`; synchronous disposers interrupt immediately, while session runtime disposal awaits every remaining scheduler fiber. Startup returns the scheduler through the runtime slot's activation value. The public scheduler Layer lets cooperative extensions own the same scoped service in their own session runtime and inject `scheduleAnimation`; independent Jiti loaders do not share the previews capability. Absent scheduling is not cached as an active animation.
- `src/layer.ts` is the sole application Layer composition root. Agent directory, environment, and Shiki adapters are private dependencies of the settings, syntax, write, and scheduler services. The final Layer retains the Node file-platform services so effects run through the session capability can use them.
- `src/config/store.ts` is the public settings persistence entrypoint for `CodePreviewSettingsService`, the loader, and the panel's Promise helpers. The service exposes `load`, `save`, and `flush`. The service keeps one complete save context in a private `Ref`; Layer construction does not publish settings. Each load or save captures a process-local monotonic admission before asynchronous work. The module-level coordinator serializes settings work across separately built Layers and publishes only admissions newer than the latest successful publication. Failed or interrupted newer work does not suppress an older success. `document-store.ts` always returns a complete save context containing only the baseline and loaded settings. Each atomic `modifyObject` derives known overrides from the locked latest document, applies only caller-edited fields, and preserves unknown root fields. `schema.ts` owns every persisted field decoder, including bundled Shiki themes and the opt-in `toolCallCollapsedStyle`; tolerant field recovery derives from that struct. Collapsed style uses the same defaults, environment mapping, trusted precedence, and persistence path as other fields, with `preview` as its default. `defaults.ts` contains the static settings and performance defaults. `env.ts` owns the single `CODE_PREVIEW_*` environment door: `CodePreviewEnvironmentService` decodes once, exposes only settings defaults, and publishes the synchronous performance/tools projection locally. Settings sources are current-only: nested `codePreview` objects in `$PI_CODING_AGENT_DIR/settings.json` and the trusted project's `.pi/settings.json` form the baseline, and the flat `$PI_CODING_AGENT_DIR/code-previews.json` stores package overrides (unknown root fields preserved). Invalid fields recover independently with bounded path-only diagnostics. Legacy settings formats and locations are ignored.
- `src/settings/` owns host commands (`controller.ts`) and the persistence-aware `/code-preview-settings` controller in `panel.ts`; `config/store.ts` owns abort-aware public loading. Signalled startup loads have independent cancellation ownership and never fall back to a one-shot runtime after abort. No-signal public loads share one admission and in-flight disk operation, then clone the settings object and tools array for each caller. The pre-session compatibility runner only builds and runs a short-lived Layer; the shared settings coordinator provides cross-runtime serialization and permits queued cancellation. A one-shot save rehydrates private state and saves under one coordinator permit without an intermediate publication. After a successful theme save, the panel catches a rejected Shiki initialization Promise locally. That failure cannot enter the persistence rollback or warning path. The host composes its settings tree with `pi-cosmic-ui/manager/settings-surface`; shared category submenus and the Vim adapter provide one search and navigation contract. Pure menus, submenus, and summaries remain under `settings/ui/`.
- `src/syntax/` and `src/write/` are the other primary stateful features. The syntax service exposes only `initialize`; it owns Shiki replacement and finalization while `syntax/ingress.ts` owns the bounded synchronous renderer request bridge and its sole invalidation callback ledger. The write service exposes only `rememberBeforeWrite` and `withPathLock`. Its bounded projection has non-destructive renderer lookup. Shiki render entries belong to one highlighter object and theme pair. Replacement and finalization discard render and ANSI color caches only when releasing their owning highlighter, so stale cleanup cannot clear newer caches. `src/shared/projection-ownership.ts` gives syntax and write projections monotonic session ownership so a newer session wins overlap and stale cleanup cannot clear it.
- `src/diff/`, `src/paths/`, `src/tools/` (including grep/path-list/shell helpers), and `src/warnings/` contain deterministic preview policy and transformation logic.
- `tools/compact-notices.ts` projects builtin result limits and write diff guards into local typed notices, counters, and metadata. Known complete-line read pagination produces `expandedOnly` recovery notices owned by the original expanded result. Byte-cap hints require an explicit numeric size-limit footer and `lastLinePartial: false`; partial lines, oversized first lines, and unknown truncation retain attention or decline compaction. Reached grep/find/ls caps use the priority counter lane, never inferred totals or continuation promises. Write guards become metadata only from validated owned size evidence or bounded byte/complexity checks with known previous contents. Prose reasons do not classify guards. Missing history, unknown reasons, output loss, partial grep lines, and secrets retain attention. These projections do not change execution results or expanded renderers.
- `src/tools/` owns tool policy, the public cooperative shell API in `cooperative-tools.ts`, `renderer-adapter.ts`, the exported built-in emoji lookup in `presentation.ts`, argument/result helpers, and synchronous renderer factories. It consumes Cosmic UI's semantic status rows but owns preview behavior. The public wrapper and every built-in factory use the same adapter. It creates one shell, copies the source definition once, preserves execution/result options, and calls supplied renderers unbound to match Pi 0.84. A path-list result creates one chunk renderer for the complete output, so collapsed head and tail chunks share the tree-mode decision and directory set across the hidden-lines marker.
- `src/preview/tool-shell.ts` captures background mode and collapsed style at wrapping/registration time; changes require `/reload`. Compact-capable tools use Pi's `self` shell and own the local detailed background/frame fallback. Semantic summary providers decide whether compaction is safe without inspecting rendered components. Ordinary pending, running, and settled calls share one text row with at most one routine detail and no expand hint. The first nonempty counter wins over metadata, then measured timing. Timing normally appears only for bash or elapsed time of at least ten seconds, when enabled and no other detail exists. Providers can opt into `showTiming` to display measured timing beside the routine detail, including short calls; counts retain priority when space is tight. Important notices and errors remain visible outside that row budget. An explicit summary `failure` grants ownership of both collapsed cause and complete expanded error text, avoiding stacked original cards and duplicate notices. `tools/builtin-failure.ts` shortens recognized builtin failure envelopes and preserves unfamiliar diagnostic/recovery text; attachment failures retain the original renderer. Expanded failures keep the selected background/frame. An explicit `detailsOnExpand: true` permits decoded non-success summaries to collapse to a header and notices only when the provider completely projects attention and recovery into subject/notices. It never overrides owned failure presentation or semantic status classification; unflagged and unknown results keep the conservative original-body fallback. Notices reuse the failure indentation helper with aligned wrapping and no second indent; normalized CRLF deduplication remains limited to owned failure text. Other expansion restores the original call/result components. Providers may mark a notice `expandedInResult` only when their expanded result renders its complete text, and set `expandedResultOwnsCall` only when that result includes all call information. The shell honors these flags only after the current original result factory succeeds, preserves slot-local caches and call-before-result construction, and encloses retained notices in the same selected frame/background. Unknown results and failed factories retain the conservative fallback without text inspection. Subagents revoke call ownership while the live panel replaces their result; cooperative tools without a provider and existing `preserveSelfShell` tools retain their rendering. Pi still owns the transcript separator and native images.
- `tools/builtin-projection.ts` owns the pure public builtin semantic projector. All settings and before-write evidence are explicit inputs. It never reads the private write registry or executes tools. `builtin-compact-summary.ts` adapts standalone context and published settings; `captureBuiltinCompactPolicy` returns a detached, no-I/O policy snapshot for cooperative consumers. Unknown previous contents remain distinct from a known new file. Standalone diff-count caching stays in `builtin-result-detail.ts`, keyed by snapshot identity, contents, and work limits; the adapter passes those counts as explicit evidence. Transient projection retains no results or raw output. `builtin-failure.ts` supplies optional explicit `failureEvidence` with a bounded semantic cause and recovery coverage for recognized shell, filesystem, and edit-refusal envelopes. Consumers may retain those semantic fields, never infer completeness from equality between cause and diagnostic body. Unknown continuations remain conservative. Consumers retaining summaries must strip `failure.details`, redact sensitive text, and bound strings and collections.
- `src/preview/presentation-policy.ts` exposes a detached, no-I/O snapshot of published timing and collapsed-style settings. Consumers capture style at registration and read live timing when rendering.
- `src/preview/compact-row.ts` exposes shared heading and notice rendering for standalone and nested calls, including sanitization, colors, clipping, counter/metadata priority, and timing policy. The public `isCompactAttention` helper classifies only expanded-only recovery as informational; warnings and errors always retain attention. Collapsed notices hide informational recovery, while expanded notices use muted styling unless the original result owns their text. Owned failures retain expanded notices regardless of original-result ownership. Branch indentation reduces the child row's available width; it adds no second heading policy. Notice rendering accepts optional plain decoration, preserving the same severity, wrapping, and narrow-width policy without a tree branch.
- `tools/builtin-subject.ts` owns argument-only builtin targets, shared by standalone summaries and the public `describeBuiltinCompactSubject` helper. It supplies path shortening, read ranges, commands and search targets without inspecting results or write snapshots.
- `src/preview/compact-children.ts` exposes semantic call-tree rendering. Child semantic fields use the shared compact row, keeping names/status separate from elided targets. Child `status` is the effective display classification and takes precedence over the separately recorded operation `outcome`; failed delivery must not look successful. It selects up to five calls, prioritizing active/problem calls and then recent completions while preserving admission order. Exact provider totals include calls omitted before rendering. Selection never consumes the separate warning/recovery budget. Selected children render their own notices; callers retain hidden-child attention in parent notices and avoid duplicating selected notices. The public selection helper lets callers use the same selection policy. The renderer's optional sixth `expanded` argument bypasses selection, renders all caller-bounded retained entries and their informational notices, and reports total minus retained entries as omitted. Its optional seventh `layout` argument selects flat rows with plain hints; tree decoration remains the default. `compact-status.ts` shares header and child status icons; neutral `returned` means delivery without an asserted operation outcome. Supplied measured child durations use the shared pure formatter and obey the same timing policy and global `toolCallTiming` gate; the renderer never estimates missing durations. Shell expansion restores original details; cooperating result renderers may explicitly use the expanded child renderer.
- `src/preview/compact-header.ts` allocates semantic action and target before one selected counter, metadata, or duration. It preserves whole counter labels and uses grapheme-safe middle elision for long targets. Counter budgets leave a minimum target width, while short or empty targets release unused space. Layout owns no execution state, timers, or argument/result cache.
- `src/commands/health.ts` supplies health projection data to the shared bounded `pi-cosmic-ui/manager/panel`; it retains the plain notification fallback for non-TUI hosts.
- `src/boundary/` wraps Node and Shiki integration plus the one-shot settings runner. Shiki initialization uses `Effect.callback` cleanup for interruption; a highlighter that resolves after cancellation is disposed without resuming the fiber. Synchronous render timing imports `synchronousNow` from `pi-cosmic-core`, while session host capture, trust, and notifications use the shared core boundaries directly.
- `src/preview/` and feature render modules are synchronous UI (no top-level `ui/` folder).
- `src/shared/terminal-text.ts` owns the code-point SGR classifiers (`matchSgrSequence`, `replaceSgrSequences`) used instead of control-character regexes for ANSI parsing.

## State and resources

Settings, syntax, and before-write correlation are Effect-owned and publish bounded synchronous projections. Deferred and scheduled renderer callbacks are Effect-owned and reached synchronously through the active session capability. Settings state is one save context in a `Ref`; its `loaded` settings publish only after a coordinated load or the atomic rename commit. A stale save exits before `modifyObject`. Global `flush` waits behind settings work from any Layer. Save lock order is coordinator, JSON document lock, then the lock-free `afterCommit` Ref update and conditional publication. Renderer installation status is bounded plain state: pending, installed, disabled, conflict, or registration error. No raw registration error is retained. Write admission captures the originating capability before entering Pi's outer file-mutation queue. That runtime owns the interruptible queue wait; its abort signal revokes the delayed callback on caller cancellation, replacement, or shutdown. The delayed callback invokes only the captured token-checked capability. Pi cannot remove the inert queue entry until its predecessor settles, but cancellation does not wait for that settlement. Lock order remains Pi mutation queue, preview path lock, then the existing uninterruptible write/correlation commit. Before-write execution uses a scoped `RcMap` of per-path semaphores: each call owns one reference, unrelated paths remain independent, and zero idle TTL removes a lock after its final active or waiting user exits. Correlation entries remain visible for duplicate renders until bounded eviction or scope cleanup. Shiki is the documented synchronous-capability exception. Pure diff and rendering calculations remain synchronous.

## Lifecycle

```text
session_start -> guarded host capture -> application Layer -> settings load -> discover and build replacements
                                                          -> install each planned replacement
                                                          -> session capability -> scoped syntax initialization
write/tool render -> frozen projections + pure rendering
session_shutdown/replacement -> session capability cleared -> runtime resources disposed
```

Installation has a two-phase boundary. Discovery and option resolution build an ordered plan that stores every constructed definition before the first `registerTool` call; it does not retain installer closures. Pre-mutation failures fail startup through the lifecycle boundary. Each attempted name enters the lifecycle-owned tool set immediately before `registerTool`; only successful returns enter the installed set. This distinction handles Pi 0.84 mutating its extension registry before a refresh can throw. A visible nonbuiltin tool in the owned set remains retryable on a later start. Registration failures record a bounded status, later tools continue, and installed replacements keep the runtime live.
