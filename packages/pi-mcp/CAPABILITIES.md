# MCP capability and evidence matrix

This is an implementation inventory, not protocol certification. The target is MCP `2026-07-28` plus the official client/core SDK 2.0.0's supported legacy revisions. [README.md](./README.md) defines configuration and actions. The [feature follow-up](../../docs/plans/pi-mcp-features.md) owns current acceptance; earlier records remain historical evidence.

The authorized follow-up passed final workspace validation and scoped review. MCP has 1,131 passing tests. The two existing pinned legacy conformance scenarios also passed. These checks establish only the scope recorded below, not universal compatibility.

## Required protocol and existing application behavior

| Area                          | Implemented behavior                                                                                 | Limits                                                                                                                                                                                                                                                                                                      |
| ----------------------------- | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Version negotiation           | Modern-first stdio and Streamable HTTP; explicit `protocol: "legacy"`                                | SDK-supported revisions only. Stdio probing can launch twice and must confirm cleanup before replacement. Generic errors and HTTP timeouts do not authorize fallback.                                                                                                                                       |
| Lifecycle and JSON-RPC        | SDK framing, correlation, wire schemas, cancellation, fixed error categories                         | Native source/process cleanup must settle separately from SDK close. Cancellation cannot undo remote work.                                                                                                                                                                                                  |
| Tools                         | Bounded listing, exact describe/call, allow/deny policy, input and captured-schema output validation | No external schema loading or complete JSON Schema dialect certification.                                                                                                                                                                                                                                   |
| Modern HTTP parameter headers | `x-mcp-header` filtering and standard `Mcp-Param-*` mirroring after input validation                 | Declared strings, safe integers, and booleans only; `number` is invalid. Invalid annotations exclude the tool. Invalid UTF-16 is rejected. At most 64 headers/16 KiB encoded data before HTTP send.                                                                                                         |
| Metadata freshness            | `ttlMs`/`cacheScope`, earliest page/family expiry, auth-context binding                              | Absent, invalid, nonpositive, or greater-than-one-day TTL gives zero freshness. Initial active access reacquires expired metadata. Passive browsing and cursor continuations stay local, even after expiry. Refresh/notification/auth/config changes invalidate cursors; invocation freshness is unchanged. |
| Resources and prompts         | Listing, templates, resource reads, prompt retrieval                                                 | Selected-server authority only. No local fetching of returned URIs, installed slash commands, or system-prompt injection.                                                                                                                                                                                   |
| Metadata changes              | Modern connection-scoped subscriptions; legacy notifications                                         | Observation loss withdraws metadata. First-page method-not-found affects only that advertised catalog.                                                                                                                                                                                                      |
| Initialization instructions   | Immutable capture and `server.instructions`                                                          | 64 KiB UTF-8 prefix; missing differs from empty. Discarded suffix is not recoverable. Instructions stay untrusted.                                                                                                                                                                                          |
| Results and certainty         | `not-sent`, `completed`, `unknown`; retention and `result.read`                                      | Accepted output retains completion certainty after local validation failure. Never replay completed/unknown work. Local retention also binds revocation generation.                                                                                                                                         |
| Authentication                | HTTP public-client OAuth, PKCE S256, env bearer, explicit no-auth; user-only sign-in                 | macOS Keychain only. Changed credentials retire the old owner before schema reuse; a later fresh request needs confirmed cleanup. No implicit login, scope escalation, or retry.                                                                                                                            |

## Optional features and era differences

| Feature                          | Implemented behavior                                                                                                   | Restrictions                                                                                                                                                                                                                                                                                                                                                                                                        |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `completion.complete`            | Exact advertised prompt/template argument completion on both transports and supported eras                             | Requires advertised completions; template URIs stay inert. At most 100 returned values.                                                                                                                                                                                                                                                                                                                             |
| `events.read`                    | Local current-authority observations, no connection or remote RPC                                                      | Decimal-string cursor; 1 to 100 events, default 32. Session ring: 128 events/128 KiB; log/progress text: 4 KiB. Coalesced progress and ingress drops make this best-effort, not an audit log.                                                                                                                                                                                                                       |
| Progress                         | Request-associated progress on HTTP and stdio, local observations and bounded live top-level `onUpdate`                | Not deprecated. Progress and missing observations establish no terminal outcome.                                                                                                                                                                                                                                                                                                                                    |
| Structured Logging               | Explicit `logLevel` compatibility for modern HTTP with advertised logging; exact request-stream and severity filtering | Structured Logging is deprecated in `2026-07-28`. Legacy and modern stdio reject `logLevel` before dispatch. No global logging or OTel exporter.                                                                                                                                                                                                                                                                    |
| Resource update subscriptions    | `resources.subscribe`, `resources.unsubscribe`, and local `resources.subscriptions` on supported eras                  | Advertised support required. Connection-owned leases: 16 per owner/32 per session. Modern raw ingress requires the exact SDK-generated subscription ID and acknowledged URI filter. HTTP source cancellation and stdio native write settlement are checked independently of SDK close. Unknown legacy pre-ack outcomes retire the owner. No false unsubscribe success, automatic reads, reconnect, or re-listening. |
| Elicitation and multi-round-trip | Private modern continuation for `tools.call`, `resources.read`, and `prompts.get` through owned forms/URL consent      | Empty constructor capabilities; per-request advertisement requires a current same-session local TUI/RPC provider. Never advertised for headless/legacy sessions. No public answers, `inputResponses`, or `requestState`.                                                                                                                                                                                            |
| HTTP+SSE transport               | Unsupported historical transport                                                                                       | HTTP+SSE is deprecated; SSE within Streamable HTTP is not.                                                                                                                                                                                                                                                                                                                                                          |
| Apps and tasks                   | Deferred                                                                                                               | Not deprecated. No implementation claim.                                                                                                                                                                                                                                                                                                                                                                            |
| Roots and sampling               | Unsupported                                                                                                            | Not advertised. No new capability added.                                                                                                                                                                                                                                                                                                                                                                            |

Subscriptions allocate private local identities before acquisition and reject stale queued generations before waiting on readiness. Modern ACK-adjacent staging is bounded to 32 updates per subscription and requires SDK/filter acceptance before queueing; overflow is reported. One owner finalizer retains only current entries. Legacy wire notifications cannot identify old server work first received after replacement. Successful stdio writes are not remote acknowledgements.

Ask User's form API is separate from its authenticated subagent relay. It uses genuine extension/operation/request ownership and the existing 16-slot FIFO, prompt gate, hide/resume, and Activity. Forms allow 0 to 16 flat fields. Ask User permits 64 choices per enum field; MCP permits 64 total across a form. MCP allows 8 dispatch rounds and 16 input requests, with 64 KiB bounds on request/response batches and opaque state. Only supported types/defaults/constraints/formats pass. Sensitive-text rejection is a heuristic, not a complete secret detector.

URLs appear as full inert text with a prominent host and user consent. MCP alone owns later private system-browser navigation after fresh authority checks and requires manual resume. It does not poll. After auth rejection, stricter continuation checks prohibit more UI/browser work while current-authority checks can still permit a separately completed result to publish. No permission engine or second executor is added.

MCP's foreign Ask User cleanup wait is bounded to one second. A module-wide process-local fence survives runtime/session replacement and blocks later provider resolution until the exact cancellation Promise succeeds. Timeout/rejection is not confirmed cleanup; rejection leaves the fence in place.

## Platform and security bounds

Trusted sessions, enabled servers, and exact-name tool allow/deny rules are the intended authorization model. Per-call approval is an optional policy addition, not an implementation gap or completion blocker for this scope. Pi has no built-in approval middleware. Nested Code Mode calls skip Pi hooks and checks from unrelated optional extensions, while shared MCP policy remains enforced. See [configuration and trust](./README.md#configuration-and-trust).

| Boundary             | Guarantee                                                                                                                      | Not guaranteed                                                                                                                                                                                                            |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Trust and policy     | Trusted session, enabled server, exact tool allow/deny, current authority at admission                                         | Server code is not sandboxed. Annotations/form consent grant no new permissions. Nested Code Mode skips checks from unrelated optional extensions.                                                                        |
| Native platform      | macOS duplex-process and Keychain ownership; scoped core `NativeContext` for callback provenance only                          | No Windows/Linux equivalence or authority from native async context. No foreign parser or Effect runner added.                                                                                                            |
| Credential admission | Default 15-second monotonic budget across auth/local-store/filesystem queues                                                   | No FIFO, waiter cap, synchronous-syscall preemption, or expiry of admitted/native-pending owners. Independent of native `timeoutMs`.                                                                                      |
| Lock storage         | OS account home `.cosmic-pi-locks-v1`, independent of `HOME`/agent directories; best-effort exact-owned normal release cleanup | No online GC or global bound. Dead-recovery barriers, crash/malformed evidence, and failed-release artifacts may remain.                                                                                                  |
| Recovery             | Quiescent dead-owner recovery; native-pending evidence fails closed; durable refresh quarantine                                | PID death, age, or login cannot prove native settlement. No reset CLI/provider-side logout revocation. Follow the [offline recovery procedure](./README.md#credential-coordination-recovery), never bulk-delete the root. |
| Remote content       | Bounded schemas/results/events and inert links                                                                                 | No guarantee against prompt injection or sensitive content. Progress/logs are observations, not authority.                                                                                                                |

## What the checks establish

- Owned regressions exercise repository policy, concurrency, cancellation, authority changes, cleanup, and failure recovery. Exact scoped reports and final acceptance are in the feature record.
- Historical `mcp:smoke` runs used pinned filesystem and Playwright servers on macOS with legacy `2025-11-25`, owned cleanup, and retained-output recovery. They do not certify new optional features or OAuth providers.
- The final `mcp:conformance` run covers only pinned upstream 0.1.16 `initialize` and `tools_call` with explicit legacy selection. The command requires upstream success and a cleanup receipt; it is opt-in, excluded from `pnpm validate`, and not certification.
- No new automated cross-SDK server matrix, Python fixture, or CI job is added. Existing smoke/conformance commands remain available; real-server checks are manual when needed. Root validation and final acceptance are recorded separately in the feature follow-up.
